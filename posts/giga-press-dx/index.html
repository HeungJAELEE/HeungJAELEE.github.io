제조 DX 프로젝트

프로토타입

가상 공장에서 미리 검토한 설비 확장

실제 설비를 들이기 전에 제어 순서와 통신 문제를 가상 공장에서 먼저 확인한 10인 교육 프로젝트

사용자 문제
목표 생산량을 맞추려면 설비를 늘리기 전에 Cycle Time, 설비 수와 배치를 함께 검토해야 했습니다.
구현 범위
10인 팀에서 통신 셋업, 생산량·배치 계산에 필요한 기술조사와 AI 적용 후보 검토를 맡았고 Ladder·SCADA 구현은 팀 결과로 구분했습니다.
결과·현재 단계
Factory I/O–PLC–SCADA–OPC UA 통신과 목표 생산량에 맞춘 가상 확장 시나리오를 교육 시연으로 연결했습니다.

왜 이 프로젝트를 했는가

공장을 확장할 때 설비 수만 늘리면 목표 생산량을 맞출 수 있는 것은 아닙니다. Cycle Time, 공정별 병목, 설비 간 거리와 물류 흐름을 함께 봐야 합니다. 이 프로젝트는 기가프레스 공장 확장을 가정해 목표 생산량에 필요한 설비 수와 배치를 가상 공장에서 먼저 비교한 10인 교육 팀 PoC입니다.

구분내용

내가 맡은 일통신 셋업, 생산량·배치 계산을 위한 기술조사, AI 적용 후보 검토
실제 확인 범위정상 통신과 목표 생산량에 맞춘 가상 공정 흐름

어떤 판단을 디지털로 옮겼는가

기존에는 주문량이나 목표 생산량이 바뀌면 설비 수, Cycle Time과 배치를 각각 따로 검토하기 쉽습니다. PoC에서는 목표 생산량 → 공정별 시간 → 병목 설비 → 필요한 설비 수 → 배치안 순서로 연결했습니다.

입력판단가상 공장에서 확인한 내용

공정별 Cycle Time병목 공정과 설비 수공정 대기와 흐름

시스템 흐름

flowchart LR A["목표 생산량·주문"] --> B["공정별 Cycle Time"] B --> C["설비 수·배치안"] C --> D["Factory I/O\n가상 공정"] D <--> E["PLC\n제어 순서"] E --> F["SCADA\n상태 확인"] E --> G["OPC UA\n상위 데이터"] G --> H["AI 적용 후보\n향후 분석"]

Factory I/O는 배치와 공정 흐름을 보여 주고, PLC는 순서를 제어하며, SCADA는 현재 상태를 확인하는 역할로 나눴습니다. OPC UA는 PLC 상태를 상위 시스템이 같은 이름으로 읽도록 연결했습니다. AI는 이 PoC에서 실행한 제어기가 아니라, 향후 상태 이력과 생산계획을 분석할 후보로만 검토했습니다.

내가 맡은 범위와 팀 범위

제가 맡은 일은 Factory I/O·PLC·SCADA·OPC UA가 같은 상태를 주고받도록 통신을 맞추고, 목표 생산량에 따른 설비 수와 배치 검토에 필요한 자료를 조사한 것입니다. Ladder와 SCADA 화면의 세부 구현은 팀원이 맡았고, 전체 공정 시나리오와 발표자료는 함께 만들었습니다.

이 구분은 중요합니다. 제가 전체 시스템을 설명할 수는 있지만, Ladder와 SCADA의 세부 구현까지 개인 결과로 적지는 않습니다.

진행 순서

  1. 목표 생산량과 공정 Flow를 정리했습니다.
  2. 공정별 Cycle Time과 병목 후보를 비교했습니다.
  3. 필요한 설비 수와 배치안을 만들었습니다.
  4. Factory I/O에서 가상 공정 흐름을 구성했습니다.
  5. PLC·SCADA·OPC UA 통신을 연결해 같은 상태가 표시되는지 확인했습니다.
  6. 향후 AI가 사용할 수 있는 생산·상태 데이터를 정리했습니다.

확인한 결과

팀은 Factory I/O–PLC–SCADA–OPC UA를 하나의 교육 시연으로 연결했고, 목표 생산량에 맞춰 설비 수와 배치를 바꿔 보는 가상 확장 시나리오를 만들었습니다. 실제 공장 생산성 개선을 측정한 프로젝트는 아니며, 센서 고장·통신 단절 같은 이상상황 회귀시험도 수행하지 않았습니다.

팀 보고서의 셋업 시간과 증설 공수 절감 수치는 실제 측정 결과가 아니라 향후 현장 적용 시 확인할 기대효과입니다.

회사에서 활용하려면

실제 설비 프로젝트로 이어가려면 실공정 Cycle Time, 물류 동선, 안전 PLC, 제조사 프로토콜과 Hardware-in-the-Loop 시험이 추가로 필요합니다. 다음 단계에서는 정상 통신 시연을 넘어 이상상황·복구 시나리오와 FAT/SAT 인수기준까지 같은 문서로 연결해야 합니다.

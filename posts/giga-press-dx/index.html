팀 경계

Ladder와 SCADA 구현은 팀원 역할이며, Factory I/O–PLC–SCADA–OPC UA 전체는 10인 팀 결과입니다.

아래 흐름은 팀 과제를 바탕으로 가상 시운전 업무에 적용할 수 있게 일반화했습니다.

처음 1분에 볼 내용

이 글에서 기가프레스는 대형 주조 설비를 중심으로 공정 셀을 증설하는 교육용 공장 시나리오입니다. 새 설비가 도착한 뒤 처음으로 PLC 순서, 화면 태그와 상위 데이터 연결을 맞추는 대신, 가상 설비에서 먼저 연결하고 실패 조건을 반복해 보는 것이 핵심입니다.

공장 확장 시나리오

공장에 기존 공정과 비슷한 설비 셀을 하나 더 추가한다고 가정했습니다. 기계만 복제한다고 증설이 끝나지는 않습니다. 센서가 어떤 순서로 켜지는지, 이전 공정의 완료 신호가 언제 들어오는지, 작업자가 어떤 알람을 보는지, 상위 시스템이 같은 설비 상태를 같은 이름으로 이해하는지까지 함께 맞아야 합니다.

실물 설비에서 처음 이 작업을 시작하면 센서 누락, 완료 신호 지연, 수동·자동 모드 충돌과 재기동 조건을 늦게 발견할 수 있습니다. 이 PoC는 Factory I/O가 실물 설비를 대신하는 동안 PLC 시퀀스, SCADA 표시와 OPC UA 데이터 흐름을 연결해 보고, 정상 운전뿐 아니라 멈춤과 복구 조건까지 미리 검토하는 방식입니다.

구성요소 담당한 일 담당하지 않는 일
Factory I/O 센서와 액추에이터가 있는 가상 공정을 움직이고 고장 조건을 반복 실제 설비의 유압·서보·안전 특성을 증명
PLC·Ladder 공정 순서, 인터록과 최종 운전 허가 판단 AI 결과를 검토 없이 실행
SCADA 상태, 알람과 작업자 조작 결과 표시 안전 회로와 PLC 인터록을 대체
OPC UA PLC 데이터를 상위 계층이 읽을 수 있는 태그 흐름으로 전달 통신 성공만으로 값의 안전성을 보증
웹·AI 후보 상태를 보여 주거나 최적화 가능성을 검토 비상정지나 설비 운전권 소유

Ladder와 SCADA는 담당 팀원이 구현했습니다. 저는 이 전체 구조를 혼자 만들었다고 설명하지 않습니다. 제 작업은 DQN 후보를 검토하고 학습하는 일, OPC UA를 포함한 통신 셋업, 그리고 구성요소를 어떤 경계로 연결할지 조사하는 일이었습니다.

신호 하나가 이동하는 과정

예를 들어 금형 준비 완료 신호는 다음 순서로 이동합니다.

  1. Factory I/O의 가상 센서가 준비 상태를 만듭니다.
  2. PLC가 현재 모드, 이전 단계 완료와 인터록을 함께 확인합니다.
  3. 조건이 맞으면 PLC가 다음 동작을 허가하고, 맞지 않으면 정지 상태와 원인을 유지합니다.
  4. SCADA는 같은 상태를 작업자가 읽을 수 있는 설비명과 알람으로 보여 줍니다.
  5. OPC UA는 상위 계층에 설비, 신호, 값, 품질과 시간 정보를 전달합니다.
  6. 웹 화면이나 AI 후보는 이 데이터를 소비하지만 PLC의 안전 판단을 건너뛰어 설비를 움직이지 않습니다.

팀 설계에서는 신호 이름만 맞추는 것으로 충분하지 않다고 보았습니다. equipment, signal, value, quality, timestamp가 함께 있어야 끊긴 통신의 마지막 값과 현재 정상 값을 구분할 수 있기 때문입니다. 실제 태그 목록과 설비 주소는 내부 팀 자료이므로 이 공개 글에는 싣지 않습니다.

AI 모델과 통신에서 내가 맡은 일

DQN 후보 선정과 학습

실시간 센서·PLC 상태를 입력으로 받아 공정 최적화 가능성을 살펴보는 DQN 후보를 선정하고 학습했습니다. 검토의 초점은 모델 이름보다 세 가지 질문에 있었습니다.

  • 어떤 PLC·센서 상태를 관측값으로 사용할 것인가
  • 시간 단축과 안전 위반 방지를 보상 설계에서 어떻게 구분할 것인가
  • AI 출력이 PLC 인터록을 우회하지 않는 권고값으로 어디에 머물러야 하는가

이 프로젝트에는 실제 기가프레스에서 반복 측정한 모델 성능이나 양산 효과 수치가 없습니다. DQN은 생산 제어기가 아니라, 상위 계층에서 최적화 가능성을 검토한 후보로 설명합니다.

OPC UA 통신 셋업과 자료 조사

PLC 쪽 값을 SCADA·웹·AI 계층이 같은 의미로 사용할 수 있도록 OPC UA 연결 위치와 데이터 흐름을 정리했습니다. 주소만 주고받기보다 태그의 의미, 통신 품질과 시각을 함께 다룰 수 있다는 점을 기준으로 삼았습니다. 또한 통신 단절, 오래된 값, 재접속 후 상태 동기화가 왜 별도 시험 항목이어야 하는지 관련 자료를 조사해 팀 시나리오에 반영했습니다.

10인 팀 결과와 개인 역할

범위 귀속
공정 시나리오, Factory I/O–PLC–SCADA–OPC UA 전체 연결, 통합 데모와 보고서 10인 팀 결과
AI 모델 후보 선정·학습, 통신 셋업, 관련 기술 조사 내 역할
PLC Ladder 시퀀스와 인터록 구현 담당 팀원 역할
SCADA 화면, 태그와 알람 구현 담당 팀원 역할

면접에서는 전체 시스템을 설명하면서도, 구현하지 않은 Ladder와 SCADA를 개인 성과로 말하지 않습니다. 위 역할표가 그 기준입니다.

작업 순서

  1. 확장 상황을 정의했습니다. 정상 공정 순서와 정지, 지연, 센서 누락, 수동·자동 모드, 재기동 조건을 정리했습니다.
  2. 신호 책임을 나눴습니다. 어떤 판단은 PLC가 하고, 무엇을 SCADA가 표시하며, 어떤 데이터를 상위 계층으로 보낼지 구분했습니다.
  3. 가상 공정과 제어를 연결했습니다. 담당 팀원이 Factory I/O 시나리오와 Ladder 로직을 연결했습니다.
  4. 작업자 화면을 구성했습니다. 담당 팀원이 SCADA 상태, 알람과 조작 결과를 같은 신호 기준으로 보이게 했습니다.
  5. AI와 통신 후보를 검토했습니다. 저는 DQN 후보를 선정·학습하고 OPC UA 흐름을 셋업하며 관련 자료를 조사했습니다.
  6. 정상·실패·복구 흐름을 통합했습니다. 팀이 각 파트를 하나의 시연과 보고서로 묶었습니다.
  7. 결과의 범위를 다시 확인했습니다. 팀 산출물, 개인 기여, 기대효과와 아직 하지 않은 현장 검증을 분리했습니다.

마주친 문제와 선택

문제 선택 이유
가상 설비, PLC와 화면이 같은 신호를 다르게 해석할 수 있음 공통 태그 의미와 값·품질·시각을 함께 정의 화면은 정상처럼 보여도 오래된 값일 수 있기 때문
현장에서 실패 조건을 반복하기 어렵고 위험함 Factory I/O에서 센서 누락, 지연과 재기동을 먼저 검토 실물 트라이아웃 전에 논리와 표시 오류를 찾기 위해
AI 응답과 네트워크에는 지연과 변동이 있음 최종 운전 허가와 인터록을 PLC에 유지 최적화 후보가 안전 판단을 대신하지 않게 하기 위해
여러 사람이 서로 다른 계층을 구현함 팀 결과와 개인 역할을 문서에서 분리 전체 구조 이해와 실제 구현 범위를 동시에 정확히 전달하기 위해
보고서에 효율 목표가 포함됨 목표값과 실측 결과를 별도 문장으로 표기 기대효과를 달성 성과로 오해하지 않게 하기 위해

확인된 결과와 기대할 수 있는 이점

확인된 결과는 공정 흐름, Factory I/O·Ladder, SCADA, OPC UA와 웹·AI 확장 위치를 연결한 10인 팀 데모와 보고서입니다. 설비가 들어오기 전에 팀이 공정 순서, 신호 이름, 알람과 통신 실패 조건을 같은 기준으로 검토할 수 있도록 구성했습니다.

보고서에 적힌 셋업 시간 50~75% 단축과 설비 증설 공수 50% 절감은 가상 시운전과 Ladder 모듈화가 잘 적용될 때의 기대효과 또는 목표값입니다. 실제 공장 적용 전후를 같은 조건으로 비교한 측정 결과가 아니며, 이 프로젝트가 달성한 성과로 사용하지 않습니다.

현장 기준선과 비교 시험을 마친다면 기대할 수 있는 이점은 다음과 같습니다.

  • 실제 설비 트라이아웃 전에 시퀀스와 태그 불일치를 찾을 가능성
  • 증설 시 재사용할 수 있는 신호 정의와 실패·복구 시험 순서
  • 제어, 화면, 통신과 분석 담당자가 같은 상태를 설명하는 공통 기준
  • 변경된 로직이 다른 공정과 알람에 미치는 영향을 먼저 검토하는 절차

현재 한계와 다음 검증

이 PoC는 실제 기가프레스 하드웨어, 안전 PLC, 유압·서보 동특성, 실제 takt와 양산 I/O에서 검증되지 않았습니다. DQN의 실공장 성능, 장시간 통신 안정성, 실제 작업자의 알람 대응도 측정하지 않았습니다.

현장 적용 전에는 실제 I/O를 연결한 Hardware-in-the-Loop 시험, FAT, 통신 끊김·재접속, 태그 버전 변경, 알람 우선순위, 네트워크 분리와 접근 권한을 검증해야 합니다. AI 후보를 사용하더라도 권고의 승인·거부·되돌리기 절차를 두고, 운전 명령과 안전 판단은 검증된 PLC와 안전 시스템에 남겨야 합니다.

Problem

실물 설비 투입 전에는 PLC 시퀀스, SCADA 태그, 센서 이상과 통신 지연을 함께 검증하기 어려워 오류가 현장 트라이아웃 단계에서 늦게 발견됩니다.

Goal

Factory I/O–PLC–SCADA–OPC UA의 책임과 데이터 계약을 먼저 정의하고, 정상·고장·재기동 시나리오를 가상 환경에서 검토할 수 있는 제조 DX 기준안을 만드는 것입니다.

Success

팀 데모와 보고서에서 데이터 흐름·역할·검증 시나리오가 추적되고, 기대효과가 실제 측정 성과와 명확히 구분되면 성공으로 판단합니다.

범위와 경계

포함 범위

  • Factory I/O, PLC, SCADA, OPC UA 사이 신호 흐름과 책임 경계
  • 정상 운전, 센서 누락, 통신 지연, 재기동 검증 시나리오
  • 실시간 센서·PLC 데이터를 활용하는 DQN 후보 검토

제외·미검증 범위

  • 실제 기가프레스 안전 PLC와 하드웨어 사양의 생산 배포
  • Ladder·SCADA 구현을 개인 단독 성과로 귀속하는 표현
  • 50~75%·50% 기대효과를 공장 실측 성과로 해석하는 주장

구현·검증 기준

해야 할 일

  • 공통 태그에 equipment, signal, value, quality, timestamp를 포함한다.
  • PLC가 인터록과 최종 운전 허가를 소유하고 AI는 보조 권고만 제공한다.
  • SCADA에서 상태·알람·지연·수동 명령 결과를 같은 태그 기준으로 추적한다.

품질·운영 기준

  • 통신 단절 시 마지막 명령을 유지하지 않고 안전 상태로 전환한다.
  • 정상 흐름뿐 아니라 실패·복구 시나리오를 반복 검증한다.
  • 목표값, 팀 결과, 개인 기여와 미검증 항목을 분리 기록한다.

왜 이렇게 구성했나

  1. PLC에 제어권 유지

    비결정적 AI 응답이나 통신 지연이 안전 인터록을 우회하지 않도록 최종 권한을 PLC에 남겼습니다.

  2. OPC UA를 상위 데이터 경계로 사용

    주소 중심 통신보다 태그 의미와 품질 정보를 함께 전달해 SCADA·분석 계층의 결합도를 낮추기 위해서입니다.

  3. 실물 전에 Factory I/O로 실패 주입

    현장에서 재현하기 어려운 센서 누락·지연·모드 충돌을 반복 시험하기 위해서입니다.

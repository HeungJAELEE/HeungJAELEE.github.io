프로젝트 배경과 Vision

GIGA Press 공정을 Factory I/O에서 구현 가능한 원자재 투입–CNC 가공–불량검사–Tray 이송–Stacker 적재·배출 흐름으로 추상화했습니다.

목표는 3D 화면 자체가 아니라, PLC·가상설비·관제·이력에 흩어진 상태를 같은 의미로 연결해 생산기술자가 Cycle, 이송시간, Buffer, 생산량과 병목후보를 한 흐름에서 검토할 수 있는 분석 기반을 만드는 것이었습니다.

제어와 분석의 권한도 처음부터 분리했습니다. PLC는 Sequence와 Interlock을 소유하고, AI 계층은 OPC UA와 SQLite의 상태·이력을 Read-only로 사용합니다. AI 출력은 설비구동 명령이 아니라 투입시점, 병목구간, Buffer·Stacker 운영과 Scale-up 시나리오를 검토하기 위한 생산기술 Advisory 후보로 설계했습니다.

가상 제조 Flow

flowchart LR A["원자재 투입"] --> B["CNC 가공"] B --> C{"불량검사"} C -->|NG| D["불량 배출"] C -->|GOOD| E["Tray 이송"] E --> F["Stacker 적재"] F --> G["Stacker 배출"]

공정단계는 설비명 목록이 아니라 상태전이 기준으로 정의했습니다. 투입완료, 가공완료, 검사판정, Tray 도착과 Rack 적재완료가 다음 Step의 시작조건이 되도록 PLC·Factory I/O·SCADA의 상태 의미를 정렬했습니다.

핵심 설계는 PLC Control Domain과 AI Advisory Domain의 Decoupling입니다. 안전·동작 권한은 PLC에 고정하고, AI 계층은 상태와 이력을 읽어 생산기술 판단을 지원하도록 배치했습니다.

통합 구현 Evidence

Factory I/O·PLC 공정제어

Start·Reset·Stop·E-Stop 입력과 PLC Step, Factory I/O 동작을 같은 화면에서 비교했습니다. 상세 Ladder 작성은 PLC 팀이 담당했습니다.

SCADA·Rack·Stacker 상태

Rack 위치, Stacker 적재상태와 Alarm을 SCADA와 가상공정에서 같은 기준으로 확인했습니다.

Web 생산기술 분석화면

Web 화면은 설비상태와 생산정보를 생산기술자가 한 번에 확인하는 View로 구성했습니다. 향후 Advisory Output도 같은 사용자 흐름에 배치할 수 있도록 설계했습니다.

기능별 PLC 구조 제안

보고서에서는 Emit, Machine, Move, Stacker, Vision 단위로 기능을 분리해 공정변경과 시나리오 비교가 가능한 구조를 제안했습니다. 상세 구현은 PLC 팀 범위입니다.

Advisory Agent 확장설계

DQN 후보는 OPC UA·SQLite 이후의 분석계층에 배치했습니다. Rack·Stacker·Cycle·Buffer·생산량을 State 후보로 사용하고, 출력은 설비명령이 아니라 병목·투입·Capa·Scale-up 시나리오 후보로 변환했습니다.

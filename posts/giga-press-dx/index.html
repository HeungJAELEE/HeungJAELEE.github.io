프로젝트 개요

이 프로젝트는 실제 GIGA Press의 주조 물리현상을 해석하는 과제가 아닙니다. 실물 설비를 반복해서 시험하기 전에 공정 순서와 설비상태가 맞는지 확인할 수 있도록, Factory I/O에서 원자재 투입·가공·검사·Tray 이송·Stacker 적재·배출 공정을 단순화했습니다.

PLC가 공정 순서를 제어하고, OPC UA를 통해 SCADA와 Web 화면이 같은 설비상태를 표시하도록 연결했습니다. AI는 실제 설비를 직접 제어하지 않았습니다. Rack·Stacker와 설비상태 데이터를 DQN에 연결할 수 있도록 State와 Action 후보, PLC와의 연결위치를 정리하는 단계까지 진행했습니다.

프로젝트는 10인 교육 팀으로 수행했습니다. 저는 Digital Twin 팀에서 제조 시나리오, 시스템 계층, 상태 연결기준과 AI 적용구간을 정리하고 통신 셋업을 지원했습니다. PLC Ladder와 SCADA 상세 구현은 각 담당 팀원이 맡았으며, 저는 분과별 결과를 하나의 제조공정 흐름으로 연결해 최종보고서를 작성했습니다.

왜 Digital Twin이 필요했는가

보고서에서는 기존 제조방식의 문제를 세 가지로 정리했습니다.

제조 문제기존 방식의 한계이번 프로젝트에서 확인한 내용
Try-out 장기화설비와 자재를 반복 투입하며 조건을 확인해야 함실물 구축 전 Sequence와 Interlock을 가상공정에서 확인
상태값 불일치설계·PLC·설비·관제가 서로 다른 상태 의미를 사용할 수 있음Factory I/O·PLC·SCADA·Web의 상태 의미를 맞춤
만성 Loss 추적 어려움설비상태와 이력이 분리되면 문제구간을 찾기 어려움Alarm·Rack·Stacker·생산정보가 전달되는 구조를 정리

이번 과제에서 Try-out 비용이나 만성 Loss 감소율을 실측한 것은 아닙니다. 교육환경에서 공정 Sequence와 상태전달 구조가 동작하는지 확인하는 데 범위를 두었습니다.

팀 목표와 완료조건

팀 목표

  1. GIGA Press 공정을 Factory I/O에서 구현 가능한 공정으로 단순화합니다.
  2. 원자재 투입부터 Stacker 배출까지 공정 순서를 구성합니다.
  3. Start·Reset·Stop·Emergency Stop 입력을 PLC와 연결합니다.
  4. PLC와 Factory I/O가 같은 공정단계와 설비상태를 사용하도록 맞춥니다.
  5. OPC UA를 통해 PLC 상태를 SCADA와 Web으로 전달합니다.
  6. Rack·Stacker 위치와 적재상태를 같은 기준으로 표시합니다.
  7. DQN에 사용할 State·Action 후보와 연결위치를 정합니다.
  8. 전체 시스템의 정상 흐름을 팀 시연으로 확인합니다.

나의 역할 — Digital Twin 시스템 설계·통합

저는 실제 제조공정을 Factory I/O의 가상공정으로 옮기기 위한 공정 순서와 시스템 연결방식을 정리했습니다.

원자재 투입, 가공, 검사, Tray 이송, Stacker 적재와 배출을 하나의 공정으로 나누고, 각 단계에서 PLC·Factory I/O·SCADA·Web이 어떤 상태를 주고받아야 하는지 정리했습니다. AI가 PLC의 안전제어를 바로 대체하지 않도록, PLC 제어영역과 DQN 분석영역도 분리했습니다.

Ladder와 SCADA 화면의 상세 구현은 해당 담당자가 수행했습니다. 저는 각 분과의 구현결과가 같은 공정 흐름과 상태 의미를 사용하는지 확인하고, 시스템 구성과 AI 적용범위를 최종보고서에 정리했습니다.

실제 구현결과

Factory I/O와 PLC 제어

Start·Reset·Stop·Emergency Stop 조작과 PLC Ladder 상태를 함께 확인했습니다. 이 화면은 가상공정 입력과 제어로직이 연결된 팀 결과입니다.

SCADA와 Stacker 상태

가상공정의 Rack 위치와 Stacker 적재상태가 SCADA에서도 같은 의미로 표시되는지 비교했습니다.

Web 운영화면

Web 화면에는 설비상태, Rack 위치와 생산정보를 표시했습니다. 예지보전이나 AI 최적제어 성능을 검증한 화면은 아닙니다.

팀 설계 검토 — Ladder 모듈화

보고서는 Emit, Machine, Move, Stacker, Vision처럼 공정기능별 Program 또는 Function Block으로 나누는 방향을 제안했습니다. 증설 공수 50% 절감은 보고서의 기대효과이며 이번 PoC에서 측정한 결과는 아닙니다.

후속 확장 설계 — DQN

보고서에서는 Rack·Stacker와 설비상태를 State로, 이동·적재·배출 명령을 Action 후보로 정리했습니다. 이번 공개범위에서 DQN은 모델 선정과 연결구조 설계 단계입니다.

다음 단계에서는 DQN의 추천값을 PLC 안전제어와 분리한 상태로 기록해야 합니다. 추천 Action, 작업자 승인과 PLC 실행결과를 각각 남기는 Shadow Test 또는 HIL 시험이 필요합니다.

3. Teaching JSON을 작업 Tree로 바꾸는 방법

JSON의 3개 핵심 배열

Robot 작업 하나는 한 레코드에 모두 들어 있지 않습니다. 작업순서, 이동조건과 실제 좌표가 서로 다른 배열로 저장되므로 세 구조를 다시 연결해야 합니다.

JSON 영역저장내용HMI에서 보이는 의미
program명령 Type, id, pId, 작업순서·분기·반복·I/OMove·Pick·Place·Wait·If·Loop 작업 Tree
moveList속도·가속도, TCP, Reference Frame, 보간·Offset, Waypoint 참조Robot이 어떤 조건으로 이동하는가
wpListJoint q[], Task p[], Blend RadiusRobot이 실제로 어디로 이동하는가

Move 명령은 다음 참조순서로 좌표를 찾습니다.

program[name]
→ moveList[name]
→ moveList.wpList[id]
→ wpList[id]
→ Joint q[6] / Task p[6]

명령 종류별 해석

명령군대표 명령프로그램에서 처리하는 내용

4. JSON 편집과 원본보존 Round-trip

원본 전체를 먼저 보관

HMI에서 보이지 않는 제조사 설정이나 사용하지 않는 Waypoint를 삭제하면 티치펜던트 호환성이 깨질 수 있습니다. Load 시 원본 전체와 주요 배열을 별도로 보관하고, Save 시 편집한 필드만 기존 데이터에 병합했습니다.

prog._raw_info = data.get("info", {"name": prog_name})
prog._raw_wpList = data.get("wpList", [])
prog._raw_moveList = data.get("moveList", [])
prog._raw_full_data = data

참조 Map 구성

move_map[mv_name] = mv
wp_map[wp_id] = wp

mv = move_map.get(node.name, {})
real_wp = wp_map.get(wp_id, {})

이 구조로 작업 Tree의 Move 이름을 이동조건에 연결하고, 다시 Waypoint ID를 따라 실제 Joint·Task 좌표를 불러옵니다.

수정·저장 흐름

저장 전에는 Parent–Child, Move–Waypoint, Joint·Task 단위, TCP·Reference Frame과 Pick·Place Target을 확인합니다. 참조가 끊긴 항목은 저장·실행 전 수정대상으로 확인하도록 구성했습니다.

Robot별 Queue와 결과추적

  • Robot A/B/C마다 독립 Command Queue를 사용합니다.
  • 모든 요청에 command_id를 붙여 수락·완료·실패를 같은 요청으로 추적합니다.
  • robot/accepted는 Queue 수락 여부, robot/result는 완료판정, robot/error는 Fault·통신·명령 오류를 전달합니다.
  • Stop·Emergency·Reset·Disconnect 같은 즉시명령은 대기 중인 명령을 비우고 우선 처리합니다.
  • Joint·Task 이동은 명령 전·후 실제 좌표와 Busy·MoveDone 상태를 비교해 완료 또는 Timeout을 판정합니다.

6. 실시간 Robot 상태와 3D Digital Twin

Runtime State 수집

Robot Controller는 연결된 Robot을 주기적으로 조회해 다음 상태를 하나의 robot/realtime Payload로 발행합니다.

상태용도
q — J1~J6각 관절의 3D 위치와 Robot 자세 계산
p — TCP Pose실제 Tool 위치와 HMI Telemetry 표시
torque축별 부하 상태 확인
di / doPLC·Tool·공정 신호 확인
busy / movedone실행·완료상태 판정
emergency / collision / errorMotion 차단과 복구판정
connectedRobot별 연결상태 표시

Forward Kinematics와 설치 Offset

실제 J1~J6를 DH Parameter 기반 Transformation Matrix에 적용하고, TCP Offset과 Robot A/B/C 설치 Offset을 더해 공장 좌표계의 Robot 자세를 계산했습니다.

J1–J6
→ DH Transformation Matrix 1~6
→ Joint·Flange 3D 위치
→ TCP Offset 적용
→ Robot A/B/C 설치 Offset 적용
→ Arm·TCP·Trajectory 갱신

T = self.compute_forward_kinematics(j_pos)
tcp_local = np.array([

    self.tcp_offset[1],
    self.tcp_offset[2],
    1.0,

P6 = (T[6] @ tcp_local)[:3]

팀이 만들려던 전체 프로젝트

팀은 자동차 자동조립 시나리오를 Indy7 실물로 시연하고 로봇 명령·상태·작업이력을 한 흐름으로 연결하려 했습니다. 자동차 조립과 실물 시연은 팀 결과이며, 저는 전체 기획과 로봇 제어·시스템 인터페이스 연결을 맡았습니다.

명령과 상태가 흐르는 시스템

flowchart LR HMI["PC-HMI\nMY CORE"] --> CMD["운전요청·command_id"] --> RC["Robot Controller\nMY CORE"] --> ROBOT["Indy7\nTEAM PHASE"] ROBOT --> RC --> STATE["result·realtime"] STATE --> UI["HMI 상태화면"] STATE --> DB["DB Worker"] STATE --> TWIN["읽기 전용 Web Twin"] PLC["PLC 상태변화"] --> BRIDGE["Read-only PLC Bridge"] --> STATE

공개코드 확장범위는 PC-HMI, Robot Controller, MQTT·DB, 읽기 전용 Web Twin과 Conty JSON 호환구조입니다. Web Twin과 DB Worker는 로봇에 직접 명령하지 않고 상태를 저장하거나 표시합니다.

로봇 명령을 한곳에 모은 이유

  • Python Robot Controller만 IndyDCP Socket을 소유합니다.
  • HMI 요청은 command_id와 함께 전달되고 Controller가 수락·결과·오류·연결상태를 구분합니다.
  • fault 또는 Queue full 상태에서는 새 명령을 거부합니다.
  • 사용자별 권한, 장시간 재접속, 전체 중복명령과 장애복구 완료를 뜻하지 않습니다.

Teaching JSON 보존

Parser와 Serializer 책임을 나누고 화면이 모르는 원본필드도 보존했습니다. 원본 로드 → 일부 편집 → 저장 → 다시 로드 → 트리·참조·단위 비교 순서로 프로그램 트리와 Waypoint 참조가 유지되는지 확인했습니다.

팀 결과와 현재 단계

팀은 자동차 조립 시나리오와 Indy7 실물시연을 연결했습니다. 개인 구현은 공개 Snapshot에서 명령·상태 경로와 읽기 전용 Web Twin으로 확인됩니다. 물리 PLC를 포함한 장시간 E2E, 재접속, 중복명령, 권한과 장애복구는 남은 검증입니다. 향후 Omniverse 시각화와 AI Teaching을 같은 명령·상태 구조에 연결할 수 있습니다.

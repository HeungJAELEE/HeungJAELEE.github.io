프로젝트 개요

이 프로젝트는 실제 자동차 공장을 모티브로 하여, 기존 Robot 프로그램과 설비를 유지하면서 Digital Twin을 적용하는 방법을 확인하기 위해 진행했습니다.

신규 공장은 처음부터 설비 데이터와 3D 모델을 연결할 수 있지만, 기존 공장은 Robot 작업 프로그램이 티치펜던트나 개별 파일에 남아 있고 설비별 데이터 형식도 서로 다른 경우가 많습니다. 이번 프로젝트에서는 Indy7 Robot에 저장된 Teaching Data를 다시 사용할 수 있도록 PC-HMI에서 읽고 수정·검증하는 구조를 만들고, Robot의 실시간 상태를 자동차 조립공정 Digital Twin에 연결했습니다.

팀 프로젝트에서는 QR Code, Robot A·B·C, AI Vision, PLC와 MySQL을 연결해 제품 투입부터 양품 배출까지 시연했습니다. 저는 전체 공정 순서와 시스템 연결 방식을 정리하고, Robot A·B·C의 제어와 Digital Twin을 담당했습니다. AI Vision 모델과 PLC Ladder는 다른 팀원이 구현했고, SCADA는 진행하지 않았습니다. 제품 정보와 검사 결과는 MySQL로 직접 저장했습니다.

QR Code 제품 확인

투입 차량의 종류와 제품 시리얼을 확인하고, 이후 조립·검사 결과를 같은 제품 기준으로 저장할 수 있도록 했습니다.

Robot A 차체 조립

Robot A는 투입된 차량의 차체 조립을 담당했습니다. PLC의 시작신호를 받은 뒤 작업하고, 완료상태를 다음 공정에 전달하도록 구성했습니다.

1차 AI Vision 검사

Robot A 작업 후 r, g, b 3개 클래스로 차량 색상을 검사했습니다.

Robot B 유리창 조립

Robot B는 1차 검사 이후 차량의 유리창을 조립했습니다. Robot A 완료와 1차 Vision 결과가 확인된 뒤 작업을 시작하도록 순서를 맞췄습니다.

2차 AI Vision 검사

유리창 조립 후 r_normal, g_normal, b_normal, r_crack, g_crack, b_crack 6개 클래스로 정상·균열 후보를 검사했습니다.

Robot C 양품 배출

2차 Vision 결과가 양품이면 Robot C가 차량을 지정된 위치로 이동시켰습니다. 불량이면 적재하지 않고 별도 경로로 통과하도록 공정을 나눴습니다.

나의 역할 — Robot + Digital Twin

저는 제조공정과 설비 셋업 경험을 바탕으로 자동차 조립공정의 순서와 설비 간 인계조건을 먼저 정리했습니다. Robot, Vision과 PLC가 각각 동작하더라도 시작·완료 신호가 맞지 않으면 전체 공정이 이어지지 않기 때문에 Robot A·B·C의 작업조건과 분과 간 인터페이스를 중심으로 진행했습니다.

Robot 공정에서는 작업 위치와 동작 순서를 설정하고, PLC의 Start 신호를 받은 뒤 작업을 수행해 Complete 또는 Error 상태를 전달하도록 구성했습니다. Digital Twin에서는 실물 셀의 Robot 위치, 레일과 공정 위치를 배치하고, Robot의 Joint·TCP와 실행상태를 화면에 반영했습니다.

기존 Robot Teaching Data를 Digital Twin으로 연결한 방법

개발 배경

기존 공장에는 Robot 프로그램이 이미 있지만, 작업 순서와 좌표가 티치펜던트와 개별 파일에 남아 있어 PC에서 전체 내용을 확인하기 어렵습니다. 같은 데이터를 Digital Twin에 사용하려면 기존 프로그램을 다시 작성하거나, 제조사 JSON의 내부 구조를 직접 해석해야 합니다.

이번 후속 구현에서는 기존 Indy7 Teaching JSON을 그대로 불러와 작업자가 읽을 수 있는 Tree로 바꾸고, 필요한 좌표와 조건을 수정한 뒤 다시 Conty 호환 형식으로 저장했습니다. 검사를 통과한 파일은 가상 실행과 실제 Robot 실행에 사용하고, Robot의 실시간 상태는 Digital Twin과 MySQL에 전달했습니다.

후속 PC-HMI 실행구조

후속 공개 코드에서는 HMI가 실제 Robot에 직접 여러 소켓을 여는 대신, Robot Controller에 작업을 요청하도록 나눴습니다. Robot Controller가 IndyDCP 통신을 맡고, Digital Twin과 DB Worker는 Robot Controller가 발행한 같은 실시간 상태를 사용합니다.

어떻게 움직일 것인가속도, 가속도, TCP, 기준좌표계moveList
어디로 움직일 것인가Joint 좌표와 Task 좌표wpList

예를 들어 ‘Robot A가 차체 조립 위치로 이동한다’는 한 동작도 JSON에서는 작업순서, 이동조건과 실제 좌표가 따로 저장됩니다. 프로그램은 Move 명령의 이름으로 이동조건을 찾고, 그 안의 Waypoint ID를 이용해 실제 좌표를 연결합니다.

flowchart TD A["Teaching JSON 파일 열기"] --> B["원본 전체 데이터 보관"] B --> C["작업 목록 읽기"] C --> D{"명령 종류 확인"} D -->|Move| E["이동조건 찾기
속도 · TCP · 기준좌표계"] E --> F["Waypoint ID 확인"] F --> G["실제 Joint · Task 좌표 연결"] D -->|Pick / Place| H["작업 위치 · 접근거리
Tool · Pallet 확인"] D -->|Wait / If| I["DI 조건·대기조건 확인"] D -->|Loop| J["반복 횟수·하위 작업 확인"] G --> K["화면용 작업 Tree 생성"] H --> K I --> K J --> K K --> L["작업자가 순서·좌표 확인"]

작업 Tree 변환 예시

JSON의 작업목록은 id와 pId를 가진 평면 목록입니다. PC-HMI에서는 부모 ID를 다시 연결해 아래처럼 보여줍니다.

Loop
 ├─ Wait DI
 ├─ If Red
 │   ├─ Pick
 │   └─ Place
 ├─ If Blue
 │   ├─ Pick
 │   └─ Place
 └─ If Green
     ├─ Pick
     └─ Place

작업자는 이 Tree에서 Move, Pick·Place, Loop, Wait DI와 조건분기의 위치를 확인하고 수정할 수 있습니다.

JSON 수정과 원본 구조 보존

기존 Robot 파일에는 HMI에서 직접 사용하지 않는 제조사 전용 설정, Tool 정보와 미사용 Waypoint가 남아 있을 수 있습니다. 저장할 때 파일을 새로 만들지 않고 원본 전체를 보관한 뒤 수정한 항목만 바꿨습니다.

flowchart LR A["원본 JSON"] --> B["전체 원본 보관"] B --> C["수정 항목 확인"] C --> D["좌표 수정"] C --> E["속도·TCP 수정"] C --> F["작업 순서 수정"] D --> G["기존 wpList의
같은 ID만 변경"] E --> H["기존 moveList의
같은 항목만 변경"] F --> I["program Tree 변경"] G --> J["미사용 항목과 병합"] H --> J I --> J J --> K["Conty 호환 JSON 저장"] K --> L["참조·단위·TCP 검사"]

보존한 항목은 다음과 같습니다.

  • 사용하지 않은 Waypoint와 Move 설정
  • Tool·Pallet 정보
  • 제조사 전용 노드
  • id·pId 관계
  • TCP와 기준좌표계
  • 상대이동과 특수 Move 정보

Digital Twin 구현방법

Digital Twin은 Teaching JSON만으로 자동 생성하지 않았습니다. Robot 작업 데이터, 공장 배치정보와 실시간 Robot 상태를 함께 사용했습니다.

공장 배치정보

Robot A·B·C 설치위치, Robot 간 간격, 차량 이동 레일, 조립·검사·배출 위치와 차량 객체는 Digital Twin 화면에서 별도로 배치했습니다.

Teaching JSON

작업 순서, 목표 좌표, TCP, Pick·Place, Pallet, DI 조건과 반복·분기 정보를 가져와 Robot별 작업내용과 예상 위치를 확인했습니다.

실시간 Robot 상태

실제 Robot에서 받은 J1~J6 값을 Forward Kinematics에 적용해 각 관절의 3D 위치를 계산했습니다. Robot별 설치 Offset과 TCP Offset을 더한 뒤 3D Robot 자세, Tool 위치와 이동궤적에 반영했습니다.

제조 지식을 모아 검색하는 HeungTology

Markdown으로 모은 제조 지식과 문서 링크를 연결해 질문과 관련된 자료를 찾아주는 개인 프로젝트

프로젝트 기간
개인 프로젝트 · 공개 main Snapshot 검증
맥락
개인 AI 활용 프로젝트
담당 범위
지식 구조, 변경분 동기화, 검색·재정렬 CLI

사용자·구현·검증 요약

사용자 문제
제조·반도체·배터리 지식이 파일마다 다른 용어와 링크로 쌓여 필요한 근거를 다시 찾기 어려웠습니다.
구현 범위
Markdown/YAML 저장소 구조와 링크 그래프 인덱스를 정리하고, 변경 파일을 ChromaDB에 동기화해 검색·재정렬하는 CLI를 구성했습니다.
결과·현재 단계
현재 공개 main에서 지식 저장소, 링크 그래프 인덱스와 `--sync`·질의 흐름을 확인할 수 있습니다.

사용자와 기존 문제

제조·반도체·배터리 자료를 오래 모으면 같은 설비와 현상을 서로 다른 이름으로 적게 됩니다. 폴더가 커질수록 “관련 문서가 있는지”, “어떤 원문에서 나온 설명인지”, “최근에 바뀐 문서만 다시 색인할 수 있는지”가 더 중요해집니다.

HeungTology는 Markdown 문서를 사람이 읽는 원본으로 유지하면서 YAML Metadata와 문서 링크를 이용해 주제와 관계를 찾고, 자연어 질문으로 후보 문서를 검색하기 위한 개인 지식 저장소입니다.

저장소 구조

HeungTology
├─ 02_Knowledge/                 # 산업별 Markdown 지식 문서
│  └─ _System/_index/
│     ├─ GRAPH.md                # 문서 링크 기반 관계 인덱스
│     ├─ VAULT_INDEX.md          # 저장소 탐색용 인덱스
│     └─ index.json              # 검색·도구용 인덱스
├─ 02_Knowledge/_System/
│  └─ _Ontology_Map.json         # 주제·관계 Map
├─ rag_cli_v2.py                 # 변경분 동기화와 자연어 질의 CLI
└─ README.md

--sync는 Markdown 변경분을 찾아 ChromaDB Collection에 넣고, 질의 흐름은 BGE 계열 Embedding과 Reranker로 후보를 다시 정렬합니다. 문서의 [[Link]], YAML Metadata와 별도 그래프 인덱스는 사람이 탐색하는 지식 구조와 검색용 인덱스를 연결합니다.

AS-IS → TO-BE

구분기존 방식HeungTology에서 정리한 방식
원본폴더마다 형식이 다른 문서Markdown 본문과 YAML Metadata
관계사람이 기억하거나 문서 안에서 검색[[Link]]와 Graph Index
갱신전체를 다시 읽음수정시간 Checkpoint 기반 변경분 동기화
검색파일명·키워드 중심ChromaDB 의미검색과 Reranking
답변 근거기억에 의존후보 문서 제목과 본문을 함께 확인

데이터와 실행 흐름

Markdown + YAML
→ 파일 변경 여부 확인
→ Chunk와 Metadata 구성
→ ChromaDB 동기화
→ 질문 Embedding
→ 후보 문서 검색
→ Reranking
→ 원문 제목·본문을 붙여 검토

문서 원본과 생성 인덱스를 분리한 이유는 인덱스가 손상돼도 사람이 읽는 원문을 다시 기준으로 만들 수 있게 하기 위해서입니다.

내가 직접 구성한 부분

  • 산업별 Markdown 저장소와 Metadata 규칙
  • 문서 링크를 이용한 관계 인덱스
  • 변경 파일만 다시 처리하는 동기화 흐름
  • 자연어 질문의 후보 검색과 재정렬 CLI
  • 검색 결과에서 원문을 다시 확인하기 위한 제목·본문 연결

AI는 후보를 빠르게 찾는 역할을 합니다. 문서 내용의 사실 여부, 출처 상태와 최종 공개 판단은 사람이 확인해야 합니다.

현재 단계

현재 공개 범위는 Markdown 지식 저장소·링크 그래프 인덱스·검색 CLI 프로토타입입니다. 다음 단계에서는 생성 인덱스를 지운 뒤 같은 결과를 다시 만드는 시험과, 검색 결과에서 원문 위치를 바로 확인하는 화면을 보강할 계획입니다.

제조현장에서 쓰려면 남은 조건

  1. 원문별 출처와 갱신일을 강제해야 합니다.
  2. 검색 결과에 문서 위치와 인용 가능한 근거를 함께 보여줘야 합니다.
  3. 생성 인덱스를 지우고 다시 만드는 재현 시험이 필요합니다.
  4. Graph DB를 실제 사용한다면 적재 코드, Query와 결과 Snapshot을 별도로 검증해야 합니다.
  5. 품질·안전 판단은 검색 결과만으로 자동 승인하지 않아야 합니다.

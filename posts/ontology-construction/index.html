프로젝트 배경과 Vision

제조·반도체·배터리 문서는 파일별 용어·폴더·링크가 달라 같은 문제가 재발해도 관련 원문과 상위 개념을 다시 찾는 데 시간이 소요됩니다. 원문을 찾은 뒤에도 원인분석 보고서, 공정 Spec과 실행계획으로 재구성하는 작업이 반복됩니다.

HeungTology는 기존 Markdown 지식원장을 유지하면서 다음 흐름을 연결했습니다.

분산 문서·Metadata
→ Graphfy 관계 시각화
→ 변경분 증분 Index
→ 자연어 검색·Reranking
→ Gemma 12B 엔지니어링 초안
→ 엔지니어 검토·수정
→ 개정 지식 재색인

공개 저장소는 Markdown/YAML·ChromaDB·BGE-M3·Reranker 검색코어를 소유합니다. 이번에 추가한 실행증거는 로컬 Graphfy 관계망과 Gemma 12B Agent가 실제로 생성한 Markdown 문서 3건입니다.

Graphfy 관계 연결

문서 링크와 YAML Frontmatter의 Domain·Object Type·is_instance_of·SPO 관계를 기반으로 Graphfy에서 지식노드의 연결을 시각화했습니다.

Graph 입력연결 의미검색·Agent 활용
Domain·Object Type·Tier분야·문서유형·우선순위후보범위·상위문서 분리
is_instance_of·Related상위개념·연관문서주변 지식노드 확장
SPO 관계Subject–Predicate–Object 문맥원인·대상·행동 관계 보강
Expected Query문서가 답할 질문Query–Document 문맥 보강
Trust·Date·Hash최신성·신뢰·변경상태후보 Score·검토 우선순위

Graph View의 현재 역할은 관계 탐색과 RAG Context 선택입니다. 자동 Graph 추론은 후속 Engineering Gate로 분리했습니다.

Incremental Sync

Markdown 탐색
→ 제외폴더 Filter
→ 파일 수정시각·Checkpoint 비교
→ 신규·수정 파일 선별
→ Frontmatter·본문 Parsing
→ ChromaDB 문서단위 Upsert
→ Checkpoint 갱신

전체 문서를 매번 Embedding하지 않고 변경된 파일만 반영했습니다. 제조문서가 계속 개정되는 환경에서 지식갱신을 반복 가능한 Sync 절차로 전환한 구조입니다.

검색모드는 검토할 원문 후보를 반환합니다. Agent 모드는 해당 후보와 관계노드를 Context로 묶어 문서 초안을 생성합니다.

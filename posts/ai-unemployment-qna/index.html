팀 경계

AI는 질문 분류와 초안을 돕고, 출처 선택·법적 표현·최종 공개는 사람이 확인합니다.

공개 범위: 원본 대화와 개인 통지는 공개하지 않고, 비식별 질문 유형과 공식 출처 연결만 사용합니다.

사용자가 질문을 찾고 공식 확인 경로로 이동하는 흐름을 중심으로 설명합니다.

문제

“자진 퇴사인데 실업급여를 받을 수 있나요?”라는 짧은 질문도 퇴사 사유, 피보험 기간, 제출 서류, 구직활동과 기관 판단에 따라 답이 달라질 수 있습니다. 한 문장으로 자격을 단정하면 최신 제도나 실제 행정 처분과 충돌할 수 있습니다. 원본 대화를 그대로 공개하면 개인 사정이 드러나고 비슷한 질문이 반복되는 문제도 생깁니다.

이 프로젝트는 개인의 수급 여부를 대신 판단하는 챗봇이 아니라, 비식별화한 질문을 공식 확인 경로로 안내하는 정적 정보 서비스로 만들었습니다.

대표 사용자 장면

퇴사한 사용자가 사이트에서 자기 상황과 가까운 유형을 고릅니다. 가이드에서 퇴사 사유, 기간, 필요한 서류와 구직활동처럼 먼저 확인할 항목을 살펴본 뒤 고용24, 고용노동부와 국가법령정보센터의 관련 근거로 이동합니다. 자신에게 적용되는 최종 결과는 사이트 문장이 아니라 기관이 발행한 개인 통지, 고용24의 현재 안내와 관할 고용센터에서 다시 확인합니다.

사이트에는 원본 채팅이나 이름, 연락처, 고용주와 사건 세부정보가 나오지 않습니다.

처음 보는 사람을 위한 화면 안내

첫 화면은 챗봇 입력창이 아니라 “지금 무엇을 해야 하는가”를 고르는 안내판입니다. 상단에는 처음 신청, 실업인정 차수, 인정서류, 근로·소득 신고처럼 방문 목적이 분명한 메뉴를 두었습니다. 본문은 처음 방문 순서, 자주 쓰는 9개 가이드, 8개 질문 유형으로 내려갑니다.

화면 독자가 확인하는 것 설계한 이유
홈 지금 필요한 가이드와 자기 상황에 가까운 질문 유형 긴 검색 없이 다음 행동부터 찾게 함
핵심 가이드 준비물, 순서, 예외와 기준일 반복 질문을 실제 행동 순서로 바꿈
질문 유형 비슷한 질문과 공통 확인 항목 원본 대화를 공개하지 않고 사례를 재사용
공식 출처 고용24·고용노동부·법령의 현재 안내 사이트 문장보다 공식 판단이 우선임을 분명히 함
편집 기준 답변 범위, 비식별화와 최신성 한계 무엇을 근거로 발행했는지 독자가 확인

이 도구가 하는 일과 하지 않는 일

이 도구는 비식별화한 질문 165개를 8개 유형으로 묶고 각 유형을 확인 항목, 공식 출처, 9개 실전 가이드와 21개 검색 페이지에 연결합니다. 사용자는 자유 대화 답변 대신 같은 근거와 주의 문구를 다시 확인할 수 있습니다.

이 도구는 개인의 수급 자격, 지급액이나 이의신청 결과를 확정하지 않습니다. 신청을 제출하거나 고용24 계정에 접근하지도 않습니다. 제도가 바뀌어도 사이트가 자동으로 최신이 되지는 않습니다. 기관 통지·고용24·관할 고용센터의 안내가 항상 사이트보다 우선합니다.

데이터, AI, 사람의 역할

데이터는 질문 유형, 상황, 확인할 사실과 문서, 공식 출처, 주의 문구를 나눠 보관합니다. 같은 source에서 Q&A, 가이드, 검색 페이지와 구조화 데이터를 생성해 문구나 링크를 서로 다른 파일에서 따로 관리하지 않도록 했습니다.

AI는 질문 유형 초안, 중복과 검색어 묶음, 답변 구조와 메타데이터 초안을 만드는 데 사용했습니다. 사람은 원본 질문을 비식별화했습니다. 고용24·고용노동부·국가법령정보센터 링크를 확인했고 개인 판정처럼 읽힐 수 있는 문장도 검토했습니다.

화면·데이터·저장소 구조

이 사이트는 사용자 질문을 실시간으로 LLM에 보내지 않습니다. 검토한 콘텐츠 source에서 홈, 질문 유형, 상세 가이드, 검색용 페이지와 구조화 데이터를 한 번에 생성하는 정적 구조입니다. 같은 주의 문구와 공식 링크를 여러 HTML 파일에 손으로 복사하지 않기 때문에 수정 범위를 추적하기 쉽고, 운영 화면에서 개인 대화를 수집하지 않아도 됩니다.

content/cases.json            비식별 질문 165건
content/site-content.mjs      8개 유형, 홈과 공통 안내
content/practical-guides.mjs  행동 순서 중심 상세 가이드
scripts/build-content-site.mjs
                              source를 HTML·sitemap·구조화 데이터로 생성
site-src/                     공통 CSS·브라우저 동작·아이콘
cloudflare-pages/             Cloudflare Pages용 정적 산출물
public/guide/                 Sites 미러가 사용하는 동일 콘텐츠
tests/                        수량·링크·메타데이터·모바일 답변 구조 검사

Git에서 읽는 순서는 content/에서 어떤 사실과 문구를 관리하는지 확인하고, scripts/build-content-site.mjs에서 페이지가 어떻게 만들어지는지 본 뒤, site-src/와 tests/로 표현과 회귀 기준을 확인하는 방식입니다. 배포 폴더는 source가 아니라 생성 결과이므로 직접 고치는 대상이 아닙니다. 소스 저장소는 공개하지 않았으며, 위 지도는 운영 화면을 이해하는 데 필요한 책임 단위만 공개한 것입니다.

만든 순서

  1. 원본 질문에서 개인정보와 사건 세부정보를 제거하고 165개 질문을 비식별화했습니다.
  2. 확인 목적이 비슷한 질문을 8개 유형으로 묶었습니다.
  3. 각 유형에 퇴사 사유, 기간, 서류, 구직활동 같은 확인 항목을 붙였습니다.
  4. 고용24·고용노동부·국가법령정보센터의 공식 근거와 다음 확인 경로를 연결했습니다.
  5. Q&A, 9개 실전 가이드, 21개 검색 페이지, Schema.org 데이터와 sitemap을 정적으로 생성했습니다.
  6. CSS·JavaScript 자산에 내용 hash를 붙이고 Cloudflare Pages와 Sites의 대표 경로를 다시 확인했습니다.

회사에서 얻을 수 있는 가치와 한계

공공정보나 사내 지원 제도를 설명할 때도 같은 구조를 쓸 수 있습니다. 반복 문의를 유형화하고 답변 옆에 공식 근거와 사용자가 다음에 확인할 곳을 붙이면 자유 형식 챗봇보다 검토 범위가 선명해집니다. 비식별화와 원본 대화 비공개 원칙은 개인정보 노출 범위를 줄이는 기준이 됩니다. 정적 생성 방식은 같은 근거와 주의 문구를 여러 페이지에서 일관되게 재사용하기에도 적합합니다.

한계는 행정 판단과 최신성입니다. 원본 채팅과 개인 통지는 공개하지 않습니다. 사이트는 자격·지급액·처분 결과를 확정하지 않습니다. 기관이 발행한 개인 통지, 고용24의 현재 안내, 관할 고용센터와 최신 법령이 사이트보다 우선합니다. 공식 출처를 확인할 수 없는 단정과 변경 위험이 큰 숫자는 발행하지 않습니다.

Problem

실업급여 질문은 퇴사 사유, 피보험 기간, 구직활동과 개인 통지에 따라 달라져 짧은 답변만으로 자격을 단정하면 실제 행정 판단과 충돌할 수 있습니다.

비식별 질문을 유형화하고 고용24·고용노동부·국가법령정보센터 근거, 실전 가이드와 개인 확인 경로를 함께 제공하는 것입니다.

165개 질문이 8개 카테고리와 가이드로 탐색되고, 공식 링크·구조화 데이터·캐시 갱신이 정적 사이트에서 재현되며 개인 판정을 대신하지 않으면 성공입니다.

AI와 사람이 나눈 역할

AI 역할
질문 유형 초안, 중복·검색어 군집화, 답변 구조와 메타데이터 초안을 만들고 정적 페이지 생성 검사를 지원했습니다.
사람 역할
원문 대화를 비식별화하고, 공식 기관·법령 링크와 제도 표현, 개인 판정이 필요한 문구를 사람이 확인했습니다.
공개 Gate
개인정보·원문 대화·개인 통지를 공개하지 않고, 공식 출처가 없거나 제도 변경 위험이 큰 단정은 발행하지 않습니다.
외부 효과
정적 정보 사이트의 공개 배포만 있습니다. 신청 제출, 수급 자격 판정, 고용24 계정 접근과 행정 처리는 수행하지 않습니다.

범위와 경계

포함 범위

  • 비식별 질문 165건·8개 카테고리·실전 가이드
  • 고용24·고용노동부·국가법령정보센터 근거 연결
  • 정적 생성, 검색 페이지, Schema.org와 자산 hash cache busting

제외·미검증 범위

  • 개별 사용자의 수급 자격·지급액·처분 결과 확정
  • 원본 채팅, 개인 통지, 연락처와 사건 정보 공개
  • 사이트 내용을 최신 법령이나 담당 기관 판단보다 우선

구현·검증 기준

해야 할 일

  • 질문을 유형·상황·확인 항목·공식 근거로 분류한다.
  • 답변마다 개인 확인이 필요한 조건과 공식 문의 경로를 제공한다.
  • 정적 페이지·검색·구조화 데이터를 동일 source에서 생성한다.

품질·운영 기준

  • 공식 출처와 사이트 설명을 구분하고 변경 가능성을 표시한다.
  • 개인정보·원문 대화·비공개 저장소 URL을 산출물에서 차단한다.
  • CSS·JS 자산 hash를 URL에 반영해 오래된 캐시를 무효화한다.

왜 이렇게 구성했나

  1. 자유 대화보다 유형화된 정적 Q&A

    같은 근거와 경고 문구를 반복 검증하고 검색 엔진에서도 확인할 수 있기 때문입니다.

  2. 공식 출처와 행동 경로를 함께 제공

    설명만 읽고 자격을 단정하지 않고 실제 개인 통지와 담당 기관을 확인하게 하기 위해서입니다.

  3. 자산 hash로 배포 캐시 통제

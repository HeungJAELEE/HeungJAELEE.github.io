    문제: 비슷한 질문도 행정 결과는 다를 수 있다

    “자진 퇴사인데 받을 수 있나요?”처럼 짧은 질문은 퇴사 사유, 피보험 기간, 이직확인서, 구직활동, 개인 통지와 관할 기관 판단에 따라 결과가 달라질 수 있습니다. 사이트가 개인 자격을 단정하면 최신 법령이나 실제 처분과 충돌할 위험이 있습니다.

    따라서 이 서비스는 답을 대신 결정하는 챗봇이 아니라 다음을 빠르게 찾는 정적 확인 도구로 설계했습니다.

    • 내 질문이 어떤 유형에 가까운가
    • 어떤 사실과 문서를 먼저 확인해야 하는가
    • 고용24·고용노동부·법령의 어느 근거를 읽어야 하는가
    • 개인 통지나 관할 고용센터에 무엇을 다시 확인해야 하는가

    왜 165개 질문을 8개 카테고리로 묶었는가

    원문 대화를 그대로 공개하면 개인정보와 중복이 늘어납니다. 반대로 하나의 거대한 FAQ는 사용자가 자기 상황을 찾기 어렵습니다.

    비식별화한 질문 165건을 의도와 확인 항목이 비슷한 8개 카테고리로 분류하고, 반복 질문은 가이드와 검색어로 연결했습니다. 완료 스냅숏에는 9개 실전 가이드와 21개 검색 페이지가 포함됩니다.

    아키텍처와 데이터 흐름

    flowchart LR A["원본 질문"] --> B["비식별화\n개인정보·사건 세부 제거"] B --> C["질문 유형 분류\n8 categories"] C --> D["확인 항목\n사유 · 기간 · 서류 · 활동"] D --> E["공식 근거\n고용24 · 고용노동부 · 법령"] E --> F["Q&A · 9 guides · 21 search pages"] F --> G["정적 생성"] G --> H["Schema.org · sitemap · asset hash"] H --> I["Cloudflare Pages · Sites"]

    질문 데이터와 페이지 HTML을 따로 수동 편집하지 않습니다. 같은 source에서 Q&A, 가이드, 검색 페이지, 구조화 데이터와 링크 검사를 생성해야 수정 누락을 줄일 수 있습니다.

    사용 기술과 구성

    영역기술사용 이유
    콘텐츠 파이프라인Node.js 정적 생성 스크립트한 source에서 Q&A·가이드·검색 페이지 생성
    데이터 모델유형·상황·확인 항목·근거·주의 문구자유 문장보다 검증 가능한 필드로 관리
    검색·SEO정적 index, Schema.org JSON-LD, sitemap질문 의도와 공식 출처를 탐색 가능하게 제공
    최신 자산CSS·JS content hash query배포 뒤 오래된 캐시가 새 화면을 깨뜨리지 않게 함
    운영Cloudflare Pages, Sites mirror공개 URL에서 대표 경로와 자산을 read-back
    개인정보비식별화·원문 비공개개인 사건과 연락처가 정적 산출물에 남지 않게 함

    AI와 사람의 역할

    AI는 질문 유형·중복·검색어 군집, 답변 구조와 메타데이터 초안을 만드는 데 사용했습니다. 그러나 공식 출처를 선택하고 법령 문구를 개인에게 적용하는 최종 판단을 AI에 맡기지 않았습니다.

    사람은 원문 대화를 비식별화하고, 고용24·고용노동부·국가법령정보센터 링크를 확인했으며, 개인 판정처럼 읽힐 수 있는 표현과 제도 변경 경고를 검토했습니다.

    구성 이유와 확인한 결과

    Problem

    실업급여 질문은 퇴사 사유, 피보험 기간, 구직활동과 개인 통지에 따라 달라져 짧은 답변만으로 자격을 단정하면 실제 행정 판단과 충돌할 수 있습니다.

    Goal

    비식별 질문을 유형화하고 고용24·고용노동부·국가법령정보센터 근거, 실전 가이드와 개인 확인 경로를 함께 제공하는 것입니다.

    Success

    165개 질문이 8개 카테고리와 가이드로 탐색되고, 공식 링크·구조화 데이터·캐시 갱신이 정적 사이트에서 재현되며 개인 판정을 대신하지 않으면 성공입니다.

    AI와 사람이 나눈 역할

    AI 역할
    질문 유형 초안, 중복·검색어 군집화, 답변 구조와 메타데이터 초안을 만들고 정적 페이지 생성 검사를 지원했습니다.
    사람 역할
    원문 대화를 비식별화하고, 공식 기관·법령 링크와 제도 표현, 개인 판정이 필요한 문구를 사람이 확인했습니다.
    공개 Gate
    개인정보·원문 대화·개인 통지를 공개하지 않고, 공식 출처가 없거나 제도 변경 위험이 큰 단정은 발행하지 않습니다.
    외부 효과
    정적 정보 사이트의 공개 배포만 있습니다. 신청 제출, 수급 자격 판정, 고용24 계정 접근과 행정 처리는 수행하지 않습니다.

    범위와 경계

    포함 범위

    • 비식별 질문 165건·8개 카테고리·실전 가이드
    • 고용24·고용노동부·국가법령정보센터 근거 연결
    • 정적 생성, 검색 페이지, Schema.org와 자산 hash cache busting

    제외·미검증 범위

    • 개별 사용자의 수급 자격·지급액·처분 결과 확정
    • 원본 채팅, 개인 통지, 연락처와 사건 정보 공개
    • 사이트 내용을 최신 법령이나 담당 기관 판단보다 우선

    구현·검증 기준

    해야 할 일

    • 질문을 유형·상황·확인 항목·공식 근거로 분류한다.
    • 답변마다 개인 확인이 필요한 조건과 공식 문의 경로를 제공한다.
    • 정적 페이지·검색·구조화 데이터를 동일 source에서 생성한다.

    품질·운영 기준

    • 공식 출처와 사이트 설명을 구분하고 변경 가능성을 표시한다.
    • 개인정보·원문 대화·비공개 저장소 URL을 산출물에서 차단한다.
    • CSS·JS 자산 hash를 URL에 반영해 오래된 캐시를 무효화한다.

    왜 이렇게 구성했나

    1. 자유 대화보다 유형화된 정적 Q&A

      같은 근거와 경고 문구를 반복 검증하고 검색 엔진에서도 확인할 수 있기 때문입니다.

    2. 공식 출처와 행동 경로를 함께 제공

      설명만 읽고 자격을 단정하지 않고 실제 개인 통지와 담당 기관을 확인하게 하기 위해서입니다.

    3. 자산 hash로 배포 캐시 통제

      콘텐츠가 갱신돼도 이전 CSS·JS가 남아 화면과 로직이 어긋나는 문제를 방지하기 위해서입니다.

    한계와 공개 Gate

    • 원본 채팅, 개인 통지, 이름·연락처·회사·사건 세부는 공개하지 않습니다.
    • 사이트는 수급 자격, 지급액, 이의신청 결과를 확정하지 않습니다.
    • 개인 통지, 고용24의 현재 안내, 관할 고용센터와 최신 법령이 사이트보다 우선합니다.
    • 공식 출처를 확인할 수 없는 단정과 제도 변경 위험이 큰 숫자는 자동 발행하지 않습니다.

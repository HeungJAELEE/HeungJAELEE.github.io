로컬 Foundation

Ontology·LLM Wiki 기반 Agent 실행명세·안전 검증 Foundation

지식과 실행조건을 Agent 명세로 구성하고 승인·근거·중단조건을 로컬 제한 실행에서 확인

개인 로컬 Foundation · 운영 연결 전
맥락
AI 개인 활용 프로젝트

30 SECOND READ

30초 요약

문제
AI가 자료를 읽고 행동을 제안했다는 사실만으로 실제 실행 권한과 안전한 결과를 보장할 수 없습니다.
내 역할
Ontology·LLM Wiki 지식과 실행조건을 Agent 명세로 묶고 근거 확인, 사람 승인, 허용·차단, 결과 재확인 순서를 설계했습니다.
결과·현재 단계
로컬 제한 실행과 차단 조건을 확인한 Foundation이며 운영 플랫폼, 외부 효과, 운영 GO는 완료하지 않았습니다.
내가 직접 한 일
개인 설계·로컬 검증

이 프로젝트를 한 문장으로 설명하면

Ontology와 LLM Wiki에서 필요한 지식을 고르고, AI Agent가 무엇을 읽고 어떤 도구를 어느 조건에서 사용할지 실행명세로 만든 뒤, 근거·사람 승인·중단조건이 모두 맞을 때만 제한된 로컬 실행을 허용하는 Foundation입니다.

완성된 운영 플랫폼이나 외부 시스템을 자동으로 바꾸는 제품은 아닙니다. Agent를 구성하고 실행하는 플랫폼으로 발전시키기 전에, 지식 선택과 실행 권한을 어떻게 안전하게 연결할지 검증한 기반입니다.

대표 사용 장면

예를 들어 제조 설비의 이상 원인을 정리하는 Agent를 만든다고 가정합니다.

  1. 사용자가 “특정 설비의 이상 징후를 읽고 점검 순서를 제안하라”고 요청합니다.
  2. Agent는 Ontology에서 설비·공정·불량·점검 항목의 관계를 찾습니다.
  3. LLM Wiki에서 관련 원문과 출처 상태를 가져옵니다.
  4. 사용할 Tool, 읽기 범위, 금지 동작과 중단조건을 실행명세로 묶습니다.
  5. AI가 제안한 작업과 근거를 사람이 확인합니다.
  6. 승인 범위 안의 로컬 읽기·분석만 실행합니다.
  7. 실행 뒤 실제 결과를 다시 읽어 예상과 일치하는지 확인합니다.

자료를 읽을 수 있다는 사실은 설비 설정을 바꿀 권한을 뜻하지 않습니다. 이 구분이 프로젝트의 출발점입니다.

사용자가 보게 될 구조

현재는 공개 운영 UI가 없으므로 화면을 완성된 제품처럼 제시하지 않습니다. 대신 플랫폼화할 때 필요한 화면과 정보 구조를 다음처럼 정의했습니다.

영역 사용자가 확인할 내용
지식 선택 어떤 Ontology 영역과 Wiki 문서를 Agent가 사용할지
Agent 명세 목적, 허용 Tool, 입력 범위, 위험과 중단조건
근거 검토 원문 위치, 출처 상태, 최신성, HOLD 항목
승인 누가 어떤 범위와 시간 동안 실행을 허용했는지
실행 기록 실행한 Tool, 입력·출력 요약과 차단 사유
결과 확인 외부 또는 로컬 상태를 다시 읽어 예상과 비교한 결과

AI 제안부터 결과 확인까지

복잡한 Gate 이름보다 실제 사용 순서가 먼저 이해되도록 다섯 단계로 정리했습니다.

AI가 작업을 제안한다
→ 근거와 사용할 지식을 확인한다
→ 사람이 허용 범위와 중단조건을 승인한다
→ 허용된 작업만 제한 실행하고 나머지는 차단한다
→ 실행 뒤 실제 상태를 다시 읽어 결과를 확인한다

차단은 실패를 숨기는 상태가 아닙니다. 필요한 근거·권한·동일한 실행대상이 없을 때 올바르게 멈춘 결과입니다.

데이터와 시스템 구조

1. Ontology·LLM Wiki

Ontology는 설비·공정·현상·원인·조치 같은 관계를 찾는 데 사용합니다. LLM Wiki는 사람이 읽을 수 있는 원문과 출처·검토 상태를 제공합니다. Agent는 검색 결과만 믿지 않고 실행에 사용한 문서와 상태를 명세에 남깁니다.

2. Agent 실행명세

실행명세에는 다음이 들어갑니다.

  • Agent가 해결할 문제와 성공조건
  • 읽을 수 있는 Source와 사용할 Tool
  • 절대 수행하면 안 되는 동작
  • 필요한 사람 승인과 유효 범위
  • 중복 실행을 막는 식별자
  • 실행 전·후 확인할 상태

3. 제한 실행

승인이 없거나 Source가 불충분하면 실행하지 않습니다. 실행을 허용하더라도 명세에 없는 Tool과 대상은 사용할 수 없게 하는 것이 목표입니다.

4. 결과 재확인

코드가 성공 응답을 냈다는 사실만으로 완료하지 않습니다. 실행 뒤 실제 상태를 다시 읽고, 예상한 대상과 결과가 맞는지 비교해야 합니다. 불일치하면 다음 동작을 멈추고 재확인 대상으로 돌립니다.

AI가 하는 일과 사람이 하는 일

구분 담당
관련 지식 후보 찾기 AI
원문 요약과 실행 초안 AI
출처가 실제 요구와 맞는지 판단 사람
위험·권한 범위 결정 사람
승인 주체와 유효시간 확인 시스템 + 사람
허용된 로컬 작업 실행 시스템
결과가 맞는지 최종 판단 사람

AI가 승인 주체를 대신하거나, 누락된 근거를 자연스러운 문장으로 채워서는 안 됩니다.

구현 순서

  1. 지식 Source와 상태를 분류했습니다.
  2. Agent 목적·Tool·위험·중단조건을 하나의 실행명세로 묶었습니다.
  3. Source, 명세와 실행 Artifact가 같은 대상을 가리키는지 확인하는 조건을 만들었습니다.
  4. 승인 누락, Artifact 불일치와 재시작 시 불명확한 상태를 차단했습니다.
  5. 로컬 제한 실행 뒤 결과를 다시 읽는 흐름을 검증했습니다.

현재 결과와 남은 조건

현재 결과는 로컬 Foundation입니다. 실제 운영 주문, 설비 제어, 결제, 배포와 권한 변경은 수행하지 않았습니다. 공개 운영 화면과 재현 가능한 공개 저장소도 없습니다.

운영 플랫폼으로 발전하려면 다음이 더 필요합니다.

  • 실제 사용자·역할별 권한과 승인 UI
  • Tool별 허용 대상과 Parameter 제한
  • 재시작·중복 요청·부분 실패 회귀시험
  • 외부 시스템별 authoritative read-back
  • 감사 가능한 실행 기록과 개인정보·Secret 처리
  • 운영 환경에서의 독립 보안 검토와 사람 승인

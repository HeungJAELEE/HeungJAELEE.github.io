로컬 Foundation

근거를 확인한 뒤 실행하는 AI Agent 실험

AI가 자료를 읽고 행동을 제안하더라도 근거와 사람의 승인을 확인한 뒤에만 실행하도록 만든 로컬 실험

프로젝트 기간
개인 로컬 실험 · 외부 시스템 연결 전
맥락
AI 개인 활용 프로젝트
담당 범위
Agent 명세, 근거·승인·중단조건, 로컬 제한 실행 구조

사용자·구현·검증 요약

사용자 문제
AI가 자료를 읽고 행동을 제안했다는 사실만으로 실제 실행 권한과 안전한 결과를 보장할 수 없습니다.
구현 범위
Ontology·LLM Wiki의 지식과 실행조건을 Agent 명세로 묶고, 근거 확인·사람 승인·중단조건을 어떤 순서로 적용할지 설계하고 있습니다.
결과·현재 단계
현재는 서로 다른 LLM과 데이터에서 판단이 어떻게 달라지는지, 사람이 어디서 승인해야 하는지를 확인하는 로컬 Foundation 단계입니다.

이 프로젝트를 한 문장으로 설명하면

Ontology와 LLM Wiki에서 필요한 지식을 고르고, AI Agent가 무엇을 읽고 어떤 도구를 어느 조건에서 사용할지 실행명세로 정리하는 로컬 실험입니다.

현재는 서로 다른 LLM과 데이터가 어떤 판단 차이를 만드는지, AI의 제안과 사람의 승인을 어디서 나눠야 하는지 확인하는 Foundation 단계입니다. 승인·차단·결과 재확인의 전체 실행 흐름은 아직 테스트 중이며, 실제 외부 시스템을 움직이는 운영 서비스는 아닙니다.

대표 사용 장면

예를 들어 제조 설비의 이상 원인을 정리하는 Agent를 만든다고 가정합니다.

  1. 사용자가 “특정 설비의 이상 징후를 읽고 점검 순서를 제안하라”고 요청합니다.
  2. Agent는 Ontology에서 설비·공정·불량·점검 항목의 관계를 찾습니다.
  3. LLM Wiki에서 관련 원문과 출처 상태를 가져옵니다.
  4. 사용할 Tool, 읽기 범위, 금지 동작과 중단조건을 실행명세로 묶습니다.
  5. AI가 제안한 작업과 근거를 사람이 확인합니다.
  6. 승인 범위 안의 로컬 읽기·분석만 허용하는 구조를 시험합니다.
  7. 다음 단계에서는 실행 뒤 실제 결과를 다시 읽어 예상과 일치하는지 확인합니다.

자료를 읽을 수 있다는 사실은 설비 설정을 바꿀 권한을 뜻하지 않습니다. 이 구분이 프로젝트의 출발점입니다.

이 실험을 화면으로 만든다면

사용자가 Agent의 제안과 근거를 직접 확인할 수 있도록 필요한 화면과 정보를 다음처럼 정리했습니다.

영역사용자가 확인할 내용
지식 선택어떤 Ontology 영역과 Wiki 문서를 Agent가 사용할지
Agent 명세목적, 허용 Tool, 입력 범위, 위험과 중단조건
근거 검토원문 위치, 출처 상태, 최신성, HOLD 항목
승인누가 어떤 범위와 시간 동안 실행을 허용했는지
실행 기록실행한 Tool, 입력·출력 요약과 차단 사유
결과 확인외부 또는 로컬 상태를 다시 읽어 예상과 비교한 결과

AI 제안부터 결과 확인까지

복잡한 용어보다 실제 사용 순서가 먼저 보이도록 다섯 단계로 정리했습니다.

  1. AI가 요청을 읽고 필요한 작업을 제안합니다.
  2. 사용자는 AI가 선택한 지식과 원문 근거를 확인합니다.
  3. 사람이 사용할 Tool, 대상, 시간과 중단조건을 승인합니다.
  4. 시스템은 승인된 작업만 실행하고 범위를 벗어나면 멈춥니다.
  5. 실행이 끝나면 실제 상태를 다시 읽어 요청한 결과와 맞는지 확인합니다.

필요한 근거와 권한이 없을 때 무엇이 부족한지 보여 주고 멈추는 방식을 목표로 합니다. 현재 공개할 수 있는 완료 결과는 설계와 로컬 실험 범위이며, 구체적인 허용·차단 시나리오와 실행 로그는 추가 검증 항목입니다.

데이터와 시스템 구조

구성 1 — Ontology·LLM Wiki

Ontology는 설비·공정·현상·원인·조치 같은 관계를 찾는 데 사용합니다. LLM Wiki는 사람이 읽을 수 있는 원문과 출처·검토 상태를 제공합니다. Agent는 검색 결과만 믿지 않고 실행에 사용한 문서와 상태를 명세에 남깁니다.

구성 2 — Agent 실행명세

실행명세에는 다음이 들어갑니다.

  • Agent가 해결할 문제와 성공조건
  • 읽을 수 있는 Source와 사용할 Tool
  • 절대 수행하면 안 되는 동작
  • 필요한 사람 승인과 유효 범위
  • 중복 실행을 막는 식별자
  • 실행 전·후 확인할 상태

구성 3 — 제한 실행

승인이 없거나 Source가 불충분하면 실행하지 않습니다. 실행을 허용하더라도 명세에 없는 Tool과 대상은 사용할 수 없게 하는 것이 목표입니다.

구성 4 — 결과 재확인

코드가 성공 응답을 냈다는 사실만으로 완료하지 않습니다. 실행 뒤 실제 상태를 다시 읽고, 예상한 대상과 결과가 맞는지 비교해야 합니다. 불일치하면 다음 동작을 멈추고 재확인 대상으로 돌립니다.

AI가 하는 일과 사람이 하는 일

구분담당
관련 지식 후보 찾기AI
원문 요약과 실행 초안AI
출처가 실제 요구와 맞는지 판단사람
위험·권한 범위 결정사람
승인 주체와 유효시간 확인시스템 + 사람
허용된 로컬 작업 실행시스템
결과가 맞는지 최종 판단사람

AI는 관련 지식을 찾고 실행 초안을 만들지만, 승인 범위와 실제 실행 결과는 사람이 확인합니다.

구현 순서

  1. 지식 Source와 상태를 분류했습니다.
  2. Agent 목적·Tool·위험·중단조건을 하나의 실행명세로 묶었습니다.
  3. Source, 명세와 실행 Artifact가 같은 대상을 가리켜야 한다는 조건을 정리했습니다.
  4. 승인 누락, Artifact 불일치와 재시작 시 불명확한 상태를 어떤 시점에 막아야 하는지 테스트 항목으로 만들었습니다.
  5. 서로 다른 LLM과 데이터에서 판단이 달라지는 지점을 비교하고 있습니다.

현재 결과와 다음 단계

현재까지 만든 결과는 Agent 명세, 근거·승인·중단조건의 구조와 로컬 실험 항목입니다. 구체적인 허용·차단 시나리오, 공개 가능한 실행 로그와 외부 상태 재확인은 아직 완료 결과로 쓰지 않습니다.

실제 서비스와 외부 시스템에 연결하려면 다음 기능을 이어서 구현해야 합니다.

  • 실제 사용자·역할별 권한과 승인 UI
  • Tool별 허용 대상과 Parameter 제한
  • 재시작·중복 요청·부분 실패 회귀시험
  • 외부 시스템별 authoritative read-back
  • 감사 가능한 실행 기록과 개인정보·Secret 처리
  • 운영 환경에서의 독립 보안 검토와 사람 승인

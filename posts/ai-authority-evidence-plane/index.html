배터리 조립라인 셋업과 수율 안정화에서는 설비 알람 하나만 보고 원인을 판단하지 않습니다. MES 이력, 검사 결과, Lot·재작업 기록, 작업자 조치, SOP·QCP·P-FMEA와 실제 설비상태를 같은 시간축과 판정기준으로 맞춰야 합니다. 그러나 이 자료는 서로 다른 시스템과 문서에 흩어져 있고, AI가 읽을 수 있다는 사실도 PLC나 MES를 바꿀 권한을 뜻하지 않습니다.

이 프로젝트는 그 간극을 줄이기 위한 제조·공정기술 의사결정 보조 시스템 설계입니다. 목표는 AI가 설비를 대신 제어하는 것이 아니라, 공정·품질·생산 자료를 근거 단위로 연결하고 여러 분석 모듈의 분석 결과를 생산기술 엔지니어가 검토할 수 있는 작업 제안으로 바꾸는 것입니다. 실행이 필요한 경우에도 사람 승인, 제한된 연결 모듈과 실제 상태 확인을 별도 단계로 둡니다.

1. 프로젝트 개요

추진 배경

생산기술자가 설비 이상, 수율 저하, 품질 편차를 확인할 때 필요한 자료는 여러 시스템에 나뉘어 있습니다. 설비 상태는 PLC·OPC, 생산 이력은 MES, 검사 결과는 품질 파일, 변경 이력은 SOP·QCP·P-FMEA와 담당자 기록에서 확인해야 합니다. 시스템마다 이름·시간·Lot·판정코드가 다르면, 원인분석보다 먼저 데이터의 의미와 적용범위를 맞추는 일이 반복됩니다.

의사결정 보조 시스템은 이 문제를 데이터 수집 → 근거 연결 → 독립 분석 → 작업 제안 → 사람 승인 → 제한 실행 → 실제 결과 재확인 흐름으로 정리합니다.

항목 설계 내용
사용자 생산기술·공정기술·품질·생산관리 엔지니어
입력 MES 생산이력, PLC·OPC 상태, 검사결과, 설비 Alarm, 표준문서, 변경·조치 기록
핵심 역할 제품 정의, 데이터·연결 구조 구조, 분석 역할 분담, 제어와 분석 분리, 승인·실제 상태 확인·복구 기준
출력 근거가 연결된 원인 후보, 반대 근거, 재확인 항목, 작업 제안과 승인 요청
안전 원칙 기본은 읽기 전용 검토 제안이며 물리 명령과 생산지시는 별도 권한으로 격리
현재 결과 제품 비전·상세 구성·실행계획과 로컬 검증 계약 확립

내가 맡은 범위

제조 현장 경험을 기준으로 다음 항목을 직접 결정하고 조율했습니다.

  • 공정·품질·생산 데이터를 어떤 공통 의미와 식별자로 묶을지
  • Worker와 통합 조정 모듈이 각각 무엇을 분석하고 어디에서 멈출지
  • 추천, 사람 승인, 외부 실행과 결과 실제 상태 확인을 왜 분리해야 하는지
  • PLC·OPC·MES 연결 모듈이 어떤 권한과 복구조건을 가져야 하는지
  • 장기 Run의 중복 Trigger, 단일 실행 주체, 중간 저장 지점과 기존 방식 복귀를 어떻게 통제할지
  • 무엇을 화면·코드·실제 상태로 확인해야 완료라고 부를지

2. 현장 문제 정의

AS-IS — 데이터는 많지만 판단의 연결이 끊긴 상태

현장 구간 기존 한계 생산기술 업무에 미치는 영향
데이터 위치 MES·PLC·OPC·Excel·표준문서·개인 기록에 분산 같은 현상을 여러 파일과 화면에서 반복 추적
의미 정합성 태그, 상태, Lot, 불량코드와 시간기준이 시스템별로 다름 서로 다른 대상을 같은 원인으로 오판할 위험
원인분석 담당자 경험과 수동 대조에 의존 누락된 반대 근거와 재시험 조건을 뒤늦게 발견
AI 활용 검색결과와 생성문장이 원문·적용범위와 분리 그럴듯한 답변을 실제 공정 판단으로 사용하기 어려움
실행 권한 분석 결과와 PLC·MES 변경권한의 경계가 불명확 추천이 곧 제어로 이어지는 안전위험
완료 판정 요청 성공·HTTP 200·제어 시스템 실행 요청 기록으로 종료 실제 설비·MES 상태가 바뀌었는지 확인되지 않음

TO-BE — 생산기술 판단을 하나의 판단 흐름으로 연결

핵심은 AI 기능을 늘리는 것이 아니라 같은 기준 자료를 놓고 공정·품질·생산 관점의 검토 결과를 비교하는 것입니다. 공정·품질·생산 Agent가 같은 Source Snapshot을 보고 독립적으로 판단하고, Manager가 충돌과 반대 의견을 지우지 않은 채 하나의 작업 제안으로 정리하는 것입니다. 생산기술 엔지니어는 근거·적용 범위·위험·복구 방법을 확인한 뒤 최종 승인하거나 보류합니다.

대표 사용 장면 — 반복 불량의 원인 추적

  1. 생산기술자가 특정 설비·Lot·시간구간의 반복 불량을 선택합니다.
  2. 읽기 전용 연결 모듈이 MES 생산이력, PLC·OPC 상태, 검사결과와 관련 표준문서의 기준 자료를 고정합니다.
  3. 공정 분석 모듈은 조건변경·4M·재시험 이력을, 품질 분석 모듈은 판정기준·측정 신뢰성을, 생산 분석 모듈은 재공·병목·Lot 흐름을 각각 확인합니다.
  4. 통합 조정 모듈은 공통 원인 후보, 배제 근거, 미확인 항목과 한 번의 통합 재검사 요청을 정리합니다.
  5. 사용자는 작업 제안을 승인·보류하거나 추가 측정을 요청합니다.
  6. 실제 변경이 필요한 경우에만 대상·변경값·만료시점을 지정한 별도 승인으로 권한이 제한된 연결 모듈을 사용합니다.
  7. 실행 뒤 설비·MES를 다시 읽고 실행 요청 기록이 아니라 실제 결과로 종료 여부를 판단합니다.

3. 시스템 구성

5개 영역과 책임 경계

영역 입력과 처리 산출물 안전·운영 규칙
읽기 전용 데이터 조회 영역 MES·QMS·PLC·OPC·Alarm·문서·이력 수집 시간·Lot·Tag·상태가 고정된 기준 자료 기본 권한은 읽기, 원문과 Runtime을 변경하지 않음
근거 확인 영역 원본 자료, 개정 이력, 최신성, 적용 범위, 권리·공개범위 인용 가능한 근거와 부족·충돌 상태 근거가 없으면 추정으로 채우지 않고 보류
검토 제안 영역 공정·품질·생산 관점의 분석 모듈과 Worker·통합 조정 흐름 원인 후보, 반대 근거, 재시험, 작업 제안 통합 조정 모듈도 더 높은 실행권한을 갖지 않음
승인·판단 영역 대상·범위·Parameter·만료·위험·기존 방식 복귀 검토 사람 승인 또는 보류 다른 대상·오래된 승인·이미 소비한 승인 재사용 금지
제한 실행 & 실제 상태 확인 영역 승인된 제한 연결 모듈과 실제 시스템 재조회 실행 요청 기록, 실제 결과, 불일치·복구 기록 요청 성공과 결과 성공을 분리하고 단일 실행 주체를 1개로 유지

초기 제조 업무 규칙 묶음은 읽기 전용 감시와 보고에 집중합니다. PLC·OPC Write, 생산지시, 자재·PO와 같은 제한 실행은 하나의 포괄 권한으로 열지 않고 연결 모듈별 승인·복구조건을 둡니다. 이 구조는 설비 안전을 지키면서도 이후 기능을 단계적으로 추가할 수 있게 합니다.

장기 운영을 위한 장기 작업 제어

  • Aggregate별 단일 실행 주체 1개와 중복 Trigger 차단
  • Queue Claim·Lease·중간 저장 지점로 장기 Run의 소유권과 진행상태 관리
  • 분석 재실행과 통신 오류 재시도를 분리
  • 재시작 뒤 같은 분석 모듈·Flow·작업 항목을 복구하되 불명확한 외부 상태에서는 자동 재실행 금지
  • Outcome Record에 근거, 반대 의견, 승인, 실행 실행 요청 기록과 실제 상태 확인 Revision을 함께 보존
  • Notion은 시스템 간 메시지 전달이 아니라 사람이 읽는 결과 기록에 사용

생산기술 의사결정 보조 도구가 제공하려는 업무 결과

  • 여러 시스템의 동일 설비·Lot·시간구간을 하나의 기준 시점 자료로 결속
  • 공정·품질·생산 관점의 원인 후보와 배제 근거를 동시에 제시
  • 재시험 전 확인할 측정 신뢰성, 변경점, 영향범위와 담당자를 한 화면에 정리
  • 작업 제안과 실행권한을 분리해 AI가 임의로 설비조건을 바꾸지 못하게 통제
  • 실행 뒤 실제 설비·MES 상태와 결과 Revision을 연결해 Close·Reopen 판단 지원

첫 제조 현장 시범 적용에서는 트러블슈팅 시간, 원인 후보 축소 시간, 재시험 횟수와 표준 반영률을 측정합니다.

시범 적용 지표 측정 목적
관련 원문·이력 확보 소요시간 수동 탐색 대비 원본 자료 결속 시간 확인
설비·Lot·검사 데이터 대조시간 시스템 간 추적 공수 확인
근거 누락·잘못된 원본 자료 비율 검토 제안 신뢰성 확인
재측정·재시험 요청의 적중률 원인분리와 현장 활용성 확인
승인 제안 채택·보류·반려율 엔지니어 판단과 AI 제안의 차이 확인
실행 요청 기록–실제 상태 확인 불일치율 실행완료 오판정 방지
중단·복구시간 중간 저장 지점·기존 방식 복귀의 운영성 확인

5. 향후 확장 비전

단계별 Scale-up

단계 적용 범위 완료 Gate
1. 읽기 전용 병행 검증 한 개 라인의 MES·검사·설비 상태와 표준문서 기준 자료 원본 자료 연결, 시간·Lot·Tag 정합성, 권리·보안 검토
2. Production 의사결정 보조 도구 공정·품질·생산 관점의 분석 모듈 독립 분석과 통합 작업 제안 Ground Truth 비교, 근거 누락·오류비용, 엔지니어 채택·반려 KPI
3. Limited 제한 실행 한 개 연결 모듈의 제한 명령 또는 생산업무 요청 Exact target·parameter·expiry, 단일 실행 주체, 기존 방식 복귀·결과 대조
4. Multi-line 업무 규칙 묶음 공정유형과 Site가 다른 라인에 공통 Core 재사용 Namespace·Manifest·연결 모듈 호환성, 단계별 Cutover
5. Autonomous Manufacturing Foundation Digital Twin·Simulation에서 제안과 제어전략 사전평가 현장 병행 검증, Safety Interlock, 사람 승인정책과 물리 E2E 재검증

Core는 분석 모듈의 역할, 처리 흐름, 승인, 기록과 복구를 담당하고, 제조 업무 규칙 묶음은 공정·품질·생산의 판정 기준을 추가합니다. 신규 라인은 업무 규칙 묶음과 연결 모듈을 교체하되 원본 자료 연결, 승인, 실제 상태 재확인과 기존 방식 복귀 절차를 유지합니다.

최종 지향점

궁극적인 목표는 AI가 공장을 임의로 운영하는 화면이 아닙니다. 생산기술 엔지니어가 여러 시스템의 상태와 근거를 빠르게 맞추고, 공정·품질·생산 분석을 비교한 뒤 필요한 작업만 승인하고 실제 결과까지 추적하는 제조 의사결정 보조 시스템입니다.

현재 단계는 상세 설계와 로컬 계획 검증입니다. 다음 우선순위는 읽기 전용 제조 기준 업무 흐름을 실제 화면과 실행 환경으로 고정하는 것입니다.

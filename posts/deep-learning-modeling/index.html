왜 이 프로젝트를 시작했는가

제조 Vision과 설비 데이터를 다루려면 모델 사용법만 아는 것으로는 부족합니다. 어떤 데이터를 학습에 썼는지, 평가 데이터가 섞이지 않았는지, 어떤 오류를 더 위험하게 봤는지 설명할 수 있어야 합니다. 이 프로젝트는 딥러닝 개념과 실험 절차를 반복해서 정리하기 위한 개인 학습 아카이브입니다.

현재 아카이브의 구성

현재 공개 저장소는 README를 중심으로 학습 주제와 실험 점검 순서를 정리한 단계입니다. 모델 코드를 많이 모으기보다, 제조 데이터에 적용할 때 어떤 조건을 남겨야 같은 실험을 다시 설명할 수 있는지에 초점을 맞췄습니다.

현재는 고정된 데이터 Split·Seed·설정파일로 대표 실험을 다시 실행한 저장소가 아닙니다. 따라서 재현 완료나 모델 성능을 성과로 내세우지 않고, 전처리부터 평가까지 놓치기 쉬운 판단 항목을 정리한 학습 아카이브로 설명합니다.

학습·실험을 보는 순서

단계 1 — 문제와 오류 비용을 먼저 정합니다

제조 데이터에서는 전체 정확도보다 놓치면 안 되는 불량, 오검 시 필요한 재검사, 데이터 수집 조건이 중요할 수 있습니다. 모델을 선택하기 전에 업무상 어떤 오류가 더 큰 비용을 만드는지 적습니다.

단계 2 — 데이터 역할을 나눕니다

원본, 학습, 검증과 최종 평가 데이터를 구분합니다. 같은 제품이나 유사한 연속 이미지가 여러 Split에 섞이면 실제보다 좋은 결과가 나올 수 있으므로, 시간·Lot·설비·제품 단위의 누수 가능성을 먼저 봅니다.

단계 3 — 전처리와 설정을 기록합니다

크기 조정, 정규화, 증강, Seed, 모델과 평가 지표를 같은 실험 기록에 둡니다. 값 하나만 남기지 않고 어떤 설정에서 나온 결과인지 연결합니다.

단계 4 — 평균값과 오류 유형을 함께 봅니다

Accuracy·F1 같은 요약값과 Confusion Matrix의 미검출·오검을 함께 확인합니다. 제조 적용을 검토할 때는 임계값을 바꿨을 때 재검사량과 미검출 위험이 어떻게 달라지는지도 봅니다.

단계 5 — 현장 적용 전 별도 Gate를 둡니다

학습 데이터 결과가 좋아도 조명, 설비, 제품과 시간 변화에서 유지되는지 확인해야 합니다. Shadow Test, 기준 Sample, 재검사 흐름, 모델 버전과 Rollback 조건이 없으면 생산 적용 완료로 보지 않습니다.

이 아카이브가 제조업무에 주는 도움

이 프로젝트의 현재 가치는 모델 성능이 아니라, AI 결과를 제조기술 판단으로 바꿀 때 필요한 질문을 정리한 데 있습니다.

  1. 문제와 오류 비용을 먼저 정의합니다.
  2. 데이터의 역할을 나누고 누수가 없는지 확인합니다.
  3. 전처리와 학습 설정을 함께 기록합니다.
  4. 평균 지표뿐 아니라 실제 오류 유형을 확인합니다.
  5. 조명·제품·설비가 달라졌을 때 결과가 유지되는지 검증합니다.
  6. 적용·재검사·Rollback 기준을 정합니다.

다음 단계에서는 주제별 Notebook, 데이터 출처, 설정파일과 평가 결과를 같은 단위로 묶어 README의 점검 순서를 실제 실행 기록과 연결할 계획입니다.

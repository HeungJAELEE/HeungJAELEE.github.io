    TECHNICAL CASE STUDY

    용접 Vision AI 판정기준

    공개 데이터와 현장성 Sample을 분리하고 Recall·Precision·F1 및 임계값을 비교해 용접 불량의 미검출 위험을 우선한 Vision AI 교육 PoC

    2026. 7. 9. · 9 · 마지막 검토 2026. 7. 31.

    • Vision AI
    • Recall
    • Threshold

    30초 요약

    현장에서는 전체 정확도보다 불량을 놓쳤을 때의 비용이 큽니다. 그래서 데이터 출처를 나누고 Recall과 임계값을 먼저 보는 방식으로 PoC를 구성했습니다.

    검출 기준 검토 단계
    기간·기준
    교육 팀 프로젝트 · 공개 정리 2026.07
    프로젝트 형태
    제조 DX PoC · 생산 적용 전

    해결하려던 문제

    공개 데이터에서 잘 보이는 모델이 조명·각도·표면 상태가 다른 현장 이미지에서도 같은 판단을 할 것이라고 가정할 수 없었습니다.

    내가 맡은 범위

    • 공개 학습 데이터와 현장 실습 이미지를 역할별로 나누고, 미검출 위험을 기준으로 평가 지표와 임계값 검토 순서를 정했습니다.

    확인된 결과·현재 단계

    • 확인된 산출물 · 개인 역할 공개·현장 데이터 분리와 Recall·임계값 중심 평가 흐름
    • 현재 단계 · 팀 결과 교육 PoC 완료·생산 적용 전

    팀 경계

    교육 팀 PoC이며 모델 성능을 실제 양산 품질 성과로 귀속하지 않습니다.

    공개 범위: 현장 이미지와 회사 품질 기준은 공개하지 않고, 데이터 분리와 판단 절차만 설명합니다.

    데이터 수집부터 생산 적용까지 필요한 절차를 공개 가능한 PoC 범위로 일반화했습니다.

    처음 1분에 볼 내용

    이 사례는 용접 사진을 보고 정상과 불량 후보를 나누는 교육 팀 Vision AI PoC입니다. 모델이 사람 대신 출하를 결정한 시스템이 아니라 검사원이 먼저 볼 대상을 좁힐 수 있는지 평가한 작업입니다.

    구분확인할 내용
    해결하려던 문제정상 이미지가 많은 상황에서 작은 용접 결함을 놓치는 위험
    팀이 만든 것공개·현장 이미지 구분, 모델 단계별 실험, 두 번째 테스트와 결과 보고서
    내가 맡은 것데이터 역할 구분, 평가지표와 비교 기준 정리, Recall 우선 임계값 검토
    현재 단계교육 PoC 평가 완료, 생산 적용 전
    공개 화면실행 가능한 검사 화면이나 보고서 캡처는 없으며, 공개 가능한 판단 흐름만 설명

    페이지 상단의 30초 요약은 결과와 역할 경계를 먼저 보여 줍니다. 본문은 왜 Recall을 우선했는지, 데이터가 어떻게 흘렀는지, 팀 결과와 개인 기여를 어떻게 나눴는지 설명합니다. 아래 설계·검증 기록은 요구사항과 작업 상태를 펼쳐 보는 부록입니다.

    용접 결함 검출이 왜 중요한가

    용접부의 미세 크랙이나 핀홀을 놓치면 불량품이 다음 공정으로 넘어갈 수 있습니다. 반대로 정상 제품을 불량 후보로 잡으면 재검사 시간이 늘어납니다. 둘 다 비용이지만 이 프로젝트에서는 불량을 정상으로 통과시키는 실수를 먼저 줄이는 쪽에 무게를 뒀습니다.

    정상 이미지가 훨씬 많다면 모델이 대부분을 정상이라고 답해도 Accuracy는 높게 나올 수 있습니다. 그래서 “전체 사진 중 몇 장을 맞혔는가”만 보지 않고 실제 불량 중 몇 장을 잡았는지를 나타내는 Recall과 재검사 부담을 함께 보여 주는 Precision을 같이 봤습니다.

    배터리 셀 조립 현장에서 초음파·레이저 용접 조건과 불량 원인을 다뤄 본 경험도 이 판단의 배경이 됐습니다. 다만 그 현장 경험과 교육 프로젝트의 모델 성능은 별개입니다. 이 사례의 목표는 자동 전수검사를 완성하는 것이 아니라 제한된 자료에서 검사 보조 가능성을 확인하는 데 있었습니다.

    이 그림은 공개 가능한 범위에서 정리한 PoC 흐름입니다. 카메라가 생산 라인에서 영상을 보내고 모델이 실시간으로 판정하는 운영 시스템을 구현했다는 뜻은 아닙니다.

    구성요소맡은 일이 단계에서 하지 않은 일
    공개 데이터여러 결함 특징을 학습하는 기반 제공현장 성능을 대신 증명
    현장 이미지제한된 촬영 조건에서 모델 반응 확인모든 설비·제품 조건 대표
    팀 모델 실험DenseNet 계열부터 ResNet+DeiT까지 후보 단계 비교모델 이름만으로 운영 모델 결정
    임계값 평가불량 확률을 어느 지점에서 불량 후보로 볼지 비교한 번 정한 값으로 모든 조건 고정
    검사 보조 기준위험 후보를 사람의 재검사로 연결사람 없이 자동 출하 판정
    오류 검토FP·FN을 다음 데이터와 촬영 조건 점검으로 연결오류 원인을 모델 문제 하나로 단정

    데이터·모델·평가가 이어지는 과정

    1. 데이터의 역할을 먼저 나눔

    • AI-Hub 공개 용접 이미지 약 60,000장은 다양한 결함 특징을 학습하는 기반으로 사용했습니다.
    • 현장 실습 이미지 198장은 제한된 촬영 조건에서 모델 반응을 확인하는 별도 자료로 두었습니다.

    두 자료를 “총 60,198장 학습 데이터”로 합쳐 표현하지 않았습니다. 촬영 장비, 조명, 표면 반사와 제품 조건이 다르기 때문입니다. 공개 데이터에서 잘 맞는 모델이 현장에서도 같은 판단을 한다고 가정하지 않았습니다.

    2. 라벨과 분할을 확인

    공개 데이터의 라벨과 현장에서 말하는 불량의 의미가 맞는지 확인하고 동일 이미지가 학습과 평가 양쪽에 섞이지 않게 분리했습니다. 이 단계가 흔들리면 높은 지표도 실제로는 같은 사진을 다시 본 결과일 수 있습니다.

    3. 팀의 모델 단계를 같은 기준으로 비교

    팀 실험 기록은 DenseNet 계열의 초기 단계, 2-model 조합, ResNet+DeiT 앙상블로 이어졌습니다. 모델마다 다른 기준을 적용하지 않고 F1, Recall, Precision과 같은 평가 틀로 비교했습니다. 이 모델 개발 전체를 개인 작업으로 설명하지는 않습니다.

    4. 확률값을 검사 기준으로 바꿈

    모델은 각 이미지가 불량일 가능성을 확률값으로 냅니다. 어느 값부터 불량 후보로 볼지 정하는 경계가 임계값입니다. 임계값을 낮추면 불량을 더 많이 잡을 수 있지만 정상까지 불량 후보로 보내는 오검이 늘 수 있습니다.

    용어면접에서 설명하는 뜻이 프로젝트에서 본 이유
    Recall실제 불량 중 모델이 잡아낸 비율놓친 불량을 우선 줄이기 위해
    Precision불량 후보 중 실제 불량의 비율재검사 부담을 함께 보기 위해
    F1Recall과 Precision의 균형한 지표만 좋아진 선택을 피하기 위해
    False Negative불량인데 정상으로 본 경우가장 먼저 줄이려 한 오류
    False Positive정상인데 불량 후보로 본 경우사람의 재검사 비용과 연결되는 오류

    5. 수치 뒤의 이미지를 다시 확인

    두 번째 테스트에서는 정상과 불량 예측이 섞이는 구간을 확인했습니다. Recall 100%가 유지되는 임계값 구간을 먼저 찾은 뒤 Precision과 F1을 비교했습니다. 이어 FP와 FN 이미지를 다시 살펴 데이터·라벨·촬영 조건 중 무엇을 다음에 점검할지 정리했습니다.

    팀 결과와 내가 맡은 일

    범위귀속
    공개·현장 데이터 준비, 모델 학습과 후보 발전, 두 번째 테스트, PoC 보고서교육 팀 결과
    공개 데이터와 현장 이미지의 용도 구분내 역할
    F1·Recall·Precision 중심의 공통 비교 기준 정리내 역할
    미검출을 우선 줄이는 임계값 구간 검토와 FP·FN 해석내 역할
    모든 모델을 혼자 개발했다는 주장, 실시간 검사 화면, 양산 배포내 성과로 주장하지 않음

    면접에서는 전체 흐름을 이해하고 있다는 점과 직접 맡은 범위를 함께 설명합니다. 팀이 만든 모델과 보고서 전체를 개인 성과로 돌리지 않고 제가 기여한 평가 설계와 운영 해석을 구체적으로 말합니다.

    마주친 문제와 선택

    문제선택이유
    정상 이미지가 많아 Accuracy가 실제 미검출 위험을 가릴 수 있음Recall을 1차 지표로 두고 Precision·F1을 함께 확인불량 통과와 재검사 비용을 따로 보기 위해
    공개 데이터와 현장 이미지의 촬영 조건이 다름두 자료의 목적을 분리공개 데이터 성능을 현장 성능처럼 말하지 않기 위해
    같은 모델도 임계값에 따라 결과가 달라짐Recall 100% 구간 안에서 Precision과 F1 비교모델 선택과 검사 정책을 함께 판단하기 위해
    수치만 보면 오류 원인을 알기 어려움Confusion Matrix와 FP·FN 이미지 재검토다음 데이터·라벨·촬영 조건 점검으로 연결하기 위해
    현장 자료와 보고서를 그대로 공개할 수 없음검증 가능한 텍스트 구조만 공개가짜 화면이나 출처가 불분명한 이미지를 만들지 않기 위해

    확인된 결과와 기대할 수 있는 이점

    선택한 평가셋과 임계값에서 보고서에 기록된 값은 **F1 93.10%, Recall 100%, Precision 87.07%**입니다. Recall 100%는 그 평가셋에 들어 있던 불량을 놓치지 않았다는 뜻입니다. 미래의 모든 불량이나 다른 설비 조건까지 보장한다는 뜻은 아닙니다. Precision 87.07%는 불량 후보 중 일부가 정상일 수 있어 재검사가 필요하다는 점을 보여 줍니다.

    이 PoC에서 확인한 이점은 모델 성능 숫자 하나가 아니라 품질 위험을 검사 기준으로 바꾸는 방법입니다.

    • 놓치면 비용이 큰 후보를 검사원이 먼저 볼 수 있는 우선순위
    • 모델 후보를 같은 기준으로 비교하는 평가 흐름
    • 미검출과 오검을 각각 품질 위험과 재검사 부담으로 설명하는 공통 언어
    • 반복되는 오류 이미지를 다음 데이터와 촬영 조건 개선으로 돌리는 순서

    실제 불량 유출 감소나 검사 시간 절감은 확인된 성과가 아닙니다. 그런 효과는 양산 전후를 같은 조건으로 측정한 뒤 판단해야 합니다.

    현재 한계와 다음 검증

    현재 단계는 제한된 데이터로 검사 보조 가능성을 확인한 PoC입니다. 현장 이미지 198장만으로 설비, 소재, 조명과 제품 형상의 변화를 모두 검증했다고 볼 수 없습니다. 실시간 카메라 입력, 라인 속도에서의 추론, 누락 프레임, 장기간 성능 변화와 작업자 재검사 절차도 검증하지 않았습니다.

    현장 적용 전에는 다음 검증이 필요합니다.

    1. 제품 또는 Lot 기준의 독립 평가셋을 마련합니다.
    2. 불량 유형별 표본 수와 라벨 기준을 품질 담당자와 다시 확인합니다.
    3. 카메라 위치, 조도, 초점과 촬영 시점을 표준화합니다.
    4. 라인 속도에서 추론 지연과 누락 프레임을 시험합니다.
    5. 모델 버전, 임계값, 이미지, 설비 조건과 재검사 결과를 함께 추적합니다.
    6. 변경 승인과 이전 모델·임계값으로 되돌리는 절차를 둡니다.

    공개 소스와 화면의 경계

    이 사례에는 현재 검증 가능한 전용 모델 코드 저장소, 실행 가능한 검사 화면이나 보기 전용 보고서가 없습니다. 현장 이미지와 회사 품질 기준도 공개하지 않습니다. 그래서 다른 프로젝트의 화면이나 제3자 용접 이미지를 대신 붙이지 않았습니다.

    구성 이유와 작업 흐름

    정확도 경쟁이 아니라 미검출 위험을 줄이는 품질검사 의사결정 문제로 정의하고, 데이터·모델·임계값 Task를 같은 평가 기준으로 연결했습니다.

    Problem

    미세 용접 결함과 정상 표면 특징이 겹치고 클래스 불균형이 있어 accuracy만으로는 불량 통과 위험을 설명할 수 없습니다.

    Goal

    공개 데이터와 현장 데이터를 분리하고 동일 지표로 모델 단계를 비교한 뒤, Recall 우선 임계값과 재검사 정책을 설계하는 것입니다.

    Success

    평가셋에서 F1·Recall·Precision을 함께 제시하고, 운영 임계값의 이유·오검출 처리·생산 적용 한계를 설명할 수 있으면 성공입니다.

    범위와 경계

    포함 범위

    • AI-Hub 약 60,000장과 현장 198장의 목적별 분리
    • DenseNet 기준선, 2모델 조합, ResNet+DeiT 앙상블 비교
    • 두 번째 테스트와 임계값 조정을 통한 미검출 우선 평가

    제외·미검증 범위

    • 전용 공개 소스 저장소가 있다는 주장
    • 모든 용접 공정·카메라 조건에 대한 생산 일반화
    • 사람의 재검사 없이 자동 판정만으로 출하하는 운영

    구현·검증 기준

    해야 할 일

    • 데이터 출처와 학습·검증·현장 확인 목적을 분리한다.
    • 모든 모델 단계를 F1, Recall, Precision과 동일한 분할 기준으로 비교한다.
    • 임계값별 false negative와 false positive를 기록하고 재검사 흐름을 둔다.

    품질·운영 기준

    • 결함 미검출 비용을 정상품 재검사 비용보다 우선한다.
    • 평가셋 수치와 생산 성능을 구분하고 데이터 누수를 점검한다.
    • 조명·재질·카메라 변화에 따른 drift를 별도 검증 대상으로 둔다.

    왜 이렇게 구성했나

    1. Recall을 1차 운영 지표로 선택

      용접 불량을 정상으로 통과시키는 위험이 정상품을 재검사하는 비용보다 크기 때문입니다.

    2. 현장 198장을 별도 검증 관점으로 유지

      대규모 공개 데이터와 적은 현장 데이터를 섞어 과도한 일반화 주장을 하지 않기 위해서입니다.

    3. 모델보다 임계값·검사 정책까지 함께 비교

      같은 모델도 운영 임계값에 따라 미검출과 오검출 비용이 달라지기 때문입니다.

    모델 개발과 평가, 운영 준비를 분리해 현재 완료 수준을 보여 줍니다.

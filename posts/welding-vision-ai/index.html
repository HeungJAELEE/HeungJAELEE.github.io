팀이 해결하려던 제조 품질문제

용접 외관검사에서 중요한 것은 전체 Accuracy가 아니라 실제 불량을 정상으로 통과시키는 미검출을 줄이는 것이었습니다. 그러나 판정기준을 지나치게 낮추면 정상품 재검사가 늘어 검사공수와 Cycle Time에 부담이 생깁니다.

팀의 목표는 AI가 최종 합격·불합격을 대신 결정하는 것이 아니었습니다. 용접 사진에서 불량후보를 먼저 찾고, 어떤 결과를 작업자가 다시 확인해야 하는지까지 연결하는 검사보조 흐름을 만드는 것이었습니다.

팀 전체 시스템과 역할

flowchart LR A["이미지·라벨 준비\nTEAM"] --> B["전처리·후보모델 학습\nSHARED·MY CORE"] --> C["점수·Threshold\nMY CORE"] C --> D["불량후보 표시\nTEAM"] --> E["작업자 수동확인\nSHARED"] --> F["오류 재검토·다음 학습"] F -.-> G["독립평가·Shadow Test\nFUTURE"]
  • TEAM: 이미지 입력, 결과표시와 수동확인까지의 시연흐름
  • MY CORE: 전체 기획, 모델링·평가와 미검출 우선 판정기준
  • SHARED: 데이터 정리, 오류이미지 검토와 보고서 공동 작성
  • FUTURE: 독립 평가셋, 고정 촬영조건과 생산 Shadow Test

발표는 팀장이 담당했고 보고서는 팀 공동으로 작성했습니다.

왜 Accuracy보다 미검출을 먼저 봤는가

오류제조현장 영향판정에서의 처리
미검출실제 불량이 후공정이나 고객으로 넘어갈 수 있음Recall과 False Negative 이미지를 먼저 확인
오검정상품 재검사와 검사공수 증가Precision과 재검사량을 함께 비교
낮은 신뢰도모델점수만으로 품질판정 곤란재촬영 또는 작업자 확인으로 전환
모델·작업자 불일치자동판정 오사용 가능원본사진과 오류유형을 다시 검토

Threshold는 가장 높은 점수를 만드는 값이 아니라, 미검출 위험과 재검사 부담 사이에서 정해야 한다고 판단했습니다.

촬영조건이 달라졌을 때 다시 본 것

공개 용접자료는 후보모델 학습과 비교에 사용했습니다. 별도 촬영 Sample은 조명·각도·표면반사와 촬영품질이 바뀌면 오류유형이 어떻게 달라지는지 확인하는 자료로 사용했습니다.

  1. 같은 평가항목으로 후보모델을 비교했습니다.
  2. 미검출·오검 이미지를 직접 확인했습니다.
  3. 촬영조건이 달라진 Sample에서 오류가 증가하는 유형을 분리했습니다.
  4. 모델점수를 그대로 현장성능으로 일반화하지 않고 수동확인 Gate를 유지했습니다.

내가 직접 맡은 모델링·평가 판단

  • 제조검사에서 더 위험한 오류를 먼저 정의했습니다.
  • 후보모델을 같은 지표와 오류이미지로 비교했습니다.
  • Threshold 변경이 미검출과 오검에 미치는 영향을 함께 봤습니다.
  • 낮은 Confidence와 작업자 판단 불일치를 자동 합격으로 보내지 않도록 했습니다.
  • 결과를 모델성능 자랑이 아니라 검사보조 흐름과 적용조건으로 정리했습니다.

팀 결과와 향후 적용

5인 팀은 공개 학습자료와 촬영조건이 다른 Sample의 오류변화를 확인하고, 미검출과 재검사 부담을 함께 보는 교육 PoC를 마쳤습니다. 향후에는 제품·Lot·촬영시점 단위의 독립 평가셋, 고정 카메라조건, Line Speed 추론시간과 Shadow Test를 연결해 실제 검사공정 적용 가능성을 단계적으로 검증할 수 있습니다.

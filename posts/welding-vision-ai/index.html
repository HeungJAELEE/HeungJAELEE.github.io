프로젝트 개요

이 프로젝트는 공개 용접영상에서 점수가 높은 모델을 만드는 데서 끝내지 않고, 직접 촬영한 용접실기품에서도 같은 판단이 가능한지 확인하기 위해 진행했습니다.

AI-Hub 용접영상으로 학습한 초기 ResNet 모델을 실기품 사진에 적용했을 때 Recall이 15.84%까지 떨어졌습니다. 직접 촬영품에는 공개자료보다 그을음, 스패터, 산화표면, 반사광, 촬영각도와 배경 노이즈가 많이 포함돼 있었습니다.

팀은 모델을 바로 교체하지 않았습니다. 먼저 FN과 FP 이미지를 확인하고, 촬영조건을 반영한 데이터 증강, 후보 아키텍처 비교, 2-Model 앙상블, Temperature Scaling과 Threshold 조정을 차례로 진행했습니다. 저는 이 실험순서와 평가기준을 정하고, 후보모델 비교, 오류이미지 분석, 저해상도 좌표 스케일링과 Threshold 판단을 담당했습니다.

검사문제와 팀 완료조건

검사문제

이 프로젝트에서 모델이 해결해야 할 문제는 단순한 이미지 분류가 아니었습니다.

  1. 공개자료에서 학습한 특징이 직접 촬영품에도 적용되는가
  2. 실제 불량을 양품으로 놓치는 FN을 얼마나 줄일 수 있는가
  3. 그을음·반사광·스패터를 불량으로 오인하는 FP를 얼마나 줄일 수 있는가
  4. 모델점수를 작업자가 확인할 수 있는 판정조건으로 바꿀 수 있는가
  5. 스마트폰 촬영부터 결과표시까지 한 흐름으로 동작하는가

핵심 모델의 정량평가는 양품·불량 2-class를 기준으로 진행했습니다. PWA에 표시된 A·C·D 등급은 결과표시 단계의 항목입니다. 공개된 보고서와 코드에서 세부 등급 매핑 규칙을 확정할 수 없어, 이 글에서는 2-class 모델구조와 실제 화면에 표시된 항목을 분리해서 설명합니다.

왜 이 순서로 평가했는가

평가 단계확인하려던 질문다음 단계로 넘어간 기준
Data Set vs Field공개자료 점수가 실제 촬영품에서도 유지되는가실기품 Recall·FPR을 별도로 측정
증강 전후성능저하의 주원인이 데이터 표현 부족인가같은 모델·평가셋에서 전후 비교
후보 아키텍처단일 CNN의 오류패턴을 다른 구조가 보완하는가Recall·FPR·오류이미지 동시 비교
2-Model vs 5-Model더 많은 모델이 추론비용만큼 이득을 주는가F1 차이와 추론부담 비교
Temperature ScalingConfidence가 Threshold 판단에 사용할 만큼 보정됐는가확률출력을 별도로 보정
Threshold Sweep불량 미검과 양품 재확인 중 무엇을 우선할 것인가FN·FP·Recall·FPR을 함께 비교
PWA 통합Notebook 결과가 실제 사용흐름으로 이어지는가촬영–API–결과표시 확인

이 순서로 평가했기 때문에, 최종 모델은 여러 모델을 무작정 결합한 결과가 아닙니다. 데이터 문제를 먼저 줄인 뒤, 남은 오류를 보완할 모델조합과 판정조건을 선택했습니다.

나의 역할 — AI 모델링·평가기준 설계

저는 공개 데이터의 검증점수만으로 모델을 선택하지 않고, 직접 촬영한 실기품에서 발생한 FN과 FP를 먼저 확인하도록 전체 실험순서를 정했습니다.

후보모델은 Accuracy 한 값이 아니라 Recall, FPR, F1과 실제 오류이미지를 같은 기준으로 비교했습니다. 데이터 증강의 효과와 모델구조의 효과가 섞이지 않도록 ResNet Baseline, 증강 후 ResNet, ResNet+DeiT 순서로 결과를 나눠 확인했습니다.

저해상도 입력에서 모델좌표가 원본사진과 어긋나는 문제는 원본 크기와 모델 입력크기의 비율을 이용해 다시 환산했습니다. Threshold는 F1이 가장 높은 지점과 FN이 0건이 되는 지점을 따로 비교하고, 시연에서는 불량 미검출을 줄이는 조건을 사용했습니다.

AI-Hub 원천자료와 직접 촬영품

보고서의 원천 데이터 표에는 언더컷과 오버랩을 합쳐 약 60,000장이 제시돼 있습니다. 직접 촬영한 용접실기품은 실험단계에 따라 약 155~198장, 즉 약 200장 규모로 사용했습니다.

FN·FP 이미지를 어떻게 평가했는가

  1. 원본이미지와 정답 Label을 기준으로 예측결과를 대조했습니다.
  2. 실제 불량을 정상으로 판단한 FN 이미지를 먼저 확인했습니다.
  3. 양품을 불량으로 판단한 FP는 그을음·스패터·반사광·촬영각도·ROI 이탈로 나눴습니다.
  4. 같은 평가셋에서 데이터·모델·Threshold만 바꿔 비교했습니다.
  5. Confidence가 낮거나 경계가 겹치는 경우는 재촬영 또는 작업자 확인 대상으로 분리했습니다.

촬영조건을 반영한 데이터 증강

촬영구도와 조명, 표면노이즈를 따로 나눠 증강했습니다. Crop·좌우반전·회전은 촬영거리와 부품방향 차이를, 밝기·대비·Lens Flare는 조명과 금속반사를, Gaussian Noise와 JPEG 열화는 모바일 촬영·전송조건을 반영했습니다.

보고서에는 학습 안정화와 확률보정을 위해 MixUp, Label Smoothing, SWA, 5-Seed Model Soup과 Temperature Scaling도 기록돼 있습니다.

새 모델을 추가하기 전에 Recall은 15.84%에서 85.15%로 개선됐습니다. 이 결과를 통해 첫 번째 원인이 단순한 모델용량 부족이 아니라, 실제 촬영조건이 학습자료에 충분히 포함되지 않은 문제라고 판단했습니다.

후보 아키텍처를 비교한 이유

증강 후에도 Recall은 85.15%였습니다. 남은 불량을 더 잡기 위해 ResNet, EfficientNet, RegNet, ConvNeXt, Swin과 DeiT 계열을 같은 평가기준으로 비교했습니다.

발표자료에는 결함유형별 전용모델과 3-Model 구조가 함께 제시돼 있지만, 최종 정량평가와 APP 시연에서 확인되는 모델은 ResNet-50 + DeiT-Small 2-Model 앙상블입니다. 따라서 이 글에서는 초기 아이디어와 최종 모델을 섞지 않습니다.

ResNet-50 + DeiT-Small을 선택한 이유

이번 후보평가에서 ResNet-50과 DeiT-Small은 서로 다른 오류이미지에 반응했습니다.

  • ResNet-50: 인접 Pixel과 국소 질감에 강해 용접 비드의 작은 형상차이를 안정적으로 확인했습니다.
  • DeiT-Small: 이미지 전체 Patch 관계를 확인해 비드 전체 흐름과 넓게 분포한 이상형상에 민감하게 반응했습니다.

보고서에는 DeiT-Small의 높은 TPR과 ResNet-50의 낮은 FPR을 근거로 두 모델을 선택했다고 기록돼 있습니다. 두 모델의 불량확률을 동일 비율로 평균해, 한 모델의 민감한 판정과 다른 모델의 보수적인 판정을 함께 사용했습니다.

Threshold를 검사조건으로 바꾼 방법

Threshold 0.49에서는 F1이 가장 높았지만 제한 평가셋에서 실제 불량 4건을 놓쳤습니다. 0.40에서는 FN이 0건이었지만 양품 재확인 대상이 15건으로 늘었습니다.

시연에서는 제한 평가셋에서 불량 미검출이 없었던 0.40을 사용했습니다. 이는 제한 평가셋에서 FN 0건을 확인한 조건이며, 실제 생산라인의 불량유출 0건을 입증한 결과는 아닙니다.

저해상도 좌표를 원본사진에 맞춘 방법

모델은 Resize된 입력이미지를 기준으로 좌표를 출력하지만, 작업자는 원본사진에서 결함위치를 확인해야 합니다. 모델좌표를 그대로 그리면 입력해상도와 원본해상도의 차이만큼 ROI가 어긋납니다.

flowchart LR A["스마트폰 원본 이미지
원본 Width · Height"] --> B["모델 입력크기로 Resize"] B --> C["모델 좌표 출력
x1 · y1 · x2 · y2"] C --> D["가로·세로 비율 계산"] D --> E["원본 기준 좌표로 환산"] E --> F["원본사진 위에
ROI·결함위치 표시"]
scale_x = 원본 가로 / 모델 입력 가로
scale_y = 원본 세로 / 모델 입력 세로

원본 x 좌표 = 모델 x 좌표 × scale_x
원본 y 좌표 = 모델 y 좌표 × scale_y

이 로직을 적용해 저해상도 추론결과를 원본사진의 같은 위치에 표시하도록 했습니다.

APP은 FastAPI의 /predict와 PWA를 연결했습니다.

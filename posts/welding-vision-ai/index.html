AI Vision 기반 용접 불량 검출 모델링

30초 요약

현장에서는 전체 정확도보다 불량을 놓쳤을 때의 비용이 큽니다. 그래서 데이터 출처를 나누고 Recall과 임계값을 먼저 보는 방식으로 PoC를 구성했습니다.

해결하려던 문제

공개 데이터에서 잘 보이는 모델이 조명·각도·표면 상태가 다른 현장 이미지에서도 같은 판단을 할 것이라고 가정할 수 없었습니다.

내가 맡은 범위

  • 공개 학습 데이터와 현장 실습 이미지를 역할별로 나누고, 미검출 위험을 기준으로 평가 지표와 임계값 검토 순서를 정했습니다.

확인된 결과·현재 단계

  • 확인된 산출물 · 개인 역할 공개·현장 데이터 분리와 Recall·임계값 중심 평가 흐름
  • 현재 단계 · 팀 결과 교육 PoC 완료·생산 적용 전

팀 경계

교육 팀 PoC이며 모델 성능을 실제 양산 품질 성과로 귀속하지 않습니다.

공개 범위: 현장 이미지와 회사 품질 기준은 공개하지 않고, 데이터 분리와 판단 절차만 설명합니다.

데이터 수집부터 생산 적용까지 필요한 절차를 공개 가능한 PoC 범위로 일반화했습니다.

왜 이 의사결정이 중요했는가

용접부의 미세 크랙이나 핀홀을 놓치면 불량품이 다음 공정으로 넘어갈 수 있습니다. 반대로 정상 제품을 불량 후보로 잡으면 재검사 부담이 생깁니다. 정상 이미지가 많은 데이터에서는 Accuracy가 높아도 실제 불량을 놓칠 수 있으므로, 현장 판단에는 “몇 개를 맞혔는가”보다 “놓치면 안 되는 불량을 잡았는가”가 더 중요했습니다.

배터리 셀 조립 현장에서 초음파·레이저 용접 조건과 불량 원인을 다뤄 본 경험을 바탕으로, 이 프로젝트의 판정 기준도 미검출 위험에서 출발했습니다. 목표는 자동 전수검사를 완성했다고 말하는 것이 아니라, 검사원이 먼저 확인할 불량 후보를 선별하는 PoC의 가능성을 검토하는 것이었습니다.

왜 디지털 방식이 필요했는가

표면 반사와 용접 자국은 실제 결함과 비슷하게 보일 수 있고, 결함 형태도 일정하지 않습니다. 사람이 모든 경계 규칙을 미리 작성하기 어려워 이미지 특징을 학습하는 비전 모델을 사용했습니다. 다만 공개 이미지에서 얻은 결과를 현장 성능으로 곧바로 해석하지 않도록 데이터의 역할을 분리했습니다.

  • AI-Hub 공개 용접 이미지 약 60,000장: 다양한 결함 특징을 학습하는 기반
  • 현장 실측 이미지 198장: 제한된 촬영 조건에서 모델 반응을 확인하는 별도 자료

두 자료를 “총 60,198장 학습 데이터”로 합쳐 표현하지 않았습니다. 촬영 장비, 조명, 표면 반사와 제품 조건이 다르기 때문에 공개 데이터와 현장 데이터는 서로 다른 질문에 답합니다.

실제로 맡은 역할

팀 프로젝트에서 F1, Recall, false-positive behavior를 포함한 평가 기준을 정리하고, 모델 후보를 같은 기준으로 비교하며, 판정 임계값을 해석하는 역할을 맡았습니다. 특히 불량을 정상으로 통과시키는 False Negative를 우선 줄이되, 늘어나는 오검은 재검사로 관리할 수 있는지 함께 판단했습니다.

모델 이름 자체를 성과로 내세우기보다 DenseNet 계열의 초기 단계와 2-model 조합, ResNet+DeiT 앙상블로 이어진 팀의 실험 기록을 동일한 평가 틀에서 검토했습니다. 최종 의사결정은 “가장 복잡한 모델”이 아니라 미검출 위험과 오검 비용을 설명할 수 있는 임계값이었습니다.

데이터 흐름

공개 이미지 학습 기반 → 모델 후보 비교 → 현장 이미지 반응 확인 → 확률값별 임계값 탐색 → Confusion Matrix와 오류 이미지 검토 → 검사 보조 기준 제안

공개 이미지와 현장 이미지를 분리한 상태에서 각 예측의 정답과 불량 확률을 남겼습니다. 이렇게 해야 모델을 다시 학습하지 않고도 임계값에 따른 Precision, Recall, F1 변화를 비교할 수 있습니다.

구현 순서

  1. 공개 데이터의 라벨과 현장 판정 기준이 같은 의미인지 먼저 확인했습니다.
  2. 공개 데이터와 현장 데이터의 용도를 분리하고, 동일 이미지가 학습과 평가에 섞이지 않도록 관리했습니다.
  3. 팀이 기록한 모델 단계를 같은 평가 지표로 비교했습니다.
  4. 2차 테스트에서 정상과 불량 예측이 섞이는 구간을 확인했습니다.
  5. Recall 100%가 유지되는 임계값 구간을 먼저 찾고, 그 안에서 Precision과 F1을 함께 검토했습니다.
  6. FP와 FN 이미지를 다시 살펴 오검·미검출 원인을 데이터와 촬영 조건의 다음 점검 항목으로 돌렸습니다.

확인된 결과와 현재 단계

선택한 평가셋과 임계값에서 보고서에 기록된 값은 **F1 93.10%, Recall 100%, Precision 87.07%**입니다. Recall 100%는 이 평가셋에 포함된 불량을 놓치지 않았다는 뜻이며, 미래의 모든 불량이나 다른 설비 조건까지 보장한다는 뜻은 아닙니다. Precision 87.07%는 불량 후보 중 일부가 정상일 수 있어 재검사가 필요하다는 점을 보여 줍니다.

현재 단계는 제한된 데이터로 검사 보조 가능성을 확인한 PoC입니다. 현장 이미지 198장만으로 설비, 소재, 조명과 제품 형상의 변화를 모두 검증했다고 볼 수 없으며, 양산 설비에 배포 완료한 시스템도 아닙니다.

배포 조건과 회사에 줄 수 있는 가치

현장 적용 전에는 제품 또는 Lot 기준의 독립 분할, 불량 유형별 표본 확인, 카메라 위치·조도·초점 표준화, 라인 속도에서의 추론 지연과 누락 프레임 시험이 필요합니다. 모델 버전과 임계값, 검사 이미지, 설비 조건, 작업자 재검사 결과를 함께 남기고 변경 승인과 되돌리기 절차도 마련해야 합니다.

이 조건이 갖춰지면 모델은 검사원을 대체하기보다 놓치면 비용이 큰 후보를 먼저 보여 주고, 반복되는 오류 이미지를 다음 데이터 개선으로 연결할 수 있습니다. 회사 입장에서는 품질 위험의 우선순위를 지표와 재검사 기준으로 공유할 수 있다는 점이 가치입니다. 다만 실제 불량 유출 감소나 검사 시간 절감은 양산 전후를 같은 조건으로 측정한 뒤에만 성과로 말할 수 있습니다.

Problem

미세 용접 결함과 정상 표면 특징이 겹치고 클래스 불균형이 있어 accuracy만으로는 불량 통과 위험을 설명할 수 없습니다.

Goal

공개 데이터와 현장 데이터를 분리하고 동일 지표로 모델 단계를 비교한 뒤, Recall 우선 임계값과 재검사 정책을 설계하는 것입니다.

Success

평가셋에서 F1·Recall·Precision을 함께 제시하고, 운영 임계값의 이유·오검출 처리·생산 적용 한계를 설명할 수 있으면 성공입니다.

범위와 경계

포함 범위

  • AI-Hub 약 60,000장과 현장 198장의 목적별 분리
  • DenseNet 기준선, 2모델 조합, ResNet+DeiT 앙상블 비교
  • 두 번째 테스트와 임계값 조정을 통한 미검출 우선 평가

제외·미검증 범위

  • 전용 공개 소스 저장소가 있다는 주장
  • 모든 용접 공정·카메라 조건에 대한 생산 일반화
  • 사람의 재검사 없이 자동 판정만으로 출하하는 운영

구현·검증 기준

해야 할 일

  • 데이터 출처와 학습·검증·현장 확인 목적을 분리한다.
  • 모든 모델 단계를 F1, Recall, Precision과 동일한 분할 기준으로 비교한다.
  • 임계값별 false negative와 false positive를 기록하고 재검사 흐름을 둔다.

품질·운영 기준

  • 결함 미검출 비용을 정상품 재검사 비용보다 우선한다.
  • 평가셋 수치와 생산 성능을 구분하고 데이터 누수를 점검한다.
  • 조명·재질·카메라 변화에 따른 drift를 별도 검증 대상으로 둔다.

왜 이렇게 구성했나

  1. Recall을 1차 운영 지표로 선택

    용접 불량을 정상으로 통과시키는 위험이 정상품을 재검사하는 비용보다 크기 때문입니다.

  2. 현장 198장을 별도 검증 관점으로 유지

    대규모 공개 데이터와 적은 현장 데이터를 섞어 과도한 일반화 주장을 하지 않기 위해서입니다.

  3. 모델보다 임계값·검사 정책까지 함께 비교

    같은 모델도 운영 임계값에 따라 미검출과 오검출 비용이 달라지기 때문입니다.

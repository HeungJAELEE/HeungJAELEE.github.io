과제 목적

이 과제는 기존에 공개된 선박·해양플랜트 용접 영상을 학습자료로 활용하고, 설비보전기사 용접실기품을 직접 촬영해 실제 제품 사진에서 모델을 다시 평가하는 것에서 시작했습니다. 공개 데이터에서 높은 점수가 나오는 모델을 고르는 데 그치지 않고, 촬영환경이 달라졌을 때 발생하는 오류를 분석해 최적의 AI Modeling을 찾고 스마트폰 APP 형태의 검사 시연으로 연결하는 것이 목표였습니다.

팀은 용접사진을 입력하면 양품·불량과 결함등급을 표시하는 교육용 검사보조 시스템을 설계했습니다. 품질기준 조사, 데이터 준비, 모델 학습·평가, Threshold 설정과 PWA 시연까지 하나의 흐름으로 구성했습니다.

팀 전체 시스템과 역할

flowchart LR A["AI-Hub 용접영상\n언더컷·오버랩"] --> C["전처리·증강\nTEAM"] B["용접실기품 직접 촬영\n약 200장 규모"] --> C C --> D["후보모델 비교\nResNet·Swin·DeiT·ConvNeXt 등"] D --> E["ResNet50 + DeiT-Small\n확률 평균·Temperature Scaling"] E --> F["Threshold·FN/FP 평가\nMY CORE"] F --> G["FastAPI /predict\nJSON 응답"] G --> H["PWA 검사화면\n등급·결함·Confidence"]
  • TEAM: 데이터 정리, 모델실험, APP 화면과 통합시연
  • MY CORE: 전체 프로젝트 기획, 후보모델 비교·평가기준, 저해상도 입력의 좌표 스케일링과 Threshold 판단
  • SHARED: 오류이미지 검토와 보고서 공동 작성
  • PRESENTATION: 팀장이 최종 발표 담당

데이터 구성과 평가셋 분리

보고서의 원천 데이터 표에는 언더컷과 오버랩을 합쳐 약 60,000장이 제시됐고, 후속 학습표에는 전처리 후 사용된 선박 부품영상 56,256장이 기록돼 있습니다. 직접 촬영한 용접실기품은 실험 단계에 따라 약 155~198장, 즉 약 200장 규모로 사용했습니다.

데이터 구분사용 목적평가에서의 처리
AI-Hub 공개 용접영상사전학습·후보모델 비교학습·검증용 자료로 사용
직접 촬영 용접실기품촬영조건 변화와 실제 시연 확인공개자료 결과와 분리해 평가
증강 이미지조명·각도·표면노이즈 강건성 보완원본 평가셋과 섞지 않고 학습에만 사용

평가셋의 수량과 촬영시점이 실험마다 달랐기 때문에 서로 다른 표의 수치를 하나의 최종 성능으로 합치지 않았습니다. 같은 평가단계 안에서 증강 전후, 모델 변경 전후와 Threshold 변경만 비교했습니다.

공개자료와 실기품 사이에서 확인한 Domain Gap

공개자료는 조명과 촬영각도가 비교적 일정하고 용접표면도 깨끗했습니다. 반면 용접실기품에는 그을음, 스패터, 산화표면, 반사광, 배경과 촬영각도 차이가 함께 포함됐습니다. 초기 모델은 공개자료의 깨끗한 특징에 치우쳐 실기품의 노이즈를 결함으로 오인하거나 실제 결함을 놓쳤습니다.

공개 학습자료와 직접 촬영한 용접실기품은 표면상태·조명·각도·배경 노이즈가 달랐습니다.

초기 ResNet 평가에서 공개자료 기반 검증수치와 직접 촬영품 결과가 크게 벌어졌습니다. 직접 촬영품 기준 Accuracy는 38.86%, F1은 21.33%, Recall은 15.84%, FPR은 **35.87%**였습니다. 모델구조를 바꾸기 전에 이 차이를 데이터와 촬영조건 문제로 먼저 분리했습니다.

이미지를 어떻게 평가했는가

모델점수만 비교하지 않고 원본사진과 오류유형을 함께 확인했습니다.

  1. 원본이미지와 정답 Label을 기준으로 예측결과를 대조했습니다.
  2. 실제 불량을 정상으로 판단한 FN 이미지를 가장 먼저 확인했습니다.
  3. 양품을 불량으로 판단한 FP는 그을음·스패터·반사광·촬영각도·ROI 이탈로 나눴습니다.
  4. 같은 평가셋에 Threshold를 바꿔 적용하며 FN과 FP가 어떻게 변하는지 비교했습니다.
  5. 낮은 Confidence와 양불 경계가 겹치는 Gray Zone은 자동 합격 대신 재촬영 또는 작업자 확인 대상으로 분리했습니다.

촬영조건을 반영한 증강과 추가학습

Crop·좌우반전·회전·원근변형으로 촬영구도를 바꾸고, 밝기·대비·감마·그림자·Lens Flare로 조명변화를 반영했습니다. Blur·Gaussian Noise·JPEG 압축과 일부 가림도 추가했습니다. 학습단계에서는 MixUp, Label Smoothing, SWA, 다중 Seed 평균과 Temperature Scaling을 함께 검토했습니다.

보고서의 증강 예시입니다. 촬영구도·조명·Noise 변화와 MixUp·Label Smoothing·SWA·다중 Seed 평균·Temperature Scaling을 학습과 보정에 적용했습니다.

가장 큰 변화는 Recall이 15.84%에서 85.15%로 69.31%p 상승한 점이었습니다. 최신 모델을 추가하는 것보다 실제 촬영조건을 반영한 데이터 구성이 먼저라는 판단근거가 됐습니다.

후보모델 비교와 최종 조합

ResNet, Swin, DeiT, ConvNeXt, EfficientNet과 RegNet 계열을 같은 평가항목으로 비교했습니다. CNN 계열은 국소 특징과 양품판정에서 상대적으로 안정적이었고, Transformer 계열은 용접비드의 전역 흐름을 보며 불량을 민감하게 찾는 경향을 보였습니다.

최종 수치평가와 APP 시연에는 ResNet-50 + DeiT-Small의 확률을 평균하는 2-Model 앙상블을 사용했습니다. 보고서에서 5개 모델 앙상블의 F1은 96.08%, 2개 모델 앙상블은 96.04%로 차이가 0.04%p였고, 추론비용은 약 3분의 1 수준으로 정리됐습니다.

Threshold를 제조검사 조건으로 바꾼 방법

F1이 가장 높았던 Threshold는 0.49였지만 제한 평가셋에서 FN이 4건 발생했습니다. Threshold를 0.40으로 낮추면 FN은 0건이 되고 Recall은 100%가 됐지만, FP는 4건에서 15건으로 늘었습니다.

0.4111499.0%15.2%93.0%첫 불량 누락 발생
0.4421298.0%13.0%93.4%중간 Trade-off

0.506394.1%3.3%95.5%오검 감소·미검 증가
0.5112388.1%3.3%92.2%FN 급증

동일한 용접실기품의 판정결과 비교입니다. Threshold를 낮출수록 불량후보로 분류되는 강도가 높아지고 작업자 재확인 대상도 함께 늘어납니다.

시연모델은 불량 누락을 우선 줄이기 위해 Threshold 0.40을 적용했습니다. 이 제한 평가셋에서 FN 4건 → 0건으로 100% 감소했고 Recall은 96.0% → 100.0%, +4.0%p가 됐습니다. 반면 FP는 4건 → 15건, 11건 증가했으며 FPR은 4.3% → 16.3%, +12.0%p가 됐습니다.

최종 시연표에는 Accuracy 92.23%, Precision 87.07%, Recall 100%, F1 **93.10%**가 기록됐습니다. 이는 생산라인 전체의 불량유출 0건을 의미하는 것이 아니라, 보고서의 제한 평가셋에서 선택한 Threshold 조건입니다.

APP 형태의 검사 시연

보고서의 APP 시연 구조입니다. 스마트폰 이미지를 /predict로 전송하고 ResNet-50·DeiT-Small 앙상블 결과를 JSON으로 반환했습니다.

스마트폰에서 촬영한 이미지는 HTTPS multipart/form-data로 FastAPI의 /predict 엔드포인트에 전달했습니다. 서버는 ResNet-50과 DeiT-Small의 추론결과를 평균하고 Temperature Scaling과 Threshold를 적용했습니다. PWA 화면에는 JSON 응답의 grade, defect_type, confidence를 등급·결함유형·신뢰도로 표시했습니다.

APP는 A·C·D 등급과 Confidence를 보여주는 시연화면까지 구현했습니다. 모델결과는 작업자가 원본사진과 함께 검토하는 검사보조 정보로 사용했습니다.

직접 촬영한 용접실기품의 A·C·D 등급 시연화면입니다. 등급·결함유형·Confidence를 원본사진과 함께 표시했습니다.

내가 직접 맡은 모델링·평가 판단

  • 전체 프로젝트 목적과 모델평가 흐름을 기획했습니다.
  • 공개자료와 직접 촬영 실기품의 Domain Gap을 분리해 평가했습니다.
  • 후보모델의 Recall·FPR·F1과 오류이미지를 같은 기준으로 비교했습니다.
  • 저해상도 입력에서도 원본과 ROI 좌표가 맞도록 좌표 스케일링 로직을 개발했습니다.
  • Threshold별 FN·FP 변화를 비교해 시연용 판정조건을 정했습니다.
  • 팀 결과를 모델점수만이 아니라 APP 입력·추론·결과표시와 작업자 확인 흐름으로 정리했습니다.

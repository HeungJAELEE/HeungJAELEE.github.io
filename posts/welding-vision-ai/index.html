    AI 용접 Vision 구축 프로젝트: 현장 품질 문제를 데이터와 임계값으로 풀어낸 과정

    2026. 7. 9. · 12 · 마지막 검토 2026. 7. 31.

    • AI

    • Manufacturing

    • Quality

    문제: 높은 정확도만으로는 용접 결함 검출 기준을 설명할 수 없다

    항목확인된 내용
    Problem미세 용접 결함은 양품과 시각 특성이 겹치고 데이터 불균형이 있어 Accuracy만으로는 불량 미검출 위험을 설명하기 어려웠습니다.
    Role팀 프로젝트에서 F1·Recall·FPR 등 평가지표 설계와 검증을 담당했습니다.
    ActionAI-Hub 공개 이미지 약 60,000장과 현장 이미지 198장의 역할을 분리하고, DenseNet 단독·2-model 조합을 거쳐 ResNet+DeiT 앙상블을 비교했습니다. 2차 테스트에서 양품/불량 혼재 구간을 확인한 뒤 Recall을 우선하도록 Threshold를 조정했습니다.
    Result선택한 평가셋과 임계값에서 **F1 93.10%, Recall 100%, Precision 87.07%**를 기록했습니다. 이는 해당 데이터 조건의 결과이며 양산 전수검사 성능 보장은 아닙니다.
    EvidenceAI 용접 Vision 보고서의 데이터·모델 진화·2차 Test·최종 지표 페이지. 전용 공개 repo는 미분리 상태입니다.

    이력서 Bullet

    • 공개 용접 이미지 약 60,000장과 현장 이미지 198장을 학습 기반/현장 검증 데이터로 분리하고, 데이터 출처와 평가 목적을 추적 가능하게 구성했습니다.
    • DenseNet 단독·2-model 조합·ResNet+DeiT 앙상블을 비교하고, 2차 테스트 오류 구간을 분석해 불량 미검출을 우선하는 Threshold를 선택했습니다.
    • 해당 평가셋에서 F1 93.10%, Recall 100%, Precision 87.07%를 확인하고, 오검은 재검사로 관리하는 품질 의사결정 기준을 제안했습니다.

    면접 STAR

    • Situation: 미세 용접 결함은 놓쳤을 때의 품질 비용이 크지만 정상 표면과 특성이 겹쳐 Accuracy만 높이는 접근이 위험했습니다.
    • Task: 모델 후보를 같은 기준으로 비교하고, 불량 미검출을 우선 줄이는 평가·판정 기준을 만드는 역할을 맡았습니다.
    • Action: 공개/현장 데이터를 분리하고 Confusion Matrix로 오류를 확인했으며, 2차 테스트의 혼재 구간을 바탕으로 Recall이 유지되는 임계값을 탐색했습니다.
    • Result: 제한된 평가셋에서 Recall 100%, F1 93.10%, Precision 87.07%를 기록했습니다. 동시에 양산 일반화가 아닌 검사 보조 PoC라는 한계를 명시했습니다.

    제조 현장에서 비전 AI의 가치는 모델 이름보다 어떤 불량을 놓치지 않아야 하는지, 그리고 오검을 어느 수준까지 감수할 것인지를 품질 기준으로 정의하는 데서 시작합니다. 이 프로젝트는 용접부의 미세 크랙과 핀홀을 판별하는 과제를 대상으로, 공개 데이터와 현장 이미지를 연결하고 판정 임계값을 조정해 불량 미검출을 줄이는 과정을 설계·검증한 비전 모델링 프로젝트입니다.

    프로젝트 기록상 사용한 데이터는 AI-Hub 공개 용접 이미지 약 60,000장과 현장 실측 이미지 198장입니다. 선택한 평가 조건에서 **F1 Score 93.10%, Recall 100%, Precision 87.07%**를 확인했습니다. 다만 이 수치는 해당 데이터와 당시의 판정 조건에서 얻은 결과이며, 실제 양산 라인의 모든 조명·설비·제품 조건에 대한 성능을 의미하지는 않습니다.

    • 프로젝트 성격: 제조 품질 문제를 다룬 AI 비전 모델링 및 검증
    • 핵심 과제: 불량 미검출(False Negative)을 우선적으로 억제하는 판정 기준 설계
    • 데이터: 공개 데이터 약 60,000장, 현장 실측 이미지 198장
    • 기록된 결과: F1 93.10%, Recall 100%, Precision 87.07%
    • 적용 범위: 제한된 데이터셋 기반 검증이며, 양산 설비에 배포 완료한 시스템은 아님

    왜 이 프로젝트를 구성했는가

    용접 품질은 전류, 출력, 가압, 위치 정렬, 소재 상태와 같은 여러 공정 조건의 영향을 동시에 받습니다. 불량이 발생한 뒤 조건을 수정하는 것만으로는 이미 만들어진 제품의 품질을 되돌릴 수 없기 때문에, 검사 단계에서 이상을 빠르게 식별하고 원인 분석으로 연결하는 체계가 필요합니다.

    저는 배터리 셀 조립 현장에서 초음파·레이저 용접 조건을 최적화하고, 해체 및 단면 분석으로 불량 원인을 확인해 온 경험이 있습니다. 2170·4695 원통형 셀과 각형 셀의 파일럿·양산 공정을 다루면서 느낀 핵심은, AI 역시 현장 품질 기준과 분리해서 설계할 수 없다는 점이었습니다. 그래서 이 프로젝트를 단순 이미지 분류 실습이 아니라 다음 질문에 답하는 구조로 구성했습니다.

    1. 공개 데이터로 시각적 결함 패턴을 충분히 학습할 수 있는가?
    2. 공개 데이터에서 학습한 특징이 소수의 현장 이미지에서도 유효한가?
    3. 정확도 하나가 아니라 미검출과 오검의 비용을 구분해 판정 기준을 정할 수 있는가?
    4. 모델 결과를 현장 엔지니어가 이해하고 재검사할 수 있는 품질 지표로 표현할 수 있는가?

    이 질문을 기준으로 데이터, 모델, 임계값, 오류 분석을 하나의 파이프라인으로 묶었습니다.

    아키텍처와 데이터 흐름

    프로젝트의 핵심은 대규모 공개 데이터로 학습 기반을 확보하고, 현장 실측 이미지로 도메인 차이를 확인한 뒤, 품질 리스크에 맞게 판정 임계값을 조정하는 것입니다.

    사용 기술과 구성

    Python 기반 데이터 처리와 실험 관리

    이미지 경로, 라벨, 전처리 조건, 예측 확률과 정답을 일관된 형식으로 관리하기 위해 Python 기반의 비전 학습 흐름을 사용했습니다. Python은 이미지 전처리부터 모델 학습, 임계값별 지표 계산까지 같은 언어 안에서 연결할 수 있어 반복 실험에 적합합니다.

    여기서 중요한 역량은 특정 라이브러리를 호출하는 것보다 다음 실험 조건을 재현 가능하게 관리하는 것입니다.

    • 어떤 이미지와 라벨을 학습·검증에 사용했는지 추적
    • 동일 이미지가 학습과 평가에 중복되지 않도록 분리
    • 입력 크기와 정규화 조건을 일관되게 유지
    • 모델별 예측값을 동일 지표로 비교
    • 임계값 변경 전후의 Precision, Recall, F1을 함께 기록

    딥러닝 비전 모델

    용접 표면의 결함은 규칙 기반 영상 처리만으로 일반화하기 어렵습니다. 반사광이나 표면 요철이 결함과 유사하게 보일 수 있고, 결함 형태도 일정하지 않기 때문입니다. 따라서 사람이 일일이 경계 규칙을 작성하기보다 이미지 특징을 학습하는 딥러닝 비전 접근을 선택했습니다.

    프로젝트 보고서에는 DenseNet121 단독, DenseNet+Mask R-CNN 조합, ResNet+DeiT 이종 앙상블의 세 단계가 기록되어 있습니다. 최종 선택은 모델 이름 자체보다 동일한 평가 데이터와 판정 기준으로 후보를 비교하고, 현장 품질 목적에 맞게 임계값을 조정한 과정에 의미가 있습니다.

    Confusion Matrix와 임계값 최적화

    모델은 보통 0과 1을 바로 출력하는 것이 아니라 불량일 가능성을 확률값으로 냅니다. 예를 들어 임계값이 0.5라면 0.5 이상을 불량으로 분류합니다. 임계값을 낮추면 불량을 더 많이 잡을 수 있지만 정상 제품까지 불량으로 판정할 수 있고, 높이면 오검은 줄어도 실제 불량을 놓칠 수 있습니다.

    용접 품질에서는 불량을 정상으로 통과시키는 비용이 크기 때문에 Recall을 우선했습니다.

    [ \text{Precision} = \frac{TP}{TP + FP} ]

    [ \text{Recall} = \frac{TP}{TP + FN} ]

    [ \text{F1 Score} = 2 \times \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}} ]

    • TP: 실제 불량을 불량으로 판정
    • FP: 정상을 불량으로 판정한 오검
    • FN: 실제 불량을 정상으로 판정한 미검출
    • TN: 실제 정상을 정상으로 판정

    Recall 100%는 평가 대상에 포함된 불량을 모두 검출했다는 뜻입니다. 동시에 Precision 87.07%는 불량으로 판단한 일부 이미지가 실제로는 정상일 수 있음을 보여줍니다. F1 93.10%는 이 두 지표의 균형을 요약합니다. 즉, 이 프로젝트의 의사결정은 “모든 지표를 완벽하게 만든다”가 아니라 미검출을 우선 억제하고 남은 오검은 재검사 프로세스로 관리한다는 품질 전략에 가깝습니다.

    데이터와 구현 흐름

    데이터 정의

    첫 단계는 모델보다 불량의 정의를 맞추는 일입니다. 공개 이미지의 라벨과 현장 판정 기준이 다르면 모델 점수를 비교해도 의미가 없습니다. 따라서 용접부 이미지, 정상·불량 라벨, 이미지 출처를 구분하고, 공개 데이터와 현장 데이터의 역할을 분리했습니다.

    공개 데이터 약 60,000장은 다양한 결함 패턴을 학습할 수 있는 기반으로, 현장 실측 198장은 실제 촬영 조건에서 모델 반응을 확인하는 자료로 보았습니다. 198장은 양산 환경 전체를 대표하기에는 작은 규모이므로, 최종 검증 결과를 현장 전체로 일반화하지 않는 것이 중요합니다.

    전처리와 입력 표준화

    비전 모델은 이미지 크기와 색상 범위가 일정해야 안정적으로 학습됩니다. 전처리 단계에서는 입력 형식을 통일하고, 육안으로 라벨과 이미지 품질을 확인하는 데이터 점검이 필요합니다. 단, 실제 프로젝트 기록에 구체적인 증강 기법이나 필터가 남아 있지 않아 이 글에서는 특정 전처리를 수행했다고 추가로 주장하지 않습니다.

    현장 적용을 확대할 때는 밝기 변화, 반사, 초점 흐림, 용접부 위치 편차를 재현하는 증강을 검토할 수 있습니다. 이 작업은 기존 결과가 아니라 다음 단계의 개선안입니다.

    학습과 예측값 저장

    학습 단계에서는 각 이미지의 정답과 모델이 출력한 불량 확률을 저장합니다. 이렇게 확률값을 남겨야 모델을 다시 학습하지 않고도 여러 임계값을 비교할 수 있습니다. 단일 정확도만 기록하면 어떤 종류의 오류가 줄었는지 알 수 없기 때문에, 이미지 단위 예측 결과와 Confusion Matrix를 함께 확인하는 흐름으로 구성했습니다.

    임계값 탐색

    임계값을 일정 간격으로 바꾸면서 Precision, Recall, F1의 변화를 비교했습니다. 불량 미검출을 최소화해야 한다는 제조 품질의 우선순위를 반영해 Recall 100%가 유지되는 구간을 먼저 확인하고, 그 안에서 F1과 Precision이 상대적으로 좋은 조건을 선택했습니다.

    이 접근은 모델을 무조건 복잡하게 만드는 대신, 이미 학습된 모델의 판정 기준을 업무 리스크에 맞게 조정한다는 장점이 있습니다. 또한 현장에서는 임계값과 재검사 기준을 함께 관리할 수 있어 모델 판단을 품질 프로세스에 연결하기 쉽습니다.

    오류 이미지 검토

    수치만으로는 오검의 원인을 알 수 없습니다. 따라서 FP와 FN에 해당하는 이미지를 분리해 표면 반사, 촬영 상태, 정상 형상의 편차와 같은 가능성을 사람이 다시 확인하는 단계가 필요합니다. 이 결과는 추가 데이터 수집과 라벨 기준 보완으로 돌아가야 합니다.

    flowchart TD A["예측 결과"] --> B{"정답과 비교"} B -->|TP / TN| C["정상 판정 사례 축적"] B -->|FP| D["오검 이미지 재검토"] B -->|FN| E["미검출 원인 우선 분석"] D --> F["라벨·촬영 조건·임계값 점검"] E --> F F --> G["데이터 보강 또는 재학습"] G --> A

    가장 어려웠던 문제와 의사결정

    공개 데이터와 현장 이미지의 차이

    가장 큰 위험은 공개 데이터에서 보인 성능이 현장에서도 그대로 재현될 것이라고 가정하는 것입니다. 그래서 60,000장과 198장을 단순히 합쳐 “총 60,198장 학습”으로 표현하지 않고, 공개 데이터는 학습 기반, 현장 데이터는 현장 조건 확인이라는 서로 다른 역할로 구분했습니다.

    Accuracy보다 Recall을 우선한 이유

    정상 이미지 비율이 높으면 불량을 거의 잡지 못해도 Accuracy가 높게 나올 수 있습니다. 용접 결함 검사에서 중요한 것은 불량 통과를 줄이는 것이므로 Recall을 우선 지표로 선택했습니다. 대신 Recall만 높이면 오검이 늘 수 있어 F1과 Precision을 보조 지표로 함께 확인했습니다.

    “자동 판정”보다 “검사 보조”로 범위를 정한 이유

    현장 데이터 198장만으로 설비, 소재, 조명, 제품 형상 변화까지 모두 검증했다고 볼 수 없습니다. 따라서 현재 결과는 무인 전수검사를 완성했다는 의미가 아니라, 불량 후보를 선별하고 검사원이 우선 확인할 대상을 제시하는 품질 보조 모델의 가능성을 확인한 것으로 해석하는 것이 합리적입니다.

    AI와 사람의 역할

    AI는 공개 데이터 분류, 실험 비교표, 임계값별 지표 해석과 기술 문서 초안을 보조했습니다. 사람은 학습·검증 데이터의 분리, 현장 이미지 198장의 역할, 미검출 비용, 공개 가능한 결과 범위와 실제 라인 적용 전 추가 검증 항목을 확인했습니다.

    Problem

    미세 용접 결함과 정상 표면 특징이 겹치고 클래스 불균형이 있어 accuracy만으로는 불량 통과 위험을 설명할 수 없습니다.

    Goal

    공개 데이터와 현장 데이터를 분리하고 동일 지표로 모델 단계를 비교한 뒤, Recall 우선 임계값과 재검사 정책을 설계하는 것입니다.

    Success

    평가셋에서 F1·Recall·Precision을 함께 제시하고, 운영 임계값의 이유·오검출 처리·생산 적용 한계를 설명할 수 있으면 성공입니다.

    범위와 경계

    포함 범위

    • AI-Hub 약 60,000장과 현장 198장의 목적별 분리
    • DenseNet 기준선, 2모델 조합, ResNet+DeiT 앙상블 비교
    • 두 번째 테스트와 임계값 조정을 통한 미검출 우선 평가

    제외·미검증 범위

    • 전용 공개 소스 저장소가 있다는 주장
    • 모든 용접 공정·카메라 조건에 대한 생산 일반화
    • 사람의 재검사 없이 자동 판정만으로 출하하는 운영

    구현·검증 기준

    해야 할 일

    • 데이터 출처와 학습·검증·현장 확인 목적을 분리한다.
    • 모든 모델 단계를 F1, Recall, Precision과 동일한 분할 기준으로 비교한다.
    • 임계값별 false negative와 false positive를 기록하고 재검사 흐름을 둔다.

    품질·운영 기준

    • 결함 미검출 비용을 정상품 재검사 비용보다 우선한다.
    • 평가셋 수치와 생산 성능을 구분하고 데이터 누수를 점검한다.
    • 조명·재질·카메라 변화에 따른 drift를 별도 검증 대상으로 둔다.

    왜 이렇게 구성했나

    1. Recall을 1차 운영 지표로 선택

      용접 불량을 정상으로 통과시키는 위험이 정상품을 재검사하는 비용보다 크기 때문입니다.

    2. 현장 198장을 별도 검증 관점으로 유지

      대규모 공개 데이터와 적은 현장 데이터를 섞어 과도한 일반화 주장을 하지 않기 위해서입니다.

    3. 모델보다 임계값·검사 정책까지 함께 비교

      같은 모델도 운영 임계값에 따라 미검출과 오검출 비용이 달라지기 때문입니다.

    검증 결과

    항목결과해석
    공개 이미지약 60,000장결함 특징 학습을 위한 공개 데이터 기반
    현장 실측 이미지198장제한된 현장 조건에서 모델 반응을 확인한 데이터
    Recall100%해당 평가셋의 불량에 한해 미검출이 없었음
    Precision87.07%불량 판정 중 일부 오검이 존재함
    F1 Score93.10%선택한 임계값에서 Precision과 Recall의 균형

    이 결과를 해석할 때 세 가지 제한을 함께 봐야 합니다.

    1. Recall 100%는 해당 평가 데이터 안에서의 결과이며 미래의 모든 불량을 보장하지 않습니다.
    2. 데이터 분할 방식, 불량 유형별 표본 수, 반복 실험 분산이 공개되지 않아 통계적 일반화 범위를 확대해서 말할 수 없습니다.
    3. 실제 양산 적용에는 카메라·조명 고정, 검사 속도, 추론 지연시간, 설비 통신, 모델 버전 관리까지 별도의 검증이 필요합니다.

    이력서 경력과의 연결

    이 프로젝트는 제 제조 경력과 AI 학습 경험이 만나는 지점에 있습니다.

    • 배터리 셀 조립에서 초음파·레이저 용접 조건을 최적화하고 해체 분석으로 불량 원인을 확인한 경험
    • 2170·4695 원통형 셀 파일럿·양산 라인에서 수율과 설비 안정화를 담당한 경험
    • P-FMEA, QCP, MSA 등 품질 기준을 수립·개정하며 지표를 현장 의사결정으로 연결한 경험
    • YOLO 기반 Classification과 OpenVINO를 활용한 양극재 비자성 이물 검사 자동화 경험
    • Python과 데이터 분석을 제조 DX·AX 과제로 확장한 경험

    다만 이력서의 YOLO·OpenVINO 경험과 본 용접 프로젝트의 모델 아키텍처는 동일하다고 단정하지 않습니다. 두 경험의 공통점은 제조 불량을 이미지 데이터로 정의하고, 미검출과 오검을 품질 관점에서 관리했다는 데 있습니다.

    프로젝트를 통해 보여준 역량

    이 프로젝트의 핵심 성과는 단순히 F1 93.10%라는 숫자가 아닙니다. 공개 데이터와 현장 데이터를 목적에 맞게 구분하고, Accuracy 대신 제조 리스크와 직접 연결되는 Recall을 우선하며, 임계값 조정 결과를 Confusion Matrix로 설명한 데 의미가 있습니다.

    제조 AI는 모델 개발로 끝나지 않습니다. 공정 조건, 품질 기준, 검사 비용, 설비 연계까지 함께 설계해야 실제 현장에서 사용할 수 있습니다. 이 프로젝트는 제가 보유한 용접·배터리 공정 경험을 비전 모델링과 연결하고, 기술 결과를 현장 의사결정 언어로 바꾸는 과정을 보여주는 포트폴리오입니다.

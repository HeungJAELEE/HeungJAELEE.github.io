팀이 해결하려던 문제

용접부 외관검사에서 팀이 먼저 본 것은 Accuracy가 아니라 실제 불량을 정상으로 통과시키는 미검출 위험이었습니다. 정상 이미지가 많은 데이터에서는 불량을 충분히 찾지 못해도 전체 정확도가 높게 보일 수 있습니다. 반대로 임계값을 지나치게 낮추면 정상품 재검사가 늘어 생산 흐름이 느려집니다.

팀은 공개 용접 불량 자료로 후보 모델을 학습하고, 촬영조건이 다른 현장성 사진에서 오류가 어떻게 달라지는지 확인했습니다. 목표는 AI가 최종 품질판정을 대신하는 것이 아니라, 불량 후보를 제시하고 사람이 다시 확인해야 할 조건까지 정리하는 것이었습니다.

이미지가 판정 후보가 되기까지의 전체 흐름

flowchart LR A["이미지·라벨 준비
TEAM"] --> B["전처리·후보 모델 학습
SHARED·MY CORE"] --> C["불량 후보 점수와 임계값
MY CORE"] C --> D["NG 후보·수동 확인
TEAM"] D --> E["오류 재검토
SHARED"] E -.-> F["생산 적용 검증
FUTURE"]

TEAM은 팀이 함께 만든 흐름, MY CORE는 제가 직접 기획·모델링·평가한 구간, SHARED는 공동 검토, FUTURE는 아직 남은 단계입니다. 발표는 팀장이 맡았고 보고서는 공동 작성했습니다.

제가 맡은 핵심은 모델보다 평가기준이었습니다

01

MY CORE

미검출 위험과 재검사 부담을 같은 판정 흐름에 넣었습니다

후보 모델의 점수만 비교하지 않고 어떤 오류를 더 위험하게 볼지 먼저 정했습니다.
flowchart LR A["후보 모델 비교
MY CORE"] --> B["Recall·Precision·오류 이미지"] --> C["미검출·과검출 함께 비교"] --> D["Threshold·판정기준 정리
MY CORE"]
  • False Negative는 실제 불량 통과로 이어질 수 있어 Recall을 먼저 확인했습니다.
  • False Positive는 정상품 재검사와 Cycle Time 부담으로 이어지므로 함께 비교했습니다.
  • 같은 데이터 분할과 같은 지표로 후보를 비교하고, 임계값을 바꿀 때 두 오류가 어떻게 달라지는지 확인했습니다.
  • 모델 확률을 바로 합격·불합격으로 사용하지 않고, 낮은 신뢰도와 모델·작업자 판정 불일치는 재촬영 또는 수동 확인으로 돌렸습니다.

촬영조건이 달라지면 같은 점수를 그대로 쓰지 않았습니다

02

EVIDENCE BOUNDARY

공개 학습자료와 현장성 사진의 역할을 분리했습니다

현장성 사진은 독립 Test Set이 아니라 촬영조건 차이를 확인하는 제한 평가자료로 사용했습니다.

관찰

  • AI-Hub의 Undercut 30,000장과 Overlap 30,000장을 학습 기반으로 사용했습니다.
  • 현장성 사진 약 198장은 조명·각도·표면 반사와 촬영 품질이 달랐습니다.
  • 공개 데이터에서 좋아 보이던 후보도 촬영조건이 바뀌면 미검출이 늘었습니다.

판단과 확인

  • 공개 자료는 학습용, 현장성 사진은 분포 차이를 확인하는 제한 평가용으로 구분했습니다.
  • Augmentation과 후보 모델을 같은 오류 기준으로 비교했습니다.
  • 데이터 출처가 달라지면 하나의 점수를 현장 성능으로 일반화할 수 없다는 점을 확인했습니다.
  • 전용 저장소·고정 평가셋·재현 가능한 실행환경이 확인되지 않아 정확한 최종 성능점수는 대표 성과에서 제외했습니다.

팀 결과와 현재 단계

팀은 공개 학습자료와 제한된 현장성 사진의 차이를 확인하고, 모델과 임계값을 미검출 우선 기준으로 비교하는 교육 PoC를 마쳤습니다. 저는 전체 기획과 AI 모델링·평가, 판정기준 수립을 맡았습니다.

확인한 범위는 공개 데이터 기반 학습·평가 절차, 촬영조건 차이에 따른 오류 변화와 수동 확인 기준입니다. 생산 적용을 판단하려면 제품·Lot·촬영시점 단위의 독립 평가셋, 카메라 조건 고정, Line Speed 추론시간, Shadow Test와 모델·임계값 변경이력 검증이 더 필요합니다.

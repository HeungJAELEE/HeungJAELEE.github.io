프로토타입

용접 사진에서 불량을 찾는 AI 모델 만들기

공개 데이터로 학습한 모델이 현장 사진에서도 통하는지 확인하고 미검출 기준을 정리한 5인 교육 프로젝트

프로젝트 기간
AI 융합 교육 팀 프로젝트
맥락
교육 과정 PoC · 생산라인 배포 미수행
담당 범위
데이터 역할 분리, 평가정책, 임계값과 현장 적용 전 Gate

사용자·구현·검증 요약

사용자 문제
공개 데이터에서 잘 맞는 모델이 조명·각도·표면상태가 다른 현장 사진에서도 불량을 놓치지 않는지 확인해야 했습니다.
구현 범위
모델 학습·평가와 보고서를 맡아 공개 데이터와 약 198장의 현장 사진을 따로 보고, Augmentation·모델 조합·임계값별 미검출과 과검출을 비교했습니다.
결과·현재 단계
제한된 현장 평가에서 공개 데이터와의 차이를 확인하고, 미검출을 우선해 모델과 임계값을 비교하는 평가 절차를 만들었습니다.

왜 이 문제를 다뤘는가

용접부 외관검사에서 중요한 것은 모델 이름이나 단일 정확도가 아니라 불량을 정상으로 통과시키는 미검출 위험을 어떤 기준으로 관리할 것인가입니다. 정상 이미지가 많은 데이터에서는 불량을 거의 찾지 못해도 전체 정확도가 높게 보일 수 있습니다. 반대로 불량 판정 기준을 지나치게 낮추면 정상품 재검사가 늘어 생산 흐름이 느려집니다.

이 프로젝트는 용접 불량 이미지를 분류하는 교육 팀 PoC입니다. 공개 학습자료와 제한된 현장 이미지를 서로 다른 목적으로 다루고, 모델의 확률값을 현장 판정으로 바꿀 때 Recall·Precision·오탐·미검출을 함께 보는 평가 흐름을 설계했습니다.

기존 방식과 목표

구분기존 상태PoC에서 정리한 방향
데이터출처와 촬영조건이 다른 이미지가 섞일 수 있음공개 학습자료와 현장 확인자료의 역할 분리
평가Accuracy 한 값으로 후보 비교Confusion Matrix와 Recall·Precision을 함께 확인
판정기본 임계값을 그대로 사용미검출 비용을 우선해 후보 임계값 비교
운영모델 결과로 끝남오탐 재검사와 미검출 원인분석 절차까지 연결

내가 맡은 범위

  • 모델 학습, 평가와 결과 보고서 작성
  • 용접 공정의 품질위험을 기준으로 평가항목과 우선순위를 정리
  • 공개 데이터와 현장 확인자료가 같은 의미로 해석되지 않도록 용도 구분
  • 모델 후보를 같은 평가기준으로 비교하는 실험 흐름 구성
  • 확률 임계값에 따른 Recall·Precision·오탐·미검출 변화를 해석
  • 생산 적용 전 필요한 추가 검증과 작업자 재검사 절차 정리

이 프로젝트의 결과는 특정 정확도 숫자보다 평가 절차와 미검출 기준을 설계한 교육 팀 PoC에 있습니다.

데이터와 판단 흐름

flowchart LR A["공개 학습자료"] --> B["라벨·중복·품질 확인"] B --> C["학습·검증 분리"] C --> D["모델 후보 비교"] E["제한된 현장 이미지"] --> F["촬영조건 차이 확인"] D --> G["불량 확률 출력"] F --> G G --> H["임계값별 Confusion Matrix"] H --> I["미검출 우선 확인"] H --> J["오탐·재검사 부담 확인"] I --> K["후보 기준 선정"] J --> K

공개 자료는 결함 특징을 학습하는 기반으로, 현장 이미지는 조명·반사·표면상태·카메라 위치가 달라질 때 모델 반응이 어떻게 변하는지 제한적으로 확인하는 자료로 구분했습니다. 두 자료를 단순히 합쳐 하나의 학습성과처럼 말하지 않았습니다.

평가 기준을 정한 이유

용접검사에서는 False Negative가 실제 불량의 통과로 이어질 수 있습니다. 그래서 Recall을 먼저 확인하되, Recall만 높이려고 임계값을 무조건 낮추지는 않았습니다. 정상품을 불량으로 보내는 False Positive가 늘면 재검사 인력과 Cycle Time 부담이 커지기 때문입니다.

쉽게 말하면 Recall은 실제 불량을 얼마나 놓치지 않았는지, Precision은 AI가 불량이라고 표시한 사진 중 실제 불량이 얼마나 되는지를 보여 줍니다. F1은 두 값을 함께 볼 때 쓰는 지표입니다.

따라서 모델 후보마다 같은 데이터 분할과 같은 지표를 사용하고, 임계값을 바꿀 때 미검출과 오탐 이미지가 실제로 어떤 모습인지 사람이 다시 확인하는 흐름으로 구성했습니다.

현장 사진으로 다시 평가한 결과

AI-Hub 공개 데이터는 Undercut 30,000장과 Overlap 30,000장, 총 60,000장을 사용했습니다. 먼저 공개 데이터에서 ResNet 계열 모델을 학습한 뒤, 촬영조건이 다른 현장 사진 약 198장으로 다시 평가했습니다.

공개 데이터에서는 성능이 좋아 보였지만 같은 모델을 현장 사진에 적용하자 미검출이 크게 늘었습니다. 조명과 각도, 표면 반사, 결함 크기와 촬영 품질이 달랐기 때문입니다. 현장조건을 반영한 Augmentation과 ResNet·DeiT 조합을 비교하면서 미검출을 줄이는 방향으로 모델을 다시 평가했습니다.

임계값도 한 값만 정답처럼 사용하지 않았습니다. 임계값을 낮추면 미검출은 줄지만 정상품 재검사가 늘어났고, 높이면 재검사는 줄지만 불량을 놓칠 위험이 커졌습니다. 전용 저장소와 고정된 평가셋·실행 설정을 공개 재현하지 못한 상태라 정확한 점수는 대표 성과로 사용하지 않고, 모델 선택과 판정기준을 정한 과정만 설명합니다.

정상 실행과 예외 처리

정상 흐름은 이미지 입력 → 확률 출력 → 임계값 판정 → 결과 저장 → 작업자 확인입니다. 다만 현장에서는 다음 예외를 별도로 관리해야 합니다.

  • 조명 변화나 반사로 신뢰도가 낮은 이미지는 자동 합격시키지 않고 재촬영 또는 수동 확인
  • 모델과 작업자 판정이 다르면 이미지를 보관해 원인과 라벨을 재검토
  • 카메라 위치·제품·용접조건이 바뀌면 기존 임계값을 그대로 사용하지 않고 재검증
  • 모델 버전과 임계값, Lot, 촬영조건을 함께 남겨 판정 이력을 추적

정리한 결과와 다음 단계

이 PoC에서는 공개 데이터로 만든 모델이 현장 사진에서 크게 흔들릴 수 있다는 점을 실제 재평가로 확인했습니다. 이후 데이터 보강, 모델 조합과 임계값 비교를 통해 성능을 개선하고, 미검출과 과검출을 함께 판단하는 순서를 만들었습니다.

생산라인 적용을 판단하려면 다음 항목을 이어서 확인해야 합니다.

  1. 제품·Lot·촬영시점 단위로 학습과 검증 데이터를 분리해 누수를 확인
  2. 불량 유형별 표본 수와 Confusion Matrix 공개
  3. 카메라 위치·초점·노출·조명을 고정하고 허용범위 정의
  4. 실제 Line Speed에서 추론시간과 누락 Frame 확인
  5. 일정 기간 Shadow Test로 검사원 판정과 AI 판정을 병행
  6. 모델·임계값 변경 승인, Rollback, 재검증 이력 관리

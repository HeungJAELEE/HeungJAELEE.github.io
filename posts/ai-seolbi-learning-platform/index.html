    근거·권리 기반 설비보전 학습 플랫폼: PUBLIC과 HOLD를 함께 설계한 이유

    설비보전 문제·이론·NCS 근거와 공개 Gate를 연결하고 제출 전 정답 누출을 차단한 개인 AI 학습 플랫폼 사례

    문제: 자연스러운 해설이 올바른 해설을 보장하지 않는다

    자격 학습 자료는 문제, 정답, 이론, NCS 능력단위와 실기 이미지가 서로 다른 출처에 흩어져 있습니다. AI는 빈칸을 자연스럽게 채울 수 있지만, 다음 조건을 확인하지 않으면 오히려 잘못된 학습을 강화합니다.

    • 정답 후보가 서로 충돌하는가
    • 이미지·도면을 공개할 권리가 있는가
    • 문제와 연결한 이론이 실제 의미상 일치하는가
    • 제출 전에 클라이언트가 정답·해설을 이미 받는가
    • 필기·필답·작업형의 다른 답안 형식을 같은 UI로 억지로 처리하는가

    그래서 목표를 “문제 수를 빠르게 늘리는 사이트”가 아니라 근거가 확인된 항목만 공개하고 불확실한 항목은 HOLD로 남기는 학습 플랫폼으로 정했습니다.

    왜 이렇게 구성했는가

    이 프로젝트의 중요한 데이터는 문제 본문만이 아닙니다. 공개 여부를 설명하는 상태와 근거가 함께 있어야 합니다.

    Question
├─ stable_id
├─ assessment_type
├─ answer_state
├─ theory_anchor
├─ source_binding
├─ rights_state
├─ publication_state
└─ hold_reason

    publication_state=PUBLIC은 콘텐츠가 존재한다는 뜻이 아니라 출처·정답·권리 Gate를 모두 통과했다는 뜻입니다. 하나라도 부족하면 HOLD를 유지합니다.

    아키텍처와 데이터 흐름

    flowchart LR A["원본 자료·확인된 메모"] --> B["Source inventory"] B --> C["정규화\nstable ID · 유형 · 이론 anchor"] C --> D{"정답 근거?"} D -- "충돌" --> H["HOLD\nheld_answer_conflict"] D -- "확인" --> E{"권리·시각 자산?"} E -- "누락/불명" --> I["HOLD\nheld_asset_missing"] E -- "확인" --> F["PUBLIC dataset"] F --> G["필기 CBT · 필답 · 실기 UI"] G --> J["제출"] J --> K["정답·해설·선택지 피드백"]

    정답은 제출 뒤에만 전달합니다. 버튼을 누르기 전 화면에서 숨기는 수준이 아니라, 제출 전 API·정적 payload에 정답과 해설이 포함되지 않는지를 검사합니다.

    AI와 사람의 역할

    AI가 지원한 일

    • 자료를 문제·이론·NCS 후보로 분류
    • 중복·의미 불일치 후보 탐색
    • 해설과 선택지 피드백 초안
    • 누출·상태 충돌·반응형 회귀 테스트 후보 작성

    사람이 직접 확인한 일

    • 원본 출처와 실제 정답
    • 정답 충돌의 최종 판정
    • 이미지·도면의 공개 권리
    • PUBLIC/HOLD 전환
    • 실제 공개 배포 승인

    AI가 “그럴듯하다”고 판단한 결과는 공개 근거가 아닙니다. 출처·권리·정답 확인과 최종 승인은 사람의 책임입니다.

    구성 이유와 확인한 결과

    정답을 많이 생성하는 것이 아니라 출처·권리·정답 근거가 확인된 학습 흐름만 공개하고, 불확실한 자료는 HOLD로 보존하는 플랫폼 운영 사례입니다.

    Problem

    문제·정답·이론·실기 자료가 흩어져 있고 권리나 시각 자료가 불충분하면, AI가 자연스러운 해설을 만들어도 학습자가 잘못된 답을 확신할 수 있습니다.

    Goal

    문제, 이론, NCS 근거, 답안 공개 상태와 HOLD 사유를 안정 ID로 연결하고 제출 전에는 정답이 노출되지 않는 필기·필답·실기 학습 흐름을 만드는 것입니다.

    Success

    공개된 항목은 출처·정답·권리 Gate를 통과하고, HOLD는 노출되지 않으며, 빌드·누출 방지·대표 E2E가 같은 정적 산출물에서 재현되면 성공입니다.

    AI와 사람이 나눈 역할

    AI 역할
    자료 분류, 중복 후보 탐색, 해설·이론 연결 초안, 테스트 케이스와 회귀 점검 목록 생성을 지원했습니다.
    사람 역할
    출처 원문, 정답 충돌, 이미지 권리, 공개/HOLD 판정과 최종 배포 승인을 사람이 확인했습니다.
    공개 Gate
    출처·정답·권리가 모두 확인된 항목만 PUBLIC으로 전환하고, 누락 시 held_asset_missing 또는 held_answer_conflict를 유지합니다. 개인정보와 원본 저작물을 공개 복제하지 않습니다.
    외부 효과
    정적 학습 사이트 2개에 공개 배포된 읽기·학습 화면만 있습니다. 결제·자격 판정·외부 계정 권한 변경은 없습니다.

    범위와 경계

    포함 범위

    • 문제·이론·NCS·답안 상태의 source-aware 데이터 계약
    • 필기 CBT, 필답·실기 정보 구조와 제출 전 정답 비노출
    • PUBLIC/HOLD Gate, 반응형 UI, 빌드·회귀·E2E 검증

    제외·미검증 범위

    • 권리 불명 이미지와 정답 충돌 항목의 자동 공개
    • 공식 시험 문제·합격을 보장하는 표현
    • 진행 중인 Skill 개편과 미구현 inventory 계약의 완료 주장

    구현·검증 기준

    해야 할 일

    • 각 문제를 이론·출처·상태·HOLD 사유와 안정 ID로 연결한다.
    • 답안 제출 전 클라이언트에 정답·해설·선택지 피드백을 포함하지 않는다.
    • 필기·필답·실기 화면에서 출처와 현재 공개 상태를 확인할 수 있다.

    품질·운영 기준

    • 정답 충돌·자산 누락·권리 불명은 fail-closed HOLD로 처리한다.
    • Node 24 기반 빌드와 단위·통합·대표 E2E를 기록한다.
    • 전체 E2E 잔여 실패를 숨기지 않고 알려진 제한으로 공개한다.

    왜 이렇게 구성했나

    1. 생성량보다 Publication Gate 우선

      검증되지 않은 한 문제는 많은 정상 문제보다 학습 신뢰를 크게 해칠 수 있기 때문입니다.

    2. 정답 비노출을 데이터 계약으로 적용

      화면에서 숨기기만 하면 네트워크 응답이나 HTML source로 정답이 새어 나갈 수 있기 때문입니다.

    3. HOLD를 삭제하지 않고 사유와 함께 보존

      근거가 추가되었을 때 같은 ID로 재검토하고 과거 불확실성을 추적하기 위해서입니다.

    한계와 공개 Gate

    • 권리나 정답 근거가 불충분한 자산은 삭제해 “완료”로 보이게 하지 않고 HOLD 사유를 유지합니다.
    • 공식 시험기관의 원문·정답을 대체하거나 합격을 보장하지 않습니다.
    • 진행 중인 Skill 업데이트와 미구현 inventory 계약은 이 글의 완료 성과가 아닙니다.
    • 공개 사이트에서 보이는 내용이 최신 공식 출제 기준과 다른 경우 공식 자료가 우선합니다.

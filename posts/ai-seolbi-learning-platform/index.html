사용자·구현·검증 요약

사용자 문제
자격시험 자료는 정답·이론·이미지 권리가 서로 다른 근거에 있어 AI가 자연스럽게 채우면 잘못된 학습을 만들 수 있습니다.
구현 범위
문제·이론·출처·권리·공개 상태를 연결하고 제출 전 정답 누출을 막는 학습 흐름과 회귀검사를 설계했습니다.
결과·현재 단계
근거가 확인된 항목만 공개하고 충돌하거나 권리가 불분명한 항목은 HOLD로 유지하는 수험생용 마스터북을 운영하고 있습니다.

문제: 자연스러운 해설이 올바른 해설을 보장하지 않는다

자격 학습 자료는 문제, 정답, 이론, NCS 능력단위와 실기 이미지가 서로 다른 출처에 흩어져 있습니다. AI는 빈칸을 자연스럽게 채울 수 있지만, 다음 조건을 확인하지 않으면 오히려 잘못된 학습을 강화합니다.

  • 정답 후보가 서로 충돌하는가
  • 이미지·도면을 공개할 권리가 있는가
  • 문제와 연결한 이론이 실제 의미상 일치하는가
  • 제출 전에 클라이언트가 정답·해설을 이미 받는가
  • 필기·필답·작업형의 다른 답안 형식을 같은 UI로 억지로 처리하는가

그래서 목표를 “문제 수를 빠르게 늘리는 사이트”가 아니라 근거가 확인된 항목만 공개하고, 틀린 이유를 이론까지 돌아가 다시 학습하는 수험용 마스터북으로 정했습니다. 근거가 불확실한 항목은 억지로 채우지 않고 HOLD로 남겼습니다.

왜 이렇게 구성했는가

이 프로젝트의 중요한 데이터는 문제 본문만이 아닙니다. 공개 여부를 설명하는 상태와 근거가 함께 있어야 합니다.

Question
├─ stable_id
├─ assessment_type
├─ answer_state
├─ theory_anchor
├─ source_binding
├─ rights_state
├─ publication_state
└─ hold_reason

publication_state=PUBLIC은 콘텐츠가 존재한다는 뜻이 아니라 출처·정답·권리 Gate를 모두 통과했다는 뜻입니다. 하나라도 부족하면 HOLD를 유지합니다.

아키텍처와 데이터 흐름

flowchart LR A["원본 자료·확인된 메모"] --> B["Source inventory"] B --> C["정규화\nstable ID · 유형 · 이론 anchor"] C --> D{"정답 근거?"} D -- "충돌" --> H["HOLD\nheld_answer_conflict"] D -- "확인" --> E{"권리·시각 자산?"} E -- "누락/불명" --> I["HOLD\nheld_asset_missing"] E -- "확인" --> F["PUBLIC dataset"] F --> G["필기 CBT · 필답 · 실기 UI"] G --> J["제출"] J --> K["정답·해설·선택지 피드백"]

정답은 제출 뒤에만 전달합니다. 버튼을 누르기 전 화면에서 숨기는 수준이 아니라, 제출 전 API·정적 payload에 정답과 해설이 포함되지 않는지를 검사합니다.

AI와 사람의 역할

AI가 지원한 일

  • 자료를 문제·이론·NCS 후보로 분류
  • 중복·의미 불일치 후보 탐색
  • 해설과 선택지 피드백 초안
  • 누출·상태 충돌·반응형 회귀 테스트 후보 작성

사람이 직접 확인한 일

  • 원본 출처와 실제 정답
  • 정답 충돌의 최종 판정
  • 이미지·도면의 공개 권리
  • PUBLIC/HOLD 전환
  • 실제 공개 배포 승인

AI는 분류와 초안을 돕고, 사람은 출처·권리·정답과 최종 공개 상태를 확인합니다.

현재 운영 기준

  • 정답 근거가 충돌하거나 이미지 권리가 불분명한 항목은 HOLD 상태와 사유를 유지합니다.
  • 제출 전 응답에는 정답·해설·선택지 피드백을 넣지 않습니다.
  • 공식 시험기준이 바뀌면 출처와 연결된 문제부터 다시 검토합니다.

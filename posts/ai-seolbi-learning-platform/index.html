해결하려던 문제

문제·정답·해설의 출처와 권리가 섞여 있고 근거가 부족한 자료까지 자동 공개하면 잘못된 학습과 권리 문제가 생길 수 있었습니다.

내가 맡은 범위

  • 문제 선택→답안 제출→근거 확인→오답 학습 흐름과 공개·보류 판정, 제출 전 정답 비노출을 설계·검증했습니다.

확인된 결과·현재 단계

  • 확인된 산출물 · 개인 역할 제출 전 정답 비노출과 제출 후 근거·오답 학습 흐름
  • 현재 단계 · 개인 역할 운영 중·근거 또는 권리가 부족한 자료는 공개 보류

팀 경계

AI는 분류·초안·점검을 돕고, 출처·권리·정답 충돌과 공개 여부는 사람이 확인합니다.

공개 범위: 공개 운영 화면과 마지막 완료 검증 범위만 설명하며, 진행 중 기능은 완료 성과에 넣지 않습니다.

학습자가 실제로 사용하는 문제 선택부터 오답 복귀까지의 흐름으로 설명합니다.

문제

설비보전 자격 학습 자료는 문제, 정답, 이론, NCS 능력단위와 실기 이미지가 여러 출처에 흩어져 있습니다. AI가 매끄러운 해설을 만들더라도 정답 후보가 충돌하거나 이미지 권리가 불분명하면 학습자는 틀린 내용을 확신할 수 있습니다. 화면에서 정답을 가렸어도 제출 전 응답에 정답이나 해설이 들어 있다면 학습 흐름도 성립하지 않습니다.

이 프로젝트는 문제 수를 늘리는 데서 출발하지 않았습니다. 근거가 확인된 항목만 공개합니다. 정답·출처·권리 중 하나라도 부족하면 같은 ID와 사유를 남기되 공개 목록에서는 제외하는 데 초점을 맞췄습니다.

대표 사용자 장면

학습자는 필기 문제를 고르고 답을 선택한 뒤 제출합니다. 제출 전에는 정답, 해설, 선택지별 피드백을 받지 않습니다. 제출하고 나면 정답과 해설뿐 아니라 연결된 출처와 이론 근거를 확인합니다. 틀린 선택지는 왜 틀렸는지 짚어 본 뒤 같은 근거를 다시 살펴보며 오답 학습으로 이어 갑니다.

필답형과 실기 자료도 같은 원칙을 따르되 답안 형식은 억지로 하나로 합치지 않습니다. 공개할 근거가 없는 문제나 시각 자료는 학습 경로에 나타나지 않고 보류 사유와 함께 남습니다.

이 도구가 하는 일과 하지 않는 일

이 도구는 문제 선택에서 제출, 근거 확인, 오답 학습까지 한 흐름으로 연결합니다. 각 문제에는 안정 ID, 시험 유형, 정답 상태, 이론 연결, 출처, 권리 상태, 공개 여부와 보류 사유가 따라갑니다. 공개 가능 판정은 콘텐츠가 있다는 뜻이 아니라 출처·정답·권리를 모두 확인했다는 뜻입니다.

이 도구는 공식 시험기관의 원문과 정답을 대신하지 않으며 합격을 보장하지 않습니다. AI가 자연스럽게 만든 설명만으로 문제를 공개하지도 않습니다. 정답 충돌은 held_answer_conflict, 필요한 시각 자료가 없거나 공개 권리를 확인할 수 없으면 held_asset_missing으로 남깁니다.

데이터, AI, 사람의 역할

데이터는 문제 본문뿐 아니라 출처와 검토 상태를 함께 보관합니다. 문제와 이론, NCS 근거, 답안 상태, 권리와 공개 여부가 같은 ID로 연결되어야 나중에 근거가 보강됐을 때도 불확실성의 이력을 잃지 않습니다.

AI는 자료 분류, 중복과 의미 불일치 후보 탐색, 해설·선택지 피드백 초안, 회귀 검사 후보 작성에 사용했습니다. 사람은 원본 출처와 정답, 충돌 판정, 이미지·도면의 공개 권리, 공개·보류 전환과 최종 배포 승인을 확인했습니다. AI의 그럴듯함은 공개 근거가 되지 않습니다.

만든 순서

  1. 원본 자료와 확인된 메모를 모으고 각 항목에 안정 ID를 붙였습니다.
  2. 필기·필답·실기 유형을 나눈 뒤 문제를 이론, NCS 근거와 출처에 연결했습니다.
  3. 정답 충돌과 시각 자료의 권리를 확인하고 부족한 항목은 공개 대상에서 분리했습니다.
  4. Next.js App Router, TypeScript, Zod와 Tailwind로 문제 선택→제출→근거 확인→오답 학습 흐름을 만들었습니다.
  5. 제출 전 응답에서 정답·해설·선택지 피드백을 제외하고 Vitest와 Playwright/Chromium으로 데이터와 대표 흐름을 확인했습니다.
  6. 정적 산출물을 Cloudflare Pages와 Sites에서 다시 확인했습니다.

회사에서 얻을 수 있는 가치와 한계

회사 교육이나 정비 지식 시스템에도 같은 방식을 적용할 수 있습니다. 작업 지식에 출처, 개정 상태, 권리와 사람의 검토 결과를 함께 묶으면 AI가 만든 설명과 승인된 교육 내용을 구분하기 쉬워집니다. 문제 선택부터 근거 확인과 오답 학습까지 이어지는 구조는 단순 문서 열람보다 실제 학습 행동을 설계하는 데 도움이 됩니다.

한계도 분명합니다. 권리나 정답 근거가 부족한 자료는 여전히 공개 보류 상태입니다. 전체 E2E 잔여도 남아 있습니다. 공식 출제 기준이 사이트와 다르면 공식 자료가 우선합니다. 진행 중인 Skill 개편과 미구현 inventory 계약은 이 글의 결과에 포함하지 않았습니다.

Problem

문제·정답·이론·실기 자료가 흩어져 있고 권리나 시각 자료가 불충분하면, AI가 자연스러운 해설을 만들어도 학습자가 잘못된 답을 확신할 수 있습니다.

Goal

문제, 이론, NCS 근거, 답안 공개 상태와 HOLD 사유를 안정 ID로 연결하고 제출 전에는 정답이 노출되지 않는 필기·필답·실기 학습 흐름을 만드는 것입니다.

Success

공개된 항목은 출처·정답·권리 Gate를 통과하고, HOLD는 노출되지 않으며, 빌드·누출 방지·대표 E2E가 같은 정적 산출물에서 재현되면 성공입니다.

AI와 사람이 나눈 역할

AI 역할
자료 분류, 중복 후보 탐색, 해설·이론 연결 초안, 테스트 케이스와 회귀 점검 목록 생성을 지원했습니다.
사람 역할
출처 원문, 정답 충돌, 이미지 권리, 공개/HOLD 판정과 최종 배포 승인을 사람이 확인했습니다.
공개 Gate
출처·정답·권리가 모두 확인된 항목만 PUBLIC으로 전환하고, 누락 시 held_asset_missing 또는 held_answer_conflict를 유지합니다. 개인정보와 원본 저작물을 공개 복제하지 않습니다.
외부 효과
정적 학습 사이트 2개에 공개 배포된 읽기·학습 화면만 있습니다. 결제·자격 판정·외부 계정 권한 변경은 없습니다.

범위와 경계

포함 범위

  • 문제·이론·NCS·답안 상태의 source-aware 데이터 계약
  • 필기 CBT, 필답·실기 정보 구조와 제출 전 정답 비노출
  • PUBLIC/HOLD Gate, 반응형 UI, 빌드·회귀·E2E 검증

제외·미검증 범위

  • 권리 불명 이미지와 정답 충돌 항목의 자동 공개
  • 공식 시험 문제·합격을 보장하는 표현
  • 진행 중인 Skill 개편과 미구현 inventory 계약의 완료 주장

구현·검증 기준

해야 할 일

  • 각 문제를 이론·출처·상태·HOLD 사유와 안정 ID로 연결한다.
  • 답안 제출 전 클라이언트에 정답·해설·선택지 피드백을 포함하지 않는다.
  • 필기·필답·실기 화면에서 출처와 현재 공개 상태를 확인할 수 있다.

품질·운영 기준

  • 정답 충돌·자산 누락·권리 불명은 fail-closed HOLD로 처리한다.
  • Node 24 기반 빌드와 단위·통합·대표 E2E를 기록한다.
  • 전체 E2E 잔여 실패를 숨기지 않고 알려진 제한으로 공개한다.

왜 이렇게 구성했나

  1. 생성량보다 Publication Gate 우선

    검증되지 않은 한 문제는 많은 정상 문제보다 학습 신뢰를 크게 해칠 수 있기 때문입니다.

  2. 정답 비노출을 데이터 계약으로 적용

    화면에서 숨기기만 하면 네트워크 응답이나 HTML source로 정답이 새어 나갈 수 있기 때문입니다.

  3. HOLD를 삭제하지 않고 사유와 함께 보존

    근거가 추가되었을 때 같은 ID로 재검토하고 과거 불확실성을 추적하기 위해서입니다.

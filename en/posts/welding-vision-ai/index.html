Project overview

This project did not stop at producing a high validation score on public weld images. The purpose was to determine whether the same decision could be made on practical weld specimens captured under different conditions.

The initial ResNet model trained on AI-Hub weld images reached only 15.84% recall on the Facility Maintenance Engineer practical specimens. Those images contained soot, spatter, oxidized surfaces, reflection, angle variation, and background noise that were not represented consistently in the public material.

The team did not immediately replace the model. It first reviewed FN and FP images, then applied capture-condition augmentation, compared candidate architectures, built a two-model ensemble, calibrated confidence, and swept operating thresholds. I planned this experiment and evaluation order and directly handled candidate comparison, error-image analysis, coordinate scaling, and threshold decisions.

Inspection problem and completion criteria

Inspection problem

  1. Does a model trained on public data retain performance on directly captured specimens?
  2. How far can false negatives, which represent missed defects, be reduced?
  3. How far can false positives caused by soot, reflection, and spatter be reduced?
  4. Can the model score be converted into an operating decision for operator review?
  5. Does the full path from smartphone capture to result display work?

The final model was therefore not selected by combining many architectures at once. Data representation was improved first, and only the remaining error pattern was addressed through architecture and operating-threshold decisions.

My role — AI modeling and evaluation-criteria design

I set the experiment order so the team would not choose a model only from public-data validation scores. False negatives and false positives on captured specimens were reviewed first.

Models were compared by recall, FPR, F1, and source error images rather than by accuracy alone. The effect of data changes and architecture changes was separated by comparing the baseline ResNet, augmented ResNet, and ResNet+DeiT in sequence.

For low-resolution inference, model coordinates were mapped back to the original image by using the original-to-input size ratios. Threshold 0.49 and the zero-FN point at 0.40 were evaluated separately, and the demo used the missed-defect-priority condition.

How FN and FP images were evaluated

  1. Compare prediction with the source image and reference label.
  2. Review false negatives first because they represent missed defects.
  3. Group false positives by soot, spatter, reflection, angle, and ROI displacement.
  4. Change data, architecture, or threshold while keeping the evaluation set fixed.
  5. Route low-confidence and gray-zone cases to recapture or operator review.

Capture-condition augmentation

Crop, flip, and rotation represented distance and part-orientation changes. Brightness, contrast, and lens flare represented lighting and metal reflection. Gaussian noise and JPEG artifacts represented mobile capture and transfer quality.

The report also records MixUp, label smoothing, SWA, five-seed model soup, and temperature scaling as learning-stability and probability-calibration elements.

Why candidate architectures were compared

Recall remained 85.15% after augmentation. ResNet, EfficientNet, RegNet, ConvNeXt, Swin, and DeiT families were then compared under the same evaluation criteria.

CandidateStructural characteristicReason for comparison
ResNet-50Residual CNNBaseline and local texture response
EfficientNet-B3Compute-scaled CNNPerformance-to-inference-cost balance
RegNet-YRegularized CNN familyTraining stability
ConvNeXt-TLarge-kernel modern CNNWider local-region response
Swin-TinyWindow attentionLocal and multiscale features
DeiT-SmallGlobal self-attentionOverall bead flow and global patterns

The presentation contains early defect-specific and three-model ideas, but the final numerical evaluation and app demonstration support the ResNet-50 + DeiT-Small two-model ensemble. The early concepts are therefore not presented as the final architecture.

Why ResNet-50 and DeiT-Small were selected

  • ResNet-50 responded consistently to local bead texture and small geometric differences.
  • DeiT-Small responded to global patch relationships, full bead flow, and spatially distributed anomalies.

The report records high TPR for DeiT-Small and low FPR for ResNet-50 as the basis for their complementary combination. Their defect probabilities were averaged with equal weight.

Accuracy alone was not used for the final decision because it can remain high while defects are missed.

Turning threshold into an inspection condition

Threshold 0.49 produced the highest F1 but missed four defects in the limited set. Threshold 0.40 produced zero FN but increased good-item review candidates to 15.

ThresholdFNFPRecallFPRF1Use meaning
0.40015100.0%16.3%93.1%Missed-defect-priority demo
0.4421298.0%13.0%93.4%Intermediate point
0.494496.0%4.3%96.0%Maximum-F1 point

The demonstration used 0.40. This means zero FN on the limited evaluation set, not proven zero defect escape on a production line.

Mapping low-resolution coordinates back to the source image

The model returned coordinates on the resized input, while the operator needed the position on the original image. Drawing model coordinates directly would shift the ROI by the resolution ratio.

flowchart LR A["Smartphone source image
source width and height"] --> B["Resize to model input"] B --> C["Model coordinates
x1 · y1 · x2 · y2"] C --> D["Calculate horizontal and vertical ratios"] D --> E["Map to source-image coordinates"] E --> F["Draw ROI and defect position
on source image"]
scale_x = source width / model-input width
scale_y = source height / model-input height

source x = model x × scale_x
source y = model y × scale_y

This kept the low-resolution inference output aligned with the original specimen image.

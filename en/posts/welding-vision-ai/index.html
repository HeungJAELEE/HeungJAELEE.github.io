Project overview

This project did not stop at achieving a high score on public weld images. It was designed to check what failed when the model was applied to practical weld specimens captured under different conditions.

The initial model trained on AI-Hub weld images reached only 15.84% recall on the Facility Maintenance Engineer practical specimens. The captured images contained soot, spatter, oxidized surfaces, reflection, background clutter, and viewing-angle variation that were not represented consistently in the public material.

The team reviewed false-negative and false-positive images, added augmentation that represented the capture conditions, compared candidate models, combined model outputs, and evaluated threshold trade-offs. I planned the project and evaluation flow and directly handled candidate-model comparison, error-image analysis, low-resolution coordinate scaling, and threshold decisions.

Team objectives and completion criteria

Team objectives

  1. Separate AI-Hub public data from directly captured practical-specimen evaluation.
  2. Identify missed defects and false alarms on the practical specimens.
  3. Classify FN and FP by surface condition, lighting, angle, and ROI issues.
  4. Apply augmentation representing the actual capture conditions.
  5. Compare candidate models using the same evaluation items.
  6. Combine ResNet-50 and DeiT-Small probabilities.
  7. Compare FN and FP across thresholds and choose a demo condition.
  8. Connect smartphone input, FastAPI inference, and PWA result display.
  9. Use the result as operator inspection assistance rather than automatic acceptance or scrap.

My role — AI modeling and evaluation-criteria design

I set the experiment order so the team did not select a model only from public-data validation scores. The first priority was reviewing false negatives and false positives on the directly captured specimens.

Candidate models were compared using recall, FPR, F1, and source error images rather than accuracy alone. For low-resolution inference, the output coordinates were mapped back to the original image using the original-to-input size ratio.

The final demo used threshold 0.40 rather than the maximum-F1 threshold of 0.49 because no defect was missed in the limited evaluation set at 0.40. The increased false-positive and operator-review load was recorded, and the result was restricted to inspection assistance rather than automatic acceptance or scrap.

Data and domain gap

The report lists about 60,000 undercut and overlap source images and 56,256 usable ship-component images after preparation. Directly captured practical specimens were used in experiment-specific sets of approximately 155–198 images, or roughly 200 images in scale.

Data groupPurposeEvaluation handling
AI-Hub public weld imagesPretraining and candidate comparisonLearning and validation material
Directly captured specimensEvaluate actual capture conditionsKept separate from public-data results
Augmented imagesAdd lighting, angle, and surface noiseTraining only, not mixed into the original evaluation set

The initial ResNet result on captured specimens was 38.86% accuracy, 21.33% F1, 15.84% recall, and 35.87% FPR. The team treated the data and capture conditions as the first problem before changing architecture.

How images were evaluated

  1. Compare the prediction with the source image and reference label.
  2. Review false negatives first because they represent missed defects.
  3. Classify false positives by soot, spatter, reflection, angle, and ROI displacement.
  4. Change only model, augmentation, or threshold on the same evaluation set.
  5. Route low-confidence and gray-zone cases to recapture or operator review.

Capture-condition augmentation

Crop, flip, rotation, and perspective transforms represented framing changes. Brightness, contrast, gamma, shadow, and lens flare represented lighting variation. Blur, Gaussian noise, JPEG artifacts, and partial occlusion represented capture-quality degradation.

Candidate models and final combination

ResNet, Swin, DeiT, ConvNeXt, EfficientNet, and RegNet families were compared. The numerical evaluation and app demo used a two-model ensemble averaging ResNet-50 and DeiT-Small probabilities.

Mapping low-resolution coordinates back to the source image

The model returned coordinates on the resized input, while the operator needed the defect position on the original image. The application therefore calculated the horizontal and vertical size ratios and mapped the model coordinates back to the source image.

flowchart LR A["Smartphone source image
source width and height"] --> B["Resize to model input"] B --> C["Model coordinates
x1 · y1 · x2 · y2"] C --> D["Calculate horizontal and vertical ratios"] D --> E["Map to source-image coordinates"] E --> F["Draw ROI and defect position
on source image"]
scale_x = source width / model-input width
scale_y = source height / model-input height

source x = model x × scale_x
source y = model y × scale_y

This kept the ROI aligned with the source image even when inference used a lower-resolution input.

Turning threshold into an inspection condition

Threshold 0.49 produced the highest F1 but missed four defects in the limited set. The demonstration used 0.40 to prioritize missed-defect control. The number of good items requiring review increased from four to fifteen.

At threshold 0.40, the final demo table recorded 92.23% accuracy, 87.07% precision, 100% recall, and 93.10% F1. These values belong to the report’s limited evaluation set and do not represent zero escapes on a production line.

App-form inspection demonstration

flowchart LR A["Smartphone capture"] --> B["Resize and preprocessing"] B --> C1["ResNet-50"] B --> C2["DeiT-Small"] C1 --> D["Probability average"] C2 --> D D --> E["Temperature scaling"] E --> F{"Threshold decision"} F -->|Clear result| G["Grade · defect · confidence"] F -->|Gray zone| H["Recapture or operator review"]

The smartphone image was sent as HTTPS multipart/form-data to FastAPI /predict. The server averaged the two model outputs, applied temperature scaling and the selected threshold, and returned JSON.

The available public evidence supports the displayed A/C/D outputs but not the detailed grade-mapping rules, so this page does not invent those rules.

A Cell S/N Trace Tool Connecting Fragmented Process Data

Using Power Query and Excel VBA to retrieve manufacturing and inspection history from electrode roll through formation

Project period
Built over about three weeks during employment at Jastech
Context
Built to connect process-level MES data from the NCM pilot line
Scope
Data-link definition, Power Query consolidation, VBA S/N search, field use, and handoff

User, build, and validation summary

User problem
Process-level MES data existed, but a cell's full history was not connected, so investigating ten customer-requested cells took about three days.
Build scope
After a MES enhancement request was rejected for cost, I spent about three weeks building Power Query consolidation and Excel VBA search and linking logic.
Result / current stage
A single search took 5–10 seconds and a ten-cell investigation about three minutes; the tool was used on site during my employment and handed over.
Single-cell search 5–10 sec
Ten-cell investigation About 3 days → about 3 min

Process-level MES data still could not show a cell’s full history

Each process recorded data in MES, but there was no single lookup linking the cathode, anode, separator, and two J/Rs assembled into one cell. Material combinations could differ within the same lot, and electrode rework made production dates insufficient for a reliable trace.

The flow from electrode production through assembly and formation spanned about three weeks. When a customer specified cell serial numbers, data from the surrounding production dates had to be reconciled manually. Investigating the manufacturing conditions and inspection results for a typical set of ten cells took about three days.

Manufacturing and inspection data were reconnected around the cell S/N

I used the cell S/N as the lookup key and linked the required records in reverse. Materials included cathode, anode, separator, tape, can, cap assy, and electrolyte. I then connected electrode-roll position, assembly and inspection results, and formation capacity.

The task was not to create new data but to define the relationships among records already produced by each process. I designed the lookup so that one S/N could lead through its materials, production section, process results, and final capacity.

I built a field lookup tool instead of modifying MES

A request to add cell-level lookup to MES was rejected for cost. I therefore used Power Query to consolidate process files and Excel VBA to build S/N search buttons and linking logic.

I built the tool myself over about three weeks outside normal working hours. I was not using AI tools at the time; I translated the field’s repeated manual-search sequence into code and a lookup form. This was a separate tool connecting existing process data by cell S/N, not a new MES implementation.

Search and reporting time were reduced as separate steps

The original three days covered the investigation of ten cells across roughly three weeks of process data. With the tool, a single-cell search took about 5–10 seconds, and the full investigation of a typical ten-cell set took about three minutes.

Interpreting the results and preparing the customer report remained a separate task and took about half a day. Search time and report-writing time are different units of work and are not combined into one headline.

A capacity anomaly was traced back to an electrode-coating section

The tool also supported cause analysis. When a capacity-loss pattern appeared, I linked each cell’s materials and process history and traced the pattern back to a section of the electrode roll.

After confirming that the pattern repeated in the same section, the electrode process was inspected. This identified a case in which pump micro-vibration loosened a fastener and changed coating quantity. The tool did not diagnose the cause automatically; it gathered fragmented records quickly enough to narrow the field investigation.

The tool was used on site and handed over

During my employment, the tool was used for production-history lookup. I handed over the search procedure and file-update method so the responsible operator could use the same workflow. Because it relies on Excel and Power Query, its linking conditions must be updated when source-data formats change.

The production context and line-acceptance work behind this tool are described in the NCM prismatic pilot-line acceptance and stabilization case.

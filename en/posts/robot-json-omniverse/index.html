Project overview

This project modeled a legacy automotive factory in which robot programs already existed but were not designed for Digital Twin integration. The objective was to reuse existing Indy7 Teaching Data, make it readable and editable from a PC-HMI, validate it before execution, and connect realtime robot state to an automotive-process Digital Twin.

The team process used QR product identification, Robot A body assembly, a first vision inspection, Robot B window assembly, a second inspection, and Robot C good-product routing. PLC Ladder and Vision models were implemented by teammates. SCADA was outside the project scope; product and inspection data were written directly to MySQL. I planned the overall process and interfaces and directly owned Robot A/B/C control and the Digital Twin.

Command path

The original team project used the PLC as the process master. The later public code separated HMI requests from physical robot command ownership.

sequenceDiagram actor OP as Operator participant HMI as PC-HMI participant RC as Robot Controller participant DCP as IndyDCP participant ROBOT as Indy7 Robot participant DT as Digital Twin participant DB as MySQL OP->>HMI: Select robot and Teaching JSON OP->>HMI: Run program HMI->>RC: robot/command RC->>RC: Check connection and duplicate execution RC->>DCP: Translate command DCP->>ROBOT: Send physical command loop While connected ROBOT-->>RC: Joint, TCP, status RC-->>HMI: execution status RC-->>DT: robot/realtime RC-->>DB: history through DB Worker end ROBOT-->>RC: Complete or Error RC-->>HMI: result

The source file is preserved first. The application modifies only the fields edited by the operator, merges them back with unused waypoints and manufacturer-specific nodes, and validates parent references, move-to-waypoint links, units, and TCP before export.

How the Digital Twin is built

The Twin is not generated from Teaching JSON alone. It combines three data sets.

flowchart TB A["Factory layout
robot positions · rail · stations"] --> DT["Automotive-process
Digital Twin"] B["Teaching JSON
sequence · targets · TCP"] --> DT C["Realtime robot state
joint · TCP · connection · execution"] --> DT DT --> E["Robot A/B/C pose"] DT --> F["Current process stage"] DT --> G["Vehicle position"] DT --> H["Run, complete, and error state"] DT --> I["TCP and trajectory"]

Realtime J1–J6 values are processed through forward kinematics. Robot-specific installation offsets and the TCP offset are then applied before the 3D robot pose, tool position, and trajectory are updated.

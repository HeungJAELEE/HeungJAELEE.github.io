Preserve source JSON round trips and use one Robot Controller so HMI, DB, PLC, and twin consumers share explicit events.

Key design decisions

  1. Preserve source on round trip

    Unknown vendor fields must survive to retain teach-pendant compatibility.

  2. Use one IndyDCP socket owner

    This prevents concurrent-command races and centralizes physical-control accountability.

  3. Keep the twin read-only

    A visualization failure must not become a physical robot command.

1. What the system does

The system reads Neuromeka Indy7 Conty/APK JSON, displays and edits its hierarchy, supports a virtual play path, writes compatible JSON, and separates physical robot commands from data consumers.

Four design decisions define the project:

  1. preserve the original tree and reference graph during round-trip conversion;
  2. allow only Robot Controller to own IndyDCP sockets in gateway mode;
  3. separate one-shot commands from repeated state streams;
  4. let HMI, DB, and a read-only twin consume the same published state.

2. Architecture

flowchart LR UI["Python / CustomTkinter HMI\nJSON edit · virtual play · command request"] -->|"robot/command"| MQ["Mosquitto MQTT"] MQ --> RC["Robot Controller\nsingle IndyDCP owner"] RC --> RA["Indy7 A"] RC --> RB["Indy7 B"] RC --> RC3["Indy7 C"] RC -->|"result · realtime · error"| MQ MQ --> UI MQ --> DBW["DB Worker"] --> DB[("MySQL")] MQ --> DT["Digital Twin service"] --> WEB["Read-only WebSocket viewer"] PLC["PLC master"] --> PB["PLC Bridge\nmonitor / event"] --> MQ MQ -.-> OV["Future read-only Omniverse adapter"]

The UI handles operator interaction. Robot polling, database writes, PLC monitoring, and WebSocket delivery are long-running operations and therefore stay outside the GUI event loop.

3. Conty JSON compatibility

The public compatibility model centers on four blocks:

  • info: tool, TCP, coordinate, and base settings;
  • wpList: taught Waypoints with stable IDs;
  • program: a parent/child execution tree;
  • moveList: speed, acceleration, blending, and Waypoint references.

Valid JSON syntax is not enough. The loader and serializer must preserve these invariants:

  • every referenced Waypoint exists;
  • program id/pId hierarchy is not broken or cyclic;
  • unknown extension fields are retained;
  • meter/mm conversions occur at one boundary;
  • the saved file reloads into the same operation order;
  • an applied TCP can be read back before motion continues.

Unknown nodes are preserved but not executed blindly. Compatibility and execution authority are separate decisions.

4. Single socket ownership

If the UI, DB, and twin each poll the robot, they can observe different moments or compete for a connection. Gateway mode gives Robot Controller one physical socket per robot. It publishes state once and lets consumers subscribe.

Flow Topic Responsibility
HMI → controller robot/command one-shot operator request
controller → HMI robot/result command outcome
controller → consumers robot/realtime repeated state stream
controller → consumers robot/connection connection state
controller → consumers robot/error control/communication fault
PLC Bridge → consumers plc/event family monitored PLC events

The WebSocket twin reads state and does not publish Home, Zero, or Stop commands. A future Omniverse adapter should follow the same read-only boundary until separately validated.

5. Execution modes

Mode Use Connection behavior
Offline UI JSON and interface checks without equipment no automatic connection
Direct lab test without Docker HMI uses a direct adapter

Auto convenience fallback selects gateway/direct by environment

Starting the program is intentionally different from connecting to a physical robot. The operator initiates the connection explicitly.

The public repository supports these architectural claims through code and operating documents. It does not provide a basis for invented packet-loss, long-duration availability, or collision-reduction percentages.

7. Manufacturing relevance and next steps

Robot overhaul and teaching experience informed the caution around TCP, coordinate units, and read-back. Battery pilot-line FAT/SAT informed staged execution from offline and virtual checks to a single low-speed command. MES and PLC experience informed the separation of command, state, process event, and history.

Next steps include a JSON Schema plus reference validator, command IDs and idempotency, MQTT authentication/TLS/ACL, replayable robot-state integration tests, and a formally calibrated read-only Omniverse mapping.

The core skill is not JSON parsing by itself. It is preserving legacy equipment compatibility while giving physical control, event transport, history, and visualization explicit and testable ownership.

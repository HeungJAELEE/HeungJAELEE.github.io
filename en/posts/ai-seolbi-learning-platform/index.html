Problem: a fluent explanation is not necessarily a supported answer

Qualification material fragments questions, answers, theory, NCS units, and practical visuals across sources. AI can fill gaps fluently while still relying on:

  • conflicting answer candidates;
  • images without publication rights;
  • theory that is textually similar but semantically wrong;
  • answers already present in a pre-submit client payload;
  • one UI forced across written and practical answer formats.

The project goal is therefore not rapid question growth. It is a platform that publishes only evidence-qualified learning and preserves uncertainty as HOLD.

Why the data is structured this way

The publication state is as important as the question:

Question
├─ stable_id
├─ assessment_type
├─ answer_state
├─ theory_anchor
├─ source_binding
├─ rights_state
├─ publication_state
└─ hold_reason

PUBLIC means source, answer, and rights gates have all passed—not merely that content exists. Any missing gate keeps the item on HOLD.

Architecture and data flow

flowchart LR A["Source material · reviewed notes"] --> B["Source inventory"] B --> C["Normalize\nstable ID · type · theory anchor"] C --> D{"Answer evidence?"} D -- "Conflict" --> H["HOLD\nheld_answer_conflict"] D -- "Verified" --> E{"Rights / visual asset?"} E -- "Missing / unclear" --> I["HOLD\nheld_asset_missing"] E -- "Verified" --> F["PUBLIC dataset"] F --> G["CBT · written · practical UI"] G --> J["Submit"] J --> K["Answer · explanation · option feedback"]

Answers are delivered only after submission. The test checks the response or static payload, not merely whether CSS hides the answer.

Technologies and implementation

Area Technology Reason
Application Next.js App Router, TypeScript Separate routes and learning contracts with types
Validation Zod and source validation Block missing IDs, state conflict, and unpublishable material
UI Tailwind-based responsive layout Keep written and practical flows usable on mobile
Regression Vitest Test publication gates, counts, and answer non-disclosure
Real flow Playwright/Chromium Verify entry, attempt, submission, and feedback
Delivery Static build, Cloudflare Pages, Sites Read back one public artifact through two surfaces

AI and human roles

AI assisted classification, duplicate and semantic-mismatch candidates, explanation drafts, and regression-test ideas.

A human reviewed original sources, actual answers, answer conflicts, image rights, PUBLIC/HOLD transitions, and final deployment approval. A plausible AI judgment is not publication evidence.

Limits and publication gate

  • Material without rights or answer support stays HOLD with a reason.
  • The site does not replace an official exam body or guarantee passing.
  • In-progress skill changes and an unimplemented inventory contract are not completed outcomes here.
  • Official source material takes priority when the public site differs.

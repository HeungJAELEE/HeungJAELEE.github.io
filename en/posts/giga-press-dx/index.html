Why the project uses virtual commissioning

The project models a Giga Press factory context through four responsibilities:

  1. edge acquisition and signal normalization;
  2. PLC sequence, interlock, and safe-state control;
  3. SCADA state, alarm, and history visibility;
  4. Factory I/O virtual commissioning and fault-scenario checks.

It is a team PoC and design scenario. It does not claim that a production Giga Press, its safety PLC, hydraulics, or complete physical dynamics were commissioned.

Architecture and data flow

flowchart LR A["Sensors / switches / actuators"] --> B["Arduino / Raspberry Pi\nacquisition · filtering · normalization"] B --> C["PLC\nsequence · interlock · safe state"] C --> D["SCADA\nstate · alarm · history"] C <--> E["Factory I/O\nvirtual commissioning"] C --> F["OPC UA data path"] F --> G["Web / MES / AI candidates"]

The control boundary matters. Edge devices may collect and normalize data, and AI may recommend parameters, but emergency stop, door interlock, sequence permission, and communication-timeout behavior remain deterministic PLC/safety responsibilities.

Technologies and data contract

Exposing physical PLC addresses directly to every consumer would make a small I/O change ripple through SCADA and reporting. The scenario therefore uses a logical tag model.

Field Purpose
equipment_id Stable equipment identity
signal_name Human-readable process signal
value Boolean, numeric, or state value
quality Good, delayed, disconnected, or invalid
timestamp Event ordering and freshness
mode Auto, manual, or maintenance state

OPC UA is useful when meaning, quality, and hierarchy must be shared upstream. Modbus/TCP remains a simpler candidate for constrained register exchange. The article treats them as interface choices subject to device and system requirements rather than claiming every protocol was production-deployed.

Implementation sequence

  1. Define normal process steps together with stop, timeout, and restart conditions.
  2. Build an I/O list and a logical tag dictionary.
  3. Separate reusable command/status/alarm/interlock blocks from equipment-specific exceptions.
  4. Treat communication loss as a quality state and require PLC re-authorization after recovery.
  5. Run Factory I/O scenarios for normal cycles, missing completion, duplicate sensors, and delayed actuators.
  6. Present process state, alarm cause, and communication freshness together in SCADA.
  7. Place AI at the optimization/recommendation boundary, not as an unrestricted safety controller.

AI and human roles

AI was used to structure the public team material into process flow, communication boundaries, validation items, and a technical writing draft. A human reviewed the PLC, SCADA, OPC UA, Factory I/O sequence, team responsibilities, and the boundary between a projected benefit and a measured result.

The public report proposes 50–75% shorter setup and 50% lower expansion effort as expected benefits of virtual commissioning and Ladder modularization. It does not provide controlled plant before/after measurements, so those values are not listed as achieved results.

Why this case matters for manufacturing roles

  • Manufacturing engineering: process sequence, FAT/SAT thinking, interlocks, and change-impact checks.
  • Manufacturing AI & data: signal quality, OPC UA, AI-placement boundary, and traceable virtual validation.
  • Data analysis: tag definitions, timestamp/quality interpretation, and test-result separation from forecasts.

Limits and next steps

  1. Add hardware-in-the-loop tests using actual I/O and safety requirements.
  2. Version the tag specification and formalize the OPC UA information model.
  3. Automate regression scenarios and issue a machine-readable test report.
  4. Add MES work-order, lot, and quality traceability.
  5. Validate network segmentation, access control, and audit logs.
  6. Measure any setup or engineering-effort improvement with a controlled baseline before using it as an achieved KPI.

The technical value of this case is not a large target number. It is the discipline of separating physical control, data acquisition, monitoring, virtual verification, and AI so that each layer can be tested and its evidence stated honestly.

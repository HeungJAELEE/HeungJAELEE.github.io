Why a virtual factory was needed

Adding equipment alone does not guarantee that a factory will meet its target output. Process cycle time, transfer time, waiting, and buffers have to be connected before production flow can be evaluated.

The team used a virtual factory to answer four manufacturing questions before physical installation:

  • Where do waiting and congestion occur?
  • Which process equipment count should be reviewed first?
  • How do logistics distance and buffers affect output?
  • Do PLC and SCADA states refer to the same process as the analysis data?

Why this technology structure was selected

ComponentManufacturing roleReason for use
Factory I/OVisualize equipment and logistics eventsMakes process order and congestion visible
PLCSequence and interlockRepresents operating conditions as process logic
OPCConnect equipment tags to upper-level dataKeeps control state consistent in SCADA and analysis
SCADAState monitoring and operator interfaceShows current state and alarms from an operating view
SQLiteStore events and production historyAllows cycle, waiting, and output to be recalculated

AI analysis was positioned as support for comparing equipment, logistics, and output candidates, not as a replacement for PLC safety control.

My core responsibility was turning state into manufacturing decision values

An ON/OFF state alone is not sufficient for production analysis. The system needed a consistent definition of process start and end, transfer, waiting, and buffer state.

Source state or eventAnalytical valueManufacturing decision use
Process start and endCycle time by processCompare load and equipment count
Transfer start and arrivalTransfer and waiting timeReview logistics bottlenecks and layout
Buffer entry and exitWIP and congestion stateReview congestion and buffer requirement
Production-complete countCumulative and hourly outputCompare target output and scenarios

I planned the objective and responsibility structure and connected OPC tags and data meaning to production metrics and analysis inputs in the final report. Teammates handled detailed ladder and SCADA implementation.

Decision sequence for production flow and bottleneck candidates

  1. Connected target output to cycle time by process.
  2. Separated processing time from logistics and waiting time.
  3. Confirmed that Factory I/O, PLC, and SCADA referred to the same process state.
  4. Separated buffer and congestion sections as bottleneck candidates.
  5. Compared equipment-count, logistics-distance, and expected-output scenarios afterward.

Team result and future application

The ten-person team connected the normal data flow across Factory I/O, PLC, OPC, SCADA, and SQLite and explained a factory-expansion scenario using production flow and bottleneck candidates. Future work can add disconnect, stale-value, timeout, reconnect, equipment-fault, and recovery cases and compare the scenario against measured cycle time and logistics data.

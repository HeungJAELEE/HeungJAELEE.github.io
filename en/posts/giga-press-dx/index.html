Project background and vision

When PLC equipment state, SCADA monitoring, and SQLite production history use different definitions, process engineers cannot compare bottlenecks or scale-up scenarios on one data basis.

The project therefore went beyond a 3D virtual view. Its target architecture connected virtual-process events→PLC state→OPC UA tags→SCADA/SQLite history→AI Copilot advisory under one state model.

I owned overall planning and integration architecture for the ten-person team. The design organized process state for AI consumption while keeping final judgement with the process engineer under a Copilot principle.

Process virtualization and state transitions

The GIGA Press flow was abstracted into operations available in Factory I/O: material input, CNC machining, defect inspection, tray transfer, stacker loading, and discharge.

Each process was defined as a state transition rather than as an equipment list. Material ready, machining complete, inspection disposition, tray arrival, and rack complete referred to the same events across PLC, Factory I/O, and SCADA.

AI Copilot interface

Control-analysis decoupling

The central architecture decision was the decoupling of the PLC control domain from the AI Copilot analysis domain.

Physical control and safety functions remained in PLC sequence and interlock logic. The Copilot consumed OPC UA and SQLite state in read-only form, with no direct command route back to the PLC. This preserved existing control authority and safety accountability as the AI analysis layer was added.

Human-in-the-Loop

Under a Human-in-the-Loop (HITL) principle, DQN and analysis-model outputs were defined as advisory outputs for engineering review rather than equipment actions.

Normal-flow integrated demonstration

Factory I/O and PLC control

Start, Reset, Stop, and E-Stop inputs were reviewed with PLC steps and Factory I/O motion. Detailed Ladder authoring belonged to the PLC team.

SCADA and SQLite state history

Rack position, stacker loading state, and alarms were compared under the same definitions, and the SCADA-to-SQLite event and production-history flow was connected.

Web production-indicator view

The web UI placed equipment state and production information in one engineering view. Bottleneck, input, and buffer advisory can use the same user flow.

Function-oriented PLC structure proposal

The report proposed separating Emit, Machine, Move, Stacker, and Vision so process changes and expansion scenarios could be reviewed by module. Detailed implementation belonged to the PLC team.

Copilot and DQN integration design

The DQN and analysis-model integration point was placed after OPC UA and SQLite. Rack, stacker, cycle, buffer, and production count formed analysis inputs, while outputs were converted into process-engineering advisory rather than equipment commands.

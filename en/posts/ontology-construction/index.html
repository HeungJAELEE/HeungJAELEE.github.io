Project background and vision

Manufacturing, semiconductor, and battery knowledge accumulates across files with different terminology, folders, and links. When a similar problem returns, the source may exist but still require substantial manual search. Having documents is different from managing searchable knowledge.

The design decision was to keep existing Markdown as the source and establish metadata and incremental indexing before attempting a large enterprise platform. The result also prioritizes source candidates over generated answers so engineers retain final control over evidence and applicability.

The current runtime does not use an external LLM API. It uses local CUDA, ChromaDB, BGE-M3, and a BGE reranker. A standard-PC or external-API deployment remains a later option behind the same source and retrieval interface.

Data standardization

Knowledge remains as Markdown under 02_Knowledge, while YAML frontmatter supplies retrieval metadata.

Metadata groupMain fieldsRetrieval role

Semanticis_instance_of and expected queriesParent and expected-question context
RelationSPO subject, predicate, and objectRelationship context
TrustStatic trust and decay rateCandidate-score adjustment
BodyMarkdown sourceRetrieval target and source review

The current implementation does not traverse a separate graph database. It fuses domain, parent, SPO, expected-query, and body text into the retrieval document.

Incremental sync

Discover Markdown
→ filter excluded folders
→ compare file modification time with checkpoint
→ select new and changed files
→ parse frontmatter and body
→ document-level ChromaDB upsert
→ update checkpoint

Only changed files are embedded instead of rebuilding every document for each revision. This converts ongoing document changes into a repeatable indexing procedure.

Search and reranking

Natural-language query
→ tier-0 and general retrieval
→ path deduplication
→ query–document pair reranking
→ document currency and trust
→ SHA-256 integrity state

The retrieval endpoint is a prioritized set of source candidates rather than an automatically generated answer. Engineers make the final decision on factuality, applicability, and publication from the source.

Department webFollow-on optionStandardized search, source navigation, and feedbackAuthentication, authorization, audit, and recovery

The current result is not an external-API system that avoids GPUs. It fixes the source and retrieval pipeline first so runtime choice can be separated. A manufacturer can later select local GPU, CPU, or external APIs according to security, infrastructure, and usage-cost constraints.

The design intent is not to demand more documentation. It is to let well-structured documents return as useful search results, creating a practical feedback loop for knowledge quality.
